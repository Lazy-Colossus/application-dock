# Story 1.2: Per-user data model, repository & schemas

Status: Done

## Story

As the platform,
I want a JSON file per user with an atomic-write repository and typed schemas,
so that every user's lists and todos are stored durably and isolated to their account.

## Acceptance Criteria

1. **Per-user file, derived from the token.** Given an authenticated user `username`, when their document is accessed, then it is read from / written to `DATA_DIR/context-switch/users/{username}.json`; the filename is derived from the JWT username (never from request input), and the repo `mkdir(parents=True, exist_ok=True)` for the `users/` directory before writing. (FR-2, NFR-2, AR-2)

2. **Empty document for a new user.** Given a user with no file yet, when their document is read, then the repo returns an empty document `{ "schema_version": 1, "lists": [] }` without error (no file is created until a first write).

3. **Atomic writes only.** Given any persisted change, when the repo writes, then it goes through the platform atomic write-`.tmp`-then-`os.replace` helper; the repo is the ONLY module in this app that touches the filesystem. (NFR-3)

4. **Typed schemas.** Given `backend/app/schemas/context_switch.py`, when models are defined, then Pydantic v2 models exist for `TodoUpdate` (`id`, `text`, `created_at`), `Todo` (`id`, `header`, `body`, `color`, `status: "active"|"archived"`, `order`, `created_at`, `updated_at`, `archived_at: str|None`, `updates: list[TodoUpdate]`), `TodoList` (`id`, `name`, `grid: {columns, rows}`, `created_at`, `todos: list[Todo]`), and a top-level `ContextSwitchDoc` (`schema_version`, `lists`).

5. **Stable ids + migrate hook.** Given a new list/todo/update, when created, then it is stamped with a stable id — `l-{uuid8}` / `t-{uuid8}` / `u-{uuid8}` — and ISO-8601 timestamps; a `migrate(raw) -> raw` runs on read so a future `schema_version` bump has a home (v1 is a pass-through).

6. **Filesystem-safe username.** Given a `username` that is not a safe bare filename (contains `/`, `\`, `..`, or path separators), when a path is built, then the repo rejects it (raises `ValueError`) rather than escaping the `users/` directory. (NFR-2)

7. **Service raises stdlib exceptions only.** Given `services/context_switch_service.py`, when it operates on a document, then it raises stdlib exceptions (`FileNotFoundError` for a missing list/todo, `ValueError` for invalid input) and never `HTTPException`. (NFR-4)

## Dev Notes

**Layering (never skip a layer).** `router → service → repo`. The repo is the only FS code; the service holds logic and raises stdlib exceptions; routers (Stories 1.3+) translate to `HTTPException`. [Source: CLAUDE.md#Architecture]

**Per-user scoping is new to this app.** Archery and Hotaru persist global (non-per-user) data. Context-Switch is the first app whose data is keyed by the JWT username. The username flows from `get_current_user` in the router (Story 1.3+) into service calls and down to `repo._user_path(username)`. **Never accept a `user`/`username` field from the request body or path** — it must come from the token, or a user could read another user's file. [Source: docs/stories/application-dock-general/done/1.5.jwt-authentication.story.md]

**Atomic write reuse.** `_atomic_write_json(path, payload)` lives in `backend/app/repositories/session_repo.py:39`; `auth_repo` imports it across the module boundary. Follow that precedent. There is a known deferred item to extract it into a shared `core/` util — **out of scope here**, just mirror the existing pattern.

**`settings.data_dir`** is created at import time in `core/config.py`; the app subdir (`context-switch/users/`) is created lazily by the repo on first write.

**Coding standards.** Type hints on all public signatures; `pathlib` over `os.path`; f-strings. [Source: docs/architecture/coding-standards.md]

- [x] [Review][Defer] Corrupt/invalid on-disk JSON is unhandled in `read_doc` — a corrupt file raises `json.JSONDecodeError` (a `ValueError` subclass); it surfaces as `500` via `GET /lists` but as `422` leaking the raw parser message (e.g. "Expecting value: line 1…") via `POST`/`PUT`, because the router catches `ValueError`. [backend/app/repositories/context_switch_repo.py:65] — deferred, pre-existing platform-wide pattern (already logged for archery/hotaru); worth a platform-wide `json.loads` hardening pass. Note the context-switch-specific 422-leak wrinkle when fixing.
- [x] [Review][Defer] `_validate_username` hardening for Windows is absent — reserved device names (`CON`/`AUX`/`NUL`/`PRN`/`COM1`…), case-insensitive collision (`Alice` vs `alice`), trailing-dot collision (`name.` vs `name`), and drive-colon (`C:evil`) are not rejected. Harmless on the Linux/Docker deployment target and the username is JWT-sourced, but the docstring's "can never escape the users/ directory" overstates the guarantee on Windows. [backend/app/repositories/context_switch_repo.py:28] — deferred, platform-dependent hardening
- [x] [Review][Defer] `read_doc`/`migrate()` does not reject an unknown *future* `schema_version` — a doc written by a newer version validates as v1 and silently drops unknown fields, which are then lost on the next `write_doc`. Only v1 exists today. A cheap guard: `if raw.get("schema_version", 1) > _CURRENT_SCHEMA_VERSION: raise ValueError(...)`. [backend/app/repositories/context_switch_repo.py:48] — deferred, forward-compat, only v1 exists
