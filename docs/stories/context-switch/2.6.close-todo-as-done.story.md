# Story 2.6: Close a todo as done (archive)

Status: Draft

## Story

As a user,
I want to close a todo as done,
so that it leaves my active board once it's finished.

## Acceptance Criteria

1. **Close as done → archived.** Given an open todo, when I close it as done (`PATCH /api/context-switch/lists/{list_id}/todos/{todo_id}` with `{ status: "archived" }`), then it is set `status: "archived"` with an `archived_at` timestamp, and it is kept in my file (not deleted). (FR-12)

2. **Removed from the active board.** Given a todo just archived, when the board re-renders, then it no longer appears among the active pills; only active todos are laid out in the grid. (FR-12)

3. **Excluded from active order.** Given an archived todo, when the active order/grid is computed, then it is excluded from the active sequence (it does not occupy a grid slot or an `order` position). (FR-9, FR-12)

4. **Terminal in this story.** Given an archived todo, when viewing the active board, then there is no reopen affordance here — archived todos are reached and managed only via the archive view (Story 2.7). (FR-13)

5. **Unknown ids → 404.** Given the PATCH for ids not in my file, when requested, then the API returns `404`.

## Dev Notes

**Archive = soft, via the shared todo-PATCH.** Archiving is just `status: "archived"` on the existing `PATCH …/todos/{todo_id}` (Story 2.4) — not a separate endpoint and not a delete. The record stays in the file for the archive view. [Source: user decision — "Archived / hidden (recoverable via archive view)"]

**Terminal by design.** There is no "reopen" in v1 (user chose view + delete only for the archive). If reopen is wanted later, it is a one-line addition (`status` back to `active`, clear `archived_at`) — leave the door open in the service but ship no UI for it.

**Active vs archived is the core read split.** Every "board" read is active-only; the archive view (2.7) is the only archived read. Centralize the filter in the service so both stories share it.
