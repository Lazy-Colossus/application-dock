# Story 1.1: Register Context-Switch in the Application Dock shell

Status: Ready for Review

## Story

As a user,
I want Context-Switch to appear as an app in the dock and open to its own home screen,
so that I can launch it like any other app in the platform.

## Acceptance Criteria

1. **Card renders on the landing page.** Given the dock landing page, when it loads the app registry, then a Context-Switch card appears (label "Context-Switch", Material icon `swap_horiz`) alongside the Archery and Hotaru cards, and selecting it navigates to `/context-switch`. (FR-1)

2. **Backend advertises the app.** Given `GET /api/apps`, when called, then the response includes a Context-Switch `AppDescriptor` (`id: "context-switch"`, `label: "Context-Switch"`, `icon: "swap_horiz"`, `route: "/context-switch"`) in addition to the existing apps.

3. **Home route resolves behind auth.** Given the route `/context-switch`, when navigated to by an authenticated user, then a lazy-loaded `ContextSwitchHomePage` renders inside `MainLayout` with a page title; unauthenticated access redirects to `/login` (route carries `meta.requiresAuth: true`).

4. **Backend router mounted behind auth.** Given the FastAPI app, when it boots, then a `context_switch` router with prefix `/api/context-switch` is included in `app/main.py` and every route is behind `Depends(get_current_user)` (no endpoints required yet — they arrive in Stories 1.2+; the module exists and is mounted).

5. **Self-contained module + no regressions.** Given the new `src/apps/context-switch/` module, when built, then the shell imports from it only via `registry.ts`; existing `npm test` and `pytest` pass; `black`/`ruff` and the working formatter (Prettier) are clean.

## Dev Notes

**This is the platform's documented "add a new app" flow** (CLAUDE.md → "Adding a new app"): (1) registry entry, (2) lazy route, (3) backend `_APPS` + router, (4) story folders. **Follow Hotaru's Story 1.2 verbatim as the reference** — it is the most recent app-registration and the cleanest template.

**Exact touch-points (read before editing):**
- `frontend/src/apps/registry.ts` — append one `AppDescriptor` (`{id, label, icon (Material Icons name), route}`).
- `frontend/src/router/routes.ts` — append a lazy child route under the `MainLayout` `children` array. **Include `requiresAuth: true`** (the Hotaru routes omit it — that is a pre-existing gap; do NOT copy that omission, since Context-Switch data is per-user and must be behind auth).
- `backend/app/routers/shell.py` — append to `_APPS`.
- `backend/app/main.py` — import `context_switch` and `app.include_router(context_switch.router)`.
- `backend/app/routers/context_switch.py` — NEW: `APIRouter(prefix="/api/context-switch", tags=["context-switch"])`.

**Icon consistency.** Use `swap_horiz` in **both** `registry.ts` and `shell.py` (archery historically differs between the two — do not repeat that inconsistency).

**Scope discipline (YAGNI).** This story is registration + skeleton ONLY. Do NOT build the picker, board, stores, repo, service, or endpoints — those are Stories 1.2+. `ContextSwitchHomePage` is a placeholder proving the app loads behind auth. Keep the backend router endpoint-free. Do NOT create `apps/context-switch/{components,composables,stores}/` yet (added per later story to avoid empty scaffolding).

**Coding standards.** Frontend: `<script setup lang="ts">`, `defineProps<{}>()`/`defineEmits<{}>()`, no `any` without justification, `interface` for object shapes, `type` for unions. Backend: type hints on public signatures. Co-locate `*.spec.ts`. [Source: docs/architecture/coding-standards.md; CLAUDE.md#Conventions]
