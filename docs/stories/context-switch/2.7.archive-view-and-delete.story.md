# Story 2.7: Archive view — browse and permanently delete

Status: Draft

## Story

As a user,
I want to see a list's archived todos and delete them for good,
so that I can review finished work and clear it out.

## Acceptance Criteria

1. **Browse the archive.** Given a list, when I open its archive view (`GET /api/context-switch/lists/{list_id}?include=archived`, or a dedicated archived read), then I see the archived todos (header, text, color, `archived_at`) separated from the active board. (FR-13)

2. **Permanent delete.** Given an archived todo, when I delete it (`DELETE /api/context-switch/lists/{list_id}/todos/{todo_id}`), then it is permanently removed from my file and disappears from the archive. (FR-13)

3. **Terminal — no reopen.** Given the archive view, when rendered, then it offers view + delete only; there is no reopen-to-active affordance in v1. (FR-13)

4. **Delete guarded + scoped.** Given a delete, when triggered, then the UI confirms first; a delete for a `todo_id` not in my file returns `404`; a user can only delete todos in their own file. (FR-2, FR-13)

5. **Active board unaffected.** Given a delete from the archive, when it completes, then the active board is unchanged (delete only ever targets an archived record here).

## Dev Notes

**Delete lives only in the archive.** Per the user's management choices, permanent delete of a todo is reached from the archive view — there is no "delete active todo" path (an active todo is closed as done first, then optionally deleted). If a direct active-delete is ever wanted, it reuses `delete_todo` with a different entry point. [Source: user decisions — "delete archived todos"; no "delete individual (active) todos"]

**Archived read = the counterpart to the active filter (Story 2.6).** Both read the same file; centralize the active/archived split in the service so this view and the board stay consistent.

**Confirm before permanent loss.** Deletion is irreversible (no reopen, no undo in v1) — always confirm. Reuse the confirm pattern from list delete (Story 1.4).
