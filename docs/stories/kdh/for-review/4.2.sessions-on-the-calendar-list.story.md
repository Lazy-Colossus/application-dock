# Story 4.2: See a calendar's sessions from the list

## Status

Ready for Review

## Story

**As** anyone opening KDH,
**I want** each calendar in the list to tell me when its next or last session is,
**so that** I know which one needs my attention without opening any of them.

## Acceptance Criteria

1. **The summary carries both** `next_session` (the nearest chosen day still to come) and `last_session` (the most recent already past), either or both `null`. (FR-5, FR-17)
2. **Today counts as still to come**, consistent with every other boundary in the app. (NFR-5)
3. **The row shows the next session if there is one**, otherwise the last, labelled so you can tell which. (FR-5)
4. **A calendar with no chosen day shows nothing** — no placeholder. (FR-5)
5. **The cached list stays honest** after an admin marks or unmarks a day, so returning to it does not still advertise a session that was called off.

### Completion Notes

- Sending **both** dates rather than one plus a flag keeps the semantics obvious
  and lets the row decide without comparing dates itself. They sort lexically
  because every date in this app is `YYYY-MM-DD`.
- The session sits in the row's **side section**, not a third line: Story 2.5 had
  already taken the subtext for the roster, and a phone row does not hold three
  lines. This deviates from the epic's literal wording, which predates 2.5.
- `syncSessions` recomputes the cached summary from the calendar after a marking,
  using the server's date from `me` — the client still never decides "past" itself.
