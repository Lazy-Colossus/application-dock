# Story 2.8: Study a scope (browse, no grading)

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want to browse a lesson or topic's words one at a time with everything on the card,
so that I can study freely without being graded.

## Acceptance Criteria

1. **Study is a second activity from the picker.** Given the pre-session picker with a chosen scope (Story 2.2), when I choose **Study** (a CTA alongside **"Let's practice ✦"**), then I enter a browse flow over that scope at `/hotaru/study?scope=…`. Both CTAs appear once a scope is selected; Practice → the graded drill (2.3), Study → the browse flow.

2. **All the scope's words, natural order, no cap.** Given `GET /api/hotaru/practice/study?scope=&user=`, then it returns **every** word in the scope in natural (lesson/list) order — **no** SRS weighting, **no** session cap (unlike the drill queue). Privacy holds (a private word appears only for its owner, per FR-7, inherited from the scope resolution).

3. **A single full-info card; "Next word" advances.** Given a study card, when it shows, then one card presents **all** of the word's info at once — the Japanese headword (kanji cyan / kana lamp-yellow per DESIGN), the reading, romaji (if present), the meaning, and the part of speech — with **no** prompt→reveal and **no** grade buttons. A **"Next word"** button simply advances to the next card.

4. **Clean end + empty state.** Given the last card, when I advance past it, then the session ends cleanly (a "that's all" state with a way back to the library), with no penalty, streak, or due-count. An empty scope shows a graceful "nothing to study here" state.

5. **Conventions + no regressions.** The study list is served by `hotaru_practice_service` reusing the existing scope resolution; `Word` carries no debt, so nothing new is needed to keep it calm. HTTP via `useApi`; the practice store exposes `loading`/`error`. `pytest` + `npm test` green; `black`/`ruff` + Prettier clean.

## Dev Notes

**Study is the calm sibling of the drill — deliberately un-graded.** It reuses everything the practice flow already built (scope selection, the picker, `useDrill`'s sequence machine, the neon card language) but drops the SRS: no queue ordering, no cap, no reveal, no grade, no progress persistence. It's browsing, not testing. This is a post-hoc story (not an original FR) — the seed of a "just let me read through these" mode. [Source: epics-hotaru.md#Story 2.8]

**No SRS, no debt — so no new contract concerns.** The study endpoint returns `list[Word]`. `Word` already carries no due-fields, so the queue-not-debt contract isn't even in play here (there's no ordering-by-due). Do NOT sort by familiarity or cap the list — the whole point is the full set in reading order. The only shared machinery with the drill is scope resolution (`_words_for_scope`) and the frontend sequence composable. [Source: architecture.md#Queue-not-debt (n/a here — no due ordering); epics-hotaru.md#Story 2.8]

**Reuse, don't rebuild:**
- `services/hotaru_practice_service.py` — `_words_for_scope(scope, user)` (from 2.2) already parses `lesson:`/`topic:` and enforces privacy. `study_words` is a one-liner over it. **Read** `overview`/`build_queue` for the pattern.
- `composables/useDrill.ts` (from 2.3) — `current`/`index`/`total`/`progress`/`finished`/`next()` fit Study exactly; `reveal`/`revealed` go unused. Feed it a `computed<QueueItem[]>` built from the study `Word[]`. Do **not** write a parallel `useStudy` — reuse.
- `components/Flashcard.vue` (from 2.3) — the visual reference for the neon card + the kanji-cyan/kana-yellow rules. `StudyCard` is its always-revealed, all-fields, no-"Prompt"-label cousin; share the `.hotaru-panel` + drill-glow styling (copy the glow box-shadow, or lift a shared class if it's clean).
- `pages/DrillPage.vue` (from 2.3) — the structural template for `StudyPage` (mount guard → load → useDrill → card + button + done/empty states). `StudyPage` is simpler (no reveal step).
- `pages/PracticeSetupPage.vue` (from 2.2/2.3) — the `startDrill()` + CTA is the template for `startStudy()`; the Home Library button's low-opacity cyan wash (`.hotaru-action--secondary`) is the style reference for the secondary Study CTA.
- `stores/useHotaruPracticeStore.ts` — mirror `loadQueue` for `loadStudy` (returns `Word[]` not `QueueItem[]`).

**Card content (all-info, one side).** The mock's *revealed* drill card is exactly the study card: Japanese headword (large, glowing), reading, romaji, meaning — plus the part of speech, which Study surfaces as a small tag. Colours follow the locked word-row rules: **kanji cyan `#38f0e6`, kana lamp-yellow `#ffd24a`** (reading line is kana → yellow). [Source: DESIGN.md#Components drill-card + word-row; mockups/drill-and-picker.html]

**Scope passing.** Same as the drill: the picker owns scope selection and passes `scope` via the route query (`/hotaru/study?scope=lesson:L2`); `StudyPage` reads `route.query.scope`, redirecting to the picker if it's missing.

**Scope (YAGNI).** Browse + next + clean end + the picker CTA only. No grading, no reveal, no shuffle, no direction, no familiarity icon, no persistence, no "mark as known". [Source: epics-hotaru.md#Story 2.8]

**Coding standards.** Backend type hints + stdlib errors in the service (HTTPException only in the router). Frontend `<script setup lang="ts">`, `defineProps<{}>()`, no `any`, scoped `.hotaru-app` theme, co-located `*.spec.ts`. [Source: docs/architecture/coding-standards.md; CLAUDE.md]
