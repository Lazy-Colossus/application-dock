# Story 2.6: See how well I know each word

Status: Ready for Review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want a gentle, glanceable signal of my familiarity with each word,
so that I can see progress without pressure.

## Acceptance Criteria

1. **A shared `FamiliarityIcon` — icon + colour + label, never colour alone.** Given the 5-tier ramp (New/Learning/Familiar/Strong/Mastered), when a familiarity indicator renders, then it shows a **distinct per-tier glyph** (a uniform circle with a per-tier fill fraction) **coloured** from the `--hotaru-fam-*` tokens **and** carries the tier name as text — always at least an `aria-label`, so colour is never the sole signal (FR-21, UX-DR3, NFR-7). This is one reusable component.

2. **Library word rows show each word's familiarity.** Given the library list, when it renders for the active user, then each `WordRow` shows that word's familiarity indicator (a never-reviewed word reads **New**). The tier comes from the active user's progress.

3. **The pre-session overview uses the same component.** Given the picker's familiarity distribution, when it renders, then each of the 5 tiers is drawn with the shared `FamiliarityIcon` (icon + colour + **visible label**) beside its count — replacing the ad-hoc inline ramp currently in `PracticeSetupPage`.

4. **Per-word familiarity data.** Given `GET /api/hotaru/practice/familiarity?user=`, then it returns a `{word_id: tier}` map of the active user's reviewed words (tiers 0–4); words absent from the map are New (tier 0) client-side. Per-user (path-as-privacy). No due-debt in the response.

5. **Conventions + no regressions.** The tier→glyph/colour/label mapping lives **only** in `FamiliarityIcon` (single source of truth; `tier`/`colour` mapping is a frontend concern per the architecture). HTTP via `useApi`; the store exposes `loading`/`error`. `pytest` + `npm test` green; `black`/`ruff` + Prettier clean.

## Dev Notes

**This makes familiarity *visible* — the read side of the SRS loop.** Story 2.1 modelled tiers, 2.5 moves them; this story surfaces them as a calm, glanceable indicator on the library rows and the pre-session overview. It's presentational + one small read endpoint; no scheduling, no writes. [Source: epics-hotaru.md#Story 2.6; architecture.md#F4]

**One component, one source of truth.** The tier→glyph/colour/label mapping is a **frontend** concern (architecture: "tier→colour/icon mapping is a frontend concern"). Right now that mapping is duplicated inline in `PracticeSetupPage` (the `.tier-glyph--0..4` CSS circles + a local `TIER_LABELS`). This story extracts it into a single `FamiliarityIcon` and has both the overview **and** the word rows consume it — delete the inline copy so there's exactly one ramp definition. [Source: architecture.md#Component map (FamiliarityIcon); DESIGN.md#Components familiarity-icon]

**The glyph is the CSS circle we already validated (not the Unicode ○◔◑◕●).** Uniform-sized circle, per-tier fill via `conic-gradient(currentColor <pct>, transparent <pct>)` inside a `border` ring, coloured `var(--hotaru-fam-{1..5})`, `drop-shadow` glow in the tier hue (New = unglowing hollow ring). This is exactly the treatment already in `PracticeSetupPage` — lift it verbatim into `FamiliarityIcon`. Fills: New 0% · Learning 25% · Familiar 50% · Strong 75% · Mastered 100%. [Source: PracticeSetupPage.vue current `.tier-glyph*`; DESIGN.md familiarity-icon]

**"Never colour alone" on dense rows.** DESIGN says colour + icon + text label always appear together. On the picker overview there's room for the **visible label** (`show-label`). On a library row (already carrying JP + reading + meaning + romaji toggle + tag + edit/delete) a visible per-row label would overflow, so the row uses the icon (its **fill-fraction shape is itself a non-colour signal**) + an always-present **`aria-label`** for the tier name. That satisfies "not colour alone" (shape + SR label) while keeping rows legible; the overview legend is where the words↔labels are learned. If you'd prefer visible labels on rows too, it's a one-prop change (`show-label`). [Source: DESIGN.md#Components (familiarity-icon note + word-row) + Do's/Don'ts]

**Per-word familiarity needs a read endpoint.** The library shows *each word's* tier, but `Word` is pure (no per-user fields) and the queue/overview don't expose per-word tiers. So add a small `GET /practice/familiarity?user=` → `{word_id: tier}` from `progress_repo.read_progress`. Keep `Word` unchanged (word data ≠ user progress). Unreviewed words are simply absent → New (tier 0) client-side. Tiers are familiarity, not due-debt, so there's no queue-not-debt concern. [Source: architecture.md#Data (progress.json {word_id:{tier,...}}); #API]

**"New" now means never studied (from the just-shipped SRS fix).** A word only leaves the `familiarity` map's default (New) once reviewed; any review floors at Learning. So the New icon genuinely means "not started". [Source: srs.next_review; DESIGN.md familiarity note]
