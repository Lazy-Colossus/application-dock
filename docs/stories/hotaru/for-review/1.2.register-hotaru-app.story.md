# Story 1.2: Register Hotaru in the Application Dock shell

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want Hotaru to appear as an app in the dock and open to its own home screen,
so that I can launch it like any other app in the platform.

## Acceptance Criteria

1. **Hotaru card renders on the landing page.** Given the dock landing page, when it loads the app registry, then a Hotaru card appears (label "Hotaru", a Material icon) alongside the Archery card, and selecting it navigates to `/hotaru`. (FR-1)

2. **Backend advertises the app.** Given `GET /api/apps`, when called, then the response includes a Hotaru `AppDescriptor` (`id: "hotaru"`, `label: "Hotaru"`, `icon`, `route: "/hotaru"`) in addition to archery.

3. **Hotaru home route resolves.** Given the route `/hotaru`, when navigated to, then a lazy-loaded `HotaruHomePage` renders inside `MainLayout` with a page title, showing entry actions (at least **Practice** and **Library** — non-functional placeholders are acceptable in this story; they are wired up in later stories).

4. **Backend router mounted.** Given the FastAPI app, when it boots, then a `hotaru` router with prefix `/api/hotaru` is included in `app/main.py` (no endpoints required yet — endpoints arrive in Stories 1.3+; the module exists and is mounted).

5. **Forest-twilight theme is scoped to Hotaru.** Given Hotaru pages render, when displayed, then they use the forest-twilight palette (moss green-brown field, bamboo-green accent, beige/washi surfaces, lamp-yellow, firefly-glow) via **Hotaru-scoped CSS variables** — and the shell landing page and the Archery app remain visually unchanged (the global Carbon theme is NOT modified).

6. **Self-contained module + no regressions.** Given the new `src/apps/hotaru/` module, when built, then the shell imports from it only via `registry.ts`; existing tests (`npm test`, `pytest`) pass; `npm run lint` and `black`/`ruff` are clean.

## Dev Notes

**This is the platform's documented "add a new app" flow** (CLAUDE.md → "Adding a new app"): (1) registry entry, (2) lazy route, (3) backend `_APPS` + router, (4) story folders. Follow the **archery app verbatim as the pattern** — it is the reference implementation of a self-contained app. [Source: CLAUDE.md#Adding a new app; docs/architecture/source-tree.md]

**Exact touch-points (read these before editing):**
- `frontend/src/apps/registry.ts` — UPDATE: append one `AppDescriptor`. It already documents this exact step in its header comment. `AppDescriptor` = `{id, label, icon (Material Icons name), route}`.
- `frontend/src/router/routes.ts` — UPDATE: append a lazy child route under the `MainLayout` `children` array (mirror the `archery` home route; lazy `() => import(...)` per NFR bundle-splitting).
- `backend/app/routers/shell.py` — UPDATE: append to `_APPS` (drives `GET /api/apps`).
- `backend/app/main.py` — UPDATE: import `hotaru` and `app.include_router(hotaru.router)`.
- `backend/app/routers/hotaru.py` — NEW: `APIRouter(prefix="/api/hotaru", tags=["hotaru"])`, mirroring the `archery.py` header. [Source: architecture.md#Project Structure — Backend additions]

**⚠️ Known inconsistency to sidestep, not "fix":** archery's icon differs between `registry.ts` (`adjust`) and `shell.py` (`sports_score`). The frontend landing page renders from `registry.ts`; the backend `/api/apps` is a parallel list. For Hotaru, set the **same** icon in both (`school`) for consistency. Do not touch the archery entries.

**Theme scoping — the one non-obvious design point.** `frontend/src/css/quasar.variables.sass` is the **global Carbon dark theme** used by the shell landing page AND archery. Hotaru's forest-twilight palette must therefore be **scoped to Hotaru only** — define it as CSS custom properties under an app-root class and apply that class on Hotaru pages. Editing the global Sass brand would restyle archery and the shell (a regression). This is a deliberate variance from the epic's looser phrasing ("tokens added to quasar.variables.sass"). [Source: DESIGN.md (palette); architecture.md#Frontend module rules; EXPERIENCE.md#Foundation]

**Forest-twilight token values (from DESIGN.md):** field `#292d1a`/`#1a1d10`, washi surfaces `#ece1c8`/`#f6efda`, bamboo accent `#8caf5d`, lamp-yellow `#ffd24a`, firefly `#fff0a8`, familiarity ramp `#e4a59e`→`#eebf86`→`#d2d088`→`#a6c87e`→`#7aa44d`. Full-bleed, mobile single-column. [Source: DESIGN.md frontmatter tokens]

**Scope discipline (YAGNI).** This story is registration + skeleton ONLY. Do NOT build IdentityPage, the picker, drill, library, stores, or API endpoints — those are Stories 1.3+. The `HotaruHomePage` here is a placeholder that proves the app loads and the theme applies. Keep the backend router endpoint-free.

**Coding standards.** Frontend: `<script setup lang="ts">`, `defineProps<{}>()`/`defineEmits<{}>()`, no `any` without justification, `interface` for object shapes. Backend: type hints on public signatures. Co-locate `*.spec.ts`. [Source: docs/architecture/coding-standards.md; CLAUDE.md#Conventions]
