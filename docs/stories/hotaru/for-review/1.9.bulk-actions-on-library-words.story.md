# Story 1.9: Bulk actions on library words

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want to select several words in the library and act on them at once,
so that I can organize and clean up vocabulary without repeating the same action word by word.

## Acceptance Criteria

1. **Selection mode with a running count.** Given the library list, when I turn on a **Select** mode, then each word row shows a checkbox, I can multi-select words, and a bar shows how many are selected; turning Select off (or switching section/subsection) clears the selection. Mobile-first: the checkboxes and the action bar work one-handed on a narrow screen, and the ＋ FAB / row ⋮ menus step out of the way in Select mode.

2. **Bulk add to topic (any section).** Given a multi-selection, when I choose **Add to topic** and pick an existing topic (or create a new one), then every selected word is added to that topic in one batch (reusing the assign endpoint), respecting per-word visibility (FR-6, FR-7).

3. **Bulk remove from topic (Topics view).** Given I'm viewing a Topic and have a multi-selection, when I choose **Remove from topic**, then the selected words are removed from that topic in one batch (reusing the unassign endpoint).

4. **Bulk delete (Custom words).** Given a multi-selection of **custom** words, when I choose **Delete**, then I confirm once for the whole batch and each word is deleted (a private word only by its owner); seeded words are never offered Delete (they're read-only, per Story 1.8).

5. **Bulk change lesson (Custom words).** Given a multi-selection of **custom** words, when I choose **Change lesson** and give a lesson code, then each selected word's `lesson` updates in place (reusing the update endpoint); seeded words are excluded. _(See Dev Notes — limited visible effect in the current IA; flagged.)_

6. **Ineligible items are reported, not silently dropped.** Given a batch where some words can't be changed (a seeded word, or a server rejection), when the action runs, then it applies to the words it can and the UI reports a brief, calm summary of how many succeeded / were skipped — no silent partial failure, no error page.

7. **Conventions & no regressions.** Bulk actions reuse the existing per-word endpoints (looped client-side); the library store keeps `loading`/`error`; single-word edit/delete/topics (the row ⋮ menu, Story 2.x refinement) and the rest of the library are unchanged. HTTP via `useApi`. `pytest` + `npm test` green; `black`/`ruff` + `vue-tsc` + Prettier clean. **No backend change expected.**

## Dev Notes

**What this story is.** Pure frontend batch-orchestration over the endpoints Epic 1 already ships — no new API. The library grew (seed + custom + topics + the 2.6 familiarity column), and one-at-a-time management via the row ⋮ menu is tedious; Select mode lets you act on many at once. [Source: epics-hotaru.md#Story 1.9]

**Reuse the existing endpoints, loop client-side, refresh once.** Assign `POST /topics/{tid}/words/{wid}?user=`, unassign `DELETE …`, update `PUT /words/{id}?user=`, delete `DELETE /words/{id}?user=` all exist (Stories 1.6–1.8). The per-word store actions (`assignWord`/`unassignWord`/`updateWord`/`deleteWord`) each trigger their own `loadWords`/reload — so **don't loop those** (N reloads). Instead the new bulk helpers call `api.*` directly per item and reload **once** at the end. Best-effort per item (a seeded word or a foreign private word returns 403/404 → counts as `failed`/skipped), mirroring `submitGrades`' "never hijack the page error" stance. [Source: useHotaruLibraryStore.ts assignWord/unassignWord/updateWord/deleteWord; routers/hotaru.py]

**Eligibility is mostly enforced by the section you're in.** The library is sectioned: **Custom** (the active user's own words — editable), **textbook** sources (seeded — read-only), **Topics** (a topic's members). So the bulk bar offers **Delete/Change lesson only in the Custom section** (`editable = section === CUSTOM`, the existing computed) and **Remove-from-topic only in the Topics section** (`inTopic`). Add-to-topic is offered everywhere (topics span the master list). Another user's private words never appear in the payload (path-privacy, NFR-2), so they can't be selected. The `{ok, failed}` summary still covers any server-side rejection. [Source: LibraryPage.vue `editable`, sections/subsections, `customWords`/`wordsForTopic`]

**`Change lesson` caveat — flagged.** Custom words are browsed under **Custom → Shared/Private**, *not* grouped by lesson, and seeded words are read-only. So bulk-changing a custom word's `lesson` field updates the data but has **little visible effect** in today's IA (the word doesn't move). It's included to satisfy the epic AC and to be forward-compatible (a future lesson-grouped custom view, or Quick Practice's lesson filter picking it up), but call this out in the completion notes and keep the UI honest (a plain prompt, not a fancy picker). If preferred, it's trivial to drop. [Source: epics-hotaru.md#Story 1.9 AC; AddWordPage lesson handling]

**Selection scope = the current view.** Keep `selectedIds` scoped to the visible list; clear it when the section/subsection changes (avoids cross-section eligibility tangles and stale ids). Simple `Set<string>`; a row is selected iff its id is in the set. [Source: LibraryPage visibleWords]
