# Story 2.7: Finish with a session summary

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want a small recap when I finish a session,
so that the session feels complete.

## Acceptance Criteria

1. **A recap replaces the bare "Session complete" end screen.** Given a completed session (the queue is exhausted), when the end screen shows, then it presents a calm summary — the scope label, **words practised this session**, and **how many remain in that scope** — in place of today's plain "Session complete." line (FR-17). It keeps the existing **"Back to practice"** button (same `data-testid="drill-done-btn"`, same return-to-picker-with-`?scope=` behaviour).

2. **Reflects updated familiarity.** Given the session's grades have synced, when the summary renders, then it shows the scope's **post-session familiarity distribution** (the 5 tiers with counts, via the shared `FamiliarityIcon`), so the learner sees their familiarity firmed up (FR-17, FR-21). The distribution is read **after** the session's grades are persisted (no stale, pre-session numbers).

3. **"Remaining in scope" is honest.** Given the scope has more words than a single capped session (default 20), when the summary shows "remaining", then it reports `scope word_count − practised` (never negative), making clear a big lesson isn't finished in one sitting — with no due-count or backlog framing (FR-18, NFR-5).

4. **Calm — no streak/debt.** Given the summary, when it renders, then it shows **no** streak, points, due-count, "overdue", or urgency language; microcopy stays in the calm register ("Session complete", "Practised N", "M to go"). (FR-18, UX-DR9)

5. **Degrades gracefully.** Given the post-session stats fetch fails or is slow, when the summary renders, then it still shows what it knows locally (words practised) and never replaces the completed session with a page-level error; a brief loading state is acceptable while the stats load.

6. **Conventions & no regressions.** HTTP via `useApi`; the practice store keeps `loading`/`error`; the grade sync loop (Story 2.5) and drill flow (2.3/2.4) are unchanged except for the end screen. `pytest` + `npm test` green; `vue-tsc` + Prettier clean (no backend code change expected — the summary reuses `GET /practice/overview`).

## Dev Notes

**What this story is.** The drill's end screen is currently a bare "Session complete." + "Back to practice" (`DrillPage.vue`, the `v-else-if="finished"` block). This story turns it into the calm recap FR-17 asks for: practised count, remaining-in-scope, and the updated familiarity distribution — still debt-free (FR-18). Purely the end screen + a best-effort stats read; the drill loop, grading, and sync are untouched. [Source: epics-hotaru.md#Story 2.7; prd FR-17/FR-18; DESIGN.md familiarity ramp]

**"Practised" is a local counter, not the queue length.** Count grades through `onGrade` (a `ref` incremented there). Both self-grade and typed-Correct route through `onGrade` (verified in Story 2.4), so it's the one true choke-point. Don't derive it from `index`/`total` — an explicit counter is clearer and won't drift if the flow changes. At the `finished` screen it equals the cards graded. [Source: DrillPage.vue onGrade; useDrill.grade]

**"Remaining" needs the scope's word_count — reuse the overview endpoint.** The drill only holds the (≤20) queue, not every scope word, so `word_count` + the familiarity distribution come from `GET /practice/overview?scope=&user=` — the same endpoint the picker uses (returns `{scope, word_count, familiarity[5]}`, queue-not-debt). `remaining = max(0, word_count − practised)`. No new endpoint, no backend change. [Source: backend routers/hotaru.py practice_overview; hotaru_practice_service.overview; types.ts PracticeOverview]

**Read stats AFTER the grades sync — fix the flush race here.** The summary's familiarity must reflect this session's grades, so the post-session fetch must run after `pending` is fully drained to the server. Today `flushGrades` guards with `if (!drillUser || flushing) return;` — a concurrent caller (the `finished` watcher) returns **early** while the last `onGrade`'s flush is still in flight, so a naive `await flushGrades()` wouldn't actually wait. Change the guard to **await the in-flight drain**: keep a module-level `flushPromise`; when a call arrives while flushing, return that promise; otherwise start a drain, assign it to `flushPromise`, and clear it when done. Then `await flushGrades()` reliably resolves once everything is synced. This is the clean fix for the off-by-one race flagged in Story 2.5's follow-up. If the sync ultimately fails (offline), `fetchOverview` returns `null` and the summary degrades to the practised count only (AC-5). [Source: DrillPage.vue flushGrades/onGrade/finished watch; Story 2.5 completion notes]

**Best-effort fetch, never hijack the page.** `store.loading`/`store.error` drive DrillPage's **page-level** `v-if` branches (loading spinner / full-page error) — so do **not** call the picker's `loadOverview` here (it flips `store.loading`, which would replace the just-completed summary with "Loading…", and route a fetch failure into the full-page error). Add `fetchOverview` as a pure getter returning `PracticeOverview | null` (same philosophy as `submitGrades`), and hold a **local** `summary` ref in `DrillPage`. [Source: DrillPage.vue store.loading/store.error branches; useHotaruPracticeStore.submitGrades]

**Files to read before editing (and what must be preserved):**
- `pages/DrillPage.vue` — the `finished` block (keep `drill-done` + `drill-done-btn` + `backToPicker`); `onGrade` (single grade path); `flushGrades` (make awaitable; keep re-queue-on-failure, the `onBeforeUnmount` + user-switch flushes); `scopeLabel`; `drillUser` (grades/stats attributed to the session's user even after a switch). Don't disturb the active-drill / empty / loading / error branches. [Source: DrillPage.vue]
- `stores/useHotaruPracticeStore.ts` — `loadOverview` (leave for the picker), `overview`/`clearOverview`, `submitGrades` (best-effort template). Add `fetchOverview` alongside. [Source: useHotaruPracticeStore.ts]
- `components/FamiliarityIcon.vue` — reuse as-is (`:tier` + `show-label`) for the tier rows, exactly like the picker overview. [Source: PracticeSetupPage.vue overview block]

**Scope (YAGNI).** End-screen recap only. **NOT** here: per-word "leveled up" deltas (would need pre/post tiers per word — the distribution is enough); a separate `/summary` endpoint; persisting session history; any change to grading maths, `srs`, or `POST /practice/grades`; charts/animations. [Source: epics-hotaru.md#Story 2.7]
