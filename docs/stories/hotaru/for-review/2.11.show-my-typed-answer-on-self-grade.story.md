# Story 2.11: Show my typed answer on self-grade

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

_Added 2026-07-19 — refines FR-14 (typed scoring). In typed mode (EN→JP) an exact match auto-grades Correct, but a miss reveals the answer + the self-grade buttons — without showing what the learner typed, so they can't fairly judge a near-miss. Show the submitted answer, quietly, beneath the (unchanged) answer._

## Story

As a learner drilling in typed mode,
I want to see what I typed next to the correct answer when I miss,
so that I can fairly judge whether I was Correct, Close, or Incorrect.

## Acceptance Criteria

1. **Show the submitted answer on a typed miss.** Given typed mode (EN→JP), when I submit a reading that is **not** an exact match and the answer reveals, then my submitted text appears beneath the answer as a quiet, secondary line labelled "you wrote", above the grade buttons.

2. **The answer stays the hero.** Given the reveal, when it renders, then the correct answer is **unchanged** — same prominence, cyan/magenta glow, kanji — and the "you wrote" line is visibly subordinate (muted `--hotaru-sage`/cream, smaller). No diff, no highlight, no colour-coding of the attempt (per the 2026-07-19 decision-log entry).

3. **Empty submission.** Given I submit with nothing typed, when the answer reveals, then the line reads "you wrote —" (em-dash) — calm, no scolding.

4. **Only when there's a typed attempt.** Given self-grade mode (or JP→EN), when a card reveals, then **no** "you wrote" line shows (there's nothing submitted). Given an exact typed match, then it auto-grades Correct with no reveal (unchanged), so the line never shows there either.

5. **Clears on advance; no regressions.** Given I grade and advance, when the next card shows, then the previous submission is gone (the typed input already resets on grade). The typed-match / self-grade / direction-toggle flows are otherwise unchanged. `npm test` green; `vue-tsc` + Prettier clean.

## Dev Notes

**Tiny, additive, and the design is already decided.** The 2026-07-19 decision-log entry rejected the diff-highlight variants: keep the answer reveal exactly as-is (the hero), and show the typed answer as a quiet muted line beneath it — no diff, no colour verdict. This story is that line plus the one prop to feed it. [Source: docs/planning-artifacts/ux-designs/ux-application-dock-2026-06-10/.decision-log.md#2026-07-19]

**Where the state already is.** `DrillPage.submitTyped` already does: exact `typedAnswer.trim() === word.reading` → `onGrade("correct")` (no reveal); else `reveal()`. `typedAnswer` persists through the reveal and is cleared in `onGrade`. So on a miss, `typedAnswer` is exactly the thing to show; nothing else needs to change in the submit/grade path. The `typing` computed already gates typed mode. [Source: pages/DrillPage.vue submitTyped/onGrade/typing/typedAnswer]

**Render it inside the card, under the answer — not below the card.** The decision is "under the answer," so put it in `Flashcard`'s reveal block (keeps the answer + attempt as one visual unit) rather than in `DrillPage` between the card and the grade buttons. `Flashcard` stays presentational: it takes `submitted` and renders; it doesn't know about "typed mode". [Source: Flashcard.vue m2r answer block; decision-log]

**`null` vs `""` matters.** `null` = self-grade / JP→EN → render nothing. `""` = typed mode, nothing typed → render "you wrote —". A plain `v-if="submitted"` would wrongly hide the empty case, so gate on `submitted !== null`. [Source: this story AC-3/AC-4]

**Files to read before editing:**
- `components/Flashcard.vue` — the `r2m`/`m2r` prompt/reveal split; add the line in the `m2r` reveal answer block, styled subordinate. Reuse the notes-strip's muted treatment as a size/colour reference (don't hardcode). [Source: Flashcard.vue]
- `pages/DrillPage.vue` — `submitTyped`, `onGrade`, `typing`, `typedAnswer`, and the existing `<Flashcard>` props; add one prop, change nothing else. [Source: DrillPage.vue]

**Scope (YAGNI).** Show the submitted attempt. **NOT** here: a computed diff/similarity, an auto-suggested grade, a score/percentage, or any change to the answer reveal or the self-grade buttons. [Source: decision-log 2026-07-19 non-goals]

**Coding standards.** `<script setup lang="ts">`, `defineProps` generics, no `any`, co-located `*.spec.ts`, `var(--hotaru-*)`. [Source: docs/architecture/coding-standards.md; CLAUDE.md]
