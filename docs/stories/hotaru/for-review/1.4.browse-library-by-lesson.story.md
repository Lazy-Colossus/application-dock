# Story 1.4: Browse the vocabulary library by Lesson

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want to see the shared vocabulary organized by Genki lesson,
so that I can find the words I'm studying.

## Acceptance Criteria

1. **Master list assembled from the seed.** Given the shipped seed (`backend/app/hotaru_seed/vocab_seed.json`, 738 words), when the library loads, then `GET /api/hotaru/words` returns the Master Vocabulary List assembled as **seed + `vocab_shared` + the active user's `words_private`** (FR-3, FR-9). In this story only the seed exists, so the writable sources contribute nothing; a missing `vocab_shared.json` / `words_private.json` must read as an empty list, never an error.

2. **Schema versioning honored.** Given the seed carries a top-level `schema_version`, when `vocab_repo` reads it, then it runs a `migrate(raw) -> current` step before validating; the current version passes through unchanged.

3. **Word records exposed correctly.** Given a returned word, when serialized, then it carries the full Word record (`id, source, reading, kanji|null, romaji, meaning, pos, lesson, visibility, drill_caps[]`) as snake_case JSON, direct array, no envelope (FR-4).

4. **Filter by Lesson.** Given the library, when I select a Lesson tab (e.g. `G`, `L1`…`L9`), then I see only that lesson's words as rows showing the Japanese, reading, and meaning (FR-5). Lessons are presented in a sensible order (`G` first, then `L1…L9`).

5. **Server-side lesson filter available.** Given `GET /api/hotaru/words?lesson=L2`, when called, then it returns only Lesson L2 words. Given `?user=<id>`, when the id is not a known user, then the request is rejected (422/404); when omitted, the shared master list is returned.

6. **Reachable + calm + no regressions.** Given the Hotaru home, when I tap **Library**, then I land on the library at `/hotaru/library`; a lesson with no words shows a calm empty state (not an error); HTTP goes through `useApi`; the store exposes `loading`/`error`; existing tests pass; `pytest` + `npm test` green; Prettier clean.

## Dev Notes

**This is the first story that reads the seed and renders real vocabulary.** It stands up the Hotaru backend data layer (shared storage helper → `vocab_repo` → `hotaru_vocab_service` → router) and the Library UI. Read-only browsing of the seeded shared list; user-added shared/private words (1.5/1.6) and Topics (1.7) come later — but the **master-list assembly is built now to accommodate them** (seed + shared + per-user private), with the writable sources simply empty in this story. [Source: architecture.md#Data Architecture; #Project Structure — Backend additions]

**Repository decomposition (architecture rule).** One shared `repositories/_storage.py` holds the atomic write/read helpers; thin per-aggregate repos sit on top (`vocab_repo` here; `progress_repo`/`notes_repo`/`topic_repo` in later stories). Repos are the ONLY filesystem code and raise stdlib errors, never `HTTPException`; routers translate. Mirror `session_repo.py`'s `_atomic_write_json` verbatim (write-`.tmp`-then-`os.replace`). [Source: architecture.md#Implementation Patterns — Repository decomposition; docs/architecture/source-tree.md#Backend layering rule]

**Seed is read-only + shipped.** The seed lives at `backend/app/hotaru_seed/vocab_seed.json` (committed, in the image), NOT under `DATA_DIR`. `vocab_repo.read_seed()` resolves it package-relative. Never write to it. Writable state (later) lives under `settings.data_dir / "hotaru" / ...`; repos `mkdir(parents=True, exist_ok=True)` before any write (no writes this story). [Source: architecture.md#Project Structure — seed-location refinement; #Implementation Patterns — Data file & path conventions]

**Master-list assembly + privacy.** `list_words(lesson, user)` = seed (all `shared`) + `vocab_shared` + `read_private(user)`. Private words are read ONLY from the active user's own directory (`users/{user}/words_private.json`) — privacy is the path, never a post-hoc filter. When `user` is omitted, no private words are included. Missing writable files → `[]` (first-run reality). [Source: architecture.md#Authentication & Security — path-as-privacy-boundary; #Core Architectural Decisions — Data Architecture]

**API contract.** `GET /api/hotaru/words?lesson=&user=` → direct array of Word records, snake_case, `{detail}` on error, ISO where relevant. Validate `user` against `VALID_USER_IDS` (from Story 1.3, already in `routers/hotaru.py`). No due-debt/other envelopes. [Source: architecture.md#API & Communication Patterns; CLAUDE.md#API contract]

**Lesson values + ordering.** Seed lessons are strings: `G` (greetings/intro) and `L1`…`L9`. Order for the tabs: `G` first, then `L{n}` by numeric `n` (so `L2` before `L10` if ever added). Lessons are **derived** from the words (no lessons entity/file). Do the derivation + ordering in the frontend store (display concern); the backend just filters by the exact `lesson` string. [Source: architecture.md#Data Architecture — "Lessons derived from lesson+edition (no file)"; Story 1.1 seed]

**Frontend fetch strategy.** Load all words once via `GET /hotaru/words` (738 records, small — NFR-6 keeps them in memory) and filter by lesson **client-side** for instant tab switches; the server `?lesson=` param stays as the documented contract and for direct API use. Pass `?user=<activeUserId>` when a user is active so private words are included once 1.5/1.6 land (harmless now — none exist). [Source: architecture.md#NFR-6; #API]

**WordRow scope.** This row shows only what Story 1.4 covers: Japanese (kanji if present, else reading), reading, meaning. The familiarity colour/icon (Story 2.6) and the shared/private mark (Story 1.6) are deliberately NOT added yet — later stories enrich the same component. Full-bleed, mobile single-column, scoped `.hotaru-app` theme (reuse `--hotaru-*` tokens from Story 1.2). [Source: DESIGN.md WordRow; EXPERIENCE.md#Information Architecture — Library]

**Store pattern.** Pinia setup store like `useArcheryHistoryStore` / `useHotaruUserStore`: `ref`s + `loading`/`error`, actions set `loading` in `try/finally`, errors → `error.value`. All HTTP via `import { api } from '@/composables/useApi'`. [Source: CLAUDE.md#Frontend; source-tree.md#Frontend boundary rules]

**Scope discipline (YAGNI).** Build read-only browse-by-lesson only. Do NOT build: add-word, shared/private toggles, topics, familiarity display, search, or any writes. Those are later stories. Keep the endpoint and repo assembly forward-compatible (empty writable sources) but don't implement writers.

**Coding standards.** Backend: type hints on public signatures, `pathlib`, f-strings, minimal comments. Frontend: `<script setup lang="ts">`, `defineProps<{}>()`/`defineEmits<{}>()`, `interface` for shapes, no `any` without justification. Co-locate `*.spec.ts`. [Source: docs/architecture/coding-standards.md]
