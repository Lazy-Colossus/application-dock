# Story 2.9: Quick Practice (presets across the whole library)

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want a "Quick Practice" option when I haven't picked a lesson or topic,
so that I can start a focused session drawn from my whole vocabulary using presets, without hand-picking a scope.

## Acceptance Criteria

1. **Quick Practice lives in the all-words view.** Given the Practice screen with **no** Lesson/Topic selected (the all-words summary from Story 2.7-era picker), when it renders, then a **Quick Practice** panel appears alongside the all-words stats — offering preset ways to build a session from the whole (visible, privacy-correct) list. Scoped practice (a chosen Lesson/Topic → the CTA row) is unchanged (FR-10 extension).

2. **Familiarity preset.** Given the Quick Practice panel, when I pick a **familiarity** preset — *Needs work* (New/Learning/Familiar), *Seen once* (Learning…Mastered), *Any*, or a single tier (*Learning*/*Familiar*/*Strong*/*Mastered*) — then the session is built from words at those tiers **across all lessons/topics** for the active user (FR-19, FR-20, FR-21).

3. **Lesson/level preset.** Given the panel, when I select one or more **lessons** (multi-select; none selected = all lessons), then the session is restricted to the union of those lessons — combinable with the familiarity preset (FR-5, FR-10 extension).

4. **Live count + calm empty state.** Given a chosen preset, when it changes, then the panel shows how many words currently match, and the **Quick practice** CTA is disabled with a calm "nothing matches" note when the count is 0 — never an error (NFR-5).

5. **Building the session obeys the drill rules.** Given I launch Quick Practice, when the queue is built (`GET /practice/queue?scope=all&tiers=&lessons=&…`), then it is SRS-ordered (weakest/due first), `drill_caps`-filtered for the direction, soft-capped to the session size (default 20), and carries **no** due-debt — identical to a scoped drill, only the word set differs (FR-12, FR-18, FR-19, NFR-5). The drill runs through the existing flow (2.3–2.7) unchanged.

6. **Remembered per user.** Given the active user's last-used Quick Practice preset, when I return to the picker, then it's restored (persisted per user) so re-entry is quick.

7. **Conventions & no regressions.** HTTP via `useApi`; stores keep `loading`/`error`; scoped practice, Study, and the drill are untouched except for the new optional queue filters. `pytest` + `npm test` green; `black`/`ruff` + `vue-tsc` + Prettier clean.

## Dev Notes

**What this story is.** Quick Practice is "practice from the whole list by preset" — it **extends** FR-10 (which scopes a session to exactly one Lesson/Topic). Mechanically it's the existing `scope=all` queue (Story 2.7-era) **plus two optional filters** (familiarity tiers, a lesson set), launched into the unchanged drill (2.3–2.7). No new endpoint, no new page, no change to grading/SRS/summary. [Source: epics-hotaru.md#Story 2.9; prd FR-10/FR-19/FR-20]

**`scope=all` already exists — build on it.** `_words_for_scope` handles `all` → `list_words(user=user)` (every visible word, privacy-correct), added in the all-words-stats work. `build_queue` already reads `progress` for SRS ordering, so tier filtering is a cheap add right there. The JP↔EN direction filter (`direction in drill_caps`) already runs; Quick Practice launches `r2m` (all words qualify), and the per-session direction toggle (2.4) still works mid-drill. [Source: hotaru_practice_service.build_queue + _words_for_scope; Story 2.7 all-scope]

**Client-side preview count — a deliberate deviation from the epic's "extend overview too".** The epic suggests extending both queue and overview with preset params. I extend **only the queue** (the thing that must be SRS-ordered server-side) and compute the picker's live match count **client-side** from `store.words` + the familiarity map (Story 2.6's `loadFamiliarity`/`familiarityTier` on the library store). Why: the picker already holds the full word list and can show an instant count with no per-chip-tap network round-trip; the launched queue remains the server's authoritative filtered set, so there's a single source of truth for *what's actually practised*. The preview is an estimate for the default `r2m` launch (where `drill_caps` excludes nothing), so it matches. Note this in the completion notes. [Source: epics-hotaru.md#Story 2.9 (overview-extension suggestion); Story 2.6 loadFamiliarity/familiarityTier]

**Persist the preset client-side, per user.** "Remembered per user" doesn't need a new backend file/repo — the app already keeps identity in `localStorage` (`hotaru.activeUser`). Store the Quick Practice preset under `hotaru.quick.<userId>`; restore on mount. This keeps 2.9 to a queue-filter + picker-panel change and avoids a whole user-settings persistence layer (YAGNI). If a server-side setting is ever wanted, it's a clean follow-up. [Source: identity-in-localStorage pattern (Story 1.3); epics-hotaru.md#Story 2.9 AC "persisted per user"]

**Preset → tiers mapping (put it in one place in the picker):**
`Needs work → [0,1,2]` · `Seen once → [1,2,3,4]` · `Any → null (no tier filter)` · `Learning → [1]` · `Familiar → [2]` · `Strong → [3]` · `Mastered → [4]`. Default `Needs work`. Tier 0 = New = never studied (the SRS model from 2.1/2.5). [Source: srs tiers; FamiliarityIcon labels]
