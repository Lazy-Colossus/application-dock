# Story 2.1: Spaced-repetition engine & familiarity model

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want the system to track how well I know each word and decide what's worth showing,
so that practice focuses on what I'm shaky on without me managing it.

## Acceptance Criteria

1. **Pure `next_review(state, grade, now)`.** Given a pure `services/srs.py`, when `next_review(state, grade, now)` is called with an **injected** `now` (no internal clock), then it returns an updated `{tier, points, last_reviewed_at}`:
   - **Correct** → +1 point; on reaching the tier's advancement threshold (`[1, 3, 9, 18]` = points to leave New→Learning→Familiar→Strong) → +1 tier and points reset to 0. At the top tier (Mastered) it holds.
   - **Close** → holds the tier, no point change.
   - **Incorrect** → drop one tier (floored at New) and reset points to 0.
   - `last_reviewed_at` is set to the injected `now`. (FR-20)

2. **Due is derived, never persisted.** Given a word's `{tier, last_reviewed_at}`, when "due" is evaluated, then it derives from `last_reviewed_at + interval[tier]` with `interval = [same-session(0), 1d, 3d, 7d, 21d]` (one per tier 0–4); a never-reviewed word (`last_reviewed_at is None`) is always due. This value is **computed on demand only** — it is never written to `progress.json` and never returned as a count.

3. **`progress_repo` owns per-user state.** Given `progress_repo`, when state is read/written, then it uses `users/{user}/progress.json` holding `{word_id: {tier, points, last_reviewed_at}}`; it is the only filesystem code for progress and raises stdlib errors. `services/srs.py` has **no file or clock dependency**.

4. **Purity & isolation, proven by tests.** Given `srs.next_review`, when table-tested at every tier/point boundary (advance, hold, drop, floor, top-tier hold, points reset), then results match the spec deterministically. Given two users, when each writes progress, then one user's `progress.json` never contains the other's state (path-as-privacy). `black`/`ruff` clean; full `pytest` green (no regressions).

## Dev Notes

**This is the one non-trivial algorithm, and it is deliberately pure.** `services/srs.py` is a pure, deterministic function with an **injected `now`** — no `datetime.now()` inside — so it is fully table-testable. State per (user, word) = `{tier, points, last_reviewed_at}`. This story delivers ONLY the engine + persistence; the picker (2.2), queue (2.3), grade endpoint (2.5), and familiarity UI (2.6) build on it later. [Source: architecture.md#SRS & Familiarity; #SRS service purity]

**The model (single source of truth for the numbers):**
- **5 tiers / intervals:** New `same-session (0)` · Learning `1d` · Familiar `3d` · Strong `7d` · Mastered `21d` (index = tier 0–4). [Source: architecture.md#SRS & Familiarity]
- **Advancement cost (points to leave a tier):** `[1, 3, 9, 18]` for New→Learning→Familiar→Strong. A single tunable array; Mastered is terminal (no 5th threshold). [Source: architecture.md — "Exponential advancement cost … `[1, 3, 9, 18]`"]
- **Grade → points:** Correct +1 (on reaching threshold → +1 tier, points reset 0); Close holds (+0); Incorrect drops one tier (floor New), points reset 0. [Source: architecture.md#SRS & Familiarity; epics-hotaru.md#Story 2.1]
- **Due:** derived (`last_reviewed_at + interval[tier]`), never persisted, never surfaced as a count. Familiarity `tier` later drives the UX colour/icon ramp (frontend concern, not here). [Source: architecture.md — "Due is derived … never persisted"; "tier→colour/icon mapping is a frontend concern"]

**Calm guardrail is a contract, enforced downstream.** "Due" exists here purely to order the queue later (Story 2.3); it must **never** be persisted or exposed as a due-count/overdue/`next_review_at`. Keeping `due_at`/`is_due` as compute-only helpers (not fields on `ProgressEntry`) is how 2.1 upholds that. [Source: architecture.md#Queue-not-debt; NFR-5]

**Layering / files to add (no existing files change except the shared schema):**
- `schemas/hotaru.py` — has `Word`, `Topic`, `CreateWordRequest`/`UpdateWordRequest`, `Visibility`, `DrillCap`. **Add** `Grade`, `ProgressEntry`. (Architecture also lists future `GradeItem`, `QueueItem` — NOT this story; they arrive with 2.3/2.5.)
- `services/srs.py` — **NEW**, pure. Imports `schemas` + stdlib only.
- `repositories/progress_repo.py` — **NEW**, mirrors `topic_repo.py` (which this story can copy structurally: `_storage.read_json`/`atomic_write_json`, per-aggregate helpers).
- Nothing in `routers/` changes yet — 2.1 has **no HTTP endpoint** (the practice endpoints come in 2.2/2.3/2.5). No frontend.

**Purity checklist (verified by test + review):** `srs.py` contains no `datetime.now()`, no `time.`, no repo import; `next_review` returns a fresh `ProgressEntry` and never mutates its argument; `ProgressEntry` has no `due`/`next_review_at` field. [Source: architecture.md#Non-negotiable constraints — "keep `srs.py` pure with injected `now`; keep debt out of response schemas"]

**Datetime handling.** Use timezone-aware UTC datetimes end-to-end. Inject `now` in tests as fixed aware datetimes (e.g. `datetime(2026, 1, 1, tzinfo=timezone.utc)`). Pydantic v2 round-trips ISO 8601 through `model_dump(mode="json")` / `model_validate`, which `progress_repo` uses for the atomic write. Store `last_reviewed_at` as the ISO string it serializes to; `read_progress` re-validates it back to a `datetime`.

**Coding standards.** Backend type hints on all public signatures; `pathlib`; f-strings; stdlib exceptions in service/repo (no `HTTPException` — there's no router here anyway). Tests in `backend/tests/` as `test_*.py`; the autouse `conftest.py` fixture wipes `DATA_DIR/hotaru` between tests, so progress files start absent. [Source: docs/architecture/coding-standards.md; CLAUDE.md; backend/conftest.py]
