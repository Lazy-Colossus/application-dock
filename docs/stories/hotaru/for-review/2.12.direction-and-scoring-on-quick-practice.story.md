# Story 2.12: Direction & Scoring on Quick Practice

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

_Added 2026-07-19 — refines Quick Practice (Story 2.9). The Direction (JP→EN / EN→JP) and Scoring (Self-grade / Typed) controls exist for a chosen scope but not for Quick Practice, which always launched JP→EN self-grade. Surface the same controls on the Quick Practice flow and pass them through._

## Story

As a learner using Quick Practice,
I want to choose the direction and scoring the same way I can for a lesson or topic,
so that a whole-library session isn't locked to JP→EN self-grade.

## Acceptance Criteria

1. **Direction + Scoring on Quick Practice.** Given the Quick Practice view (no scope selected), when it renders, then the **Direction** (JP→EN / EN→JP) and **Scoring** (Self-grade / Typed) controls are present — the same segmented controls used for a chosen scope.

2. **They drive the launched session.** Given I set Direction and/or Scoring in Quick Practice, when I start (`Quick practice ✦`), then the drill launches with those choices (`direction`/`mode` in the route query), not the hardcoded `r2m`/`self`.

3. **Typed stays EN→JP-only.** Given Quick Practice, when Direction is JP→EN, then Typed is disabled and Scoring is Self-grade (the existing `setDirection` rule: choosing JP→EN forces Self-grade); switching to EN→JP re-enables Typed. (Same constraint as the scoped picker.)

4. **Scoped picker unchanged.** Given a chosen Lesson/Topic, when it renders, then Direction + Scoring + the Study/Practice CTAs behave exactly as before (no regression). The shared `direction`/`mode` state is reused.

5. **Quality gate.** `npm test` green; `vue-tsc` + Prettier clean. No backend change (the drill already reads `direction`/`mode` from the query).

## Dev Notes

**One block, two flows — no duplication.** The `.practice-opts` Direction/Scoring markup + its styles already live in `PracticeSetupPage`; the only reason Quick Practice didn't show them was the `selected !== null` gate. Removing it (the block sits inside the `v-else-if="practice.overview"` panel, which is present for the all-words view too) surfaces the same controls with zero new markup or styles. The `direction`/`mode` refs and `setDirection` are shared, so the choice carries between the quick and scoped views. [Source: pages/PracticeSetupPage.vue `.practice-opts`, `direction`/`mode`/`setDirection`, `startQuick`]

**The only real wiring is the query.** `startQuick` currently hardcodes `direction=r2m` + `mode=self`; the scoped `startDrill` already uses `direction.value`/`mode.value`. Make `startQuick` do the same. The drill (`DrillPage`) already parses `direction`/`mode` from the route query — **no backend, no store, no drill change**. [Source: PracticeSetupPage.startQuick vs startDrill; DrillPage route.query.direction/mode]

**Typed constraint is already enforced.** `setDirection('r2m')` forces `mode='self'`, and the Typed button is `:disabled="direction === 'r2m'"`. Reusing the same block means Quick Practice inherits this for free — a JP→EN quick session can't be Typed. [Source: PracticeSetupPage setDirection + mode-typed disabled binding]

**Layout note.** Moving `start-quick` below the options keeps a consistent "choose options → launch" order in both flows and avoids the button sitting above its own settings. The count preview (`quick-count`) stays with the presets. [Source: PracticeSetupPage quick block + practice-cta ordering]

**Scope (YAGNI).** Surface + pass Direction/Scoring on Quick Practice. **NOT** here: persisting direction/mode with the quick preset (the scoped picker doesn't persist them either — keep parity), any new preset, or backend changes. [Source: Story 2.9 quick persistence saves preset+lessons only]
