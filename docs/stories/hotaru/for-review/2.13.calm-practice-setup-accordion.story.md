# Story 2.13: Calm the Practice setup screen (collapsed accordion)

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

_Added 2026-07-19 — the Practice setup screen (`PracticeSetupPage`) grows too tall on a phone. Lessons and Topics are meant to become full, browsable lists (not the current horizontal chip strips), and stacking two long lists plus the Quick Practice panel on one scroll is overwhelming. Redesign the screen as a single calm accordion: an ambient familiarity ramp, a collapsible Quick Practice card, and Lessons / Topics as collapsible lists — one region open at a time. Design decided with Sally (Design 1 of the "whole-screen" comparison); Quick Practice opens its settings inline before Start (nothing launches unseen)._

## Story

As a learner opening Practice on my phone,
I want the setup screen to stay short and calm even when my Lessons and Topics lists are long,
so that choosing what to practise never means scrolling past a wall of controls.

## Acceptance Criteria

1. **Ambient familiarity ramp.** Given the screen loads, when it renders, then the whole-library familiarity is shown as a single compact 5-tier ramp bar with a caption (`{n} words · mostly {tier}`) — replacing the old stacked 5-tier rows. Counts and tiers are computed client-side from the already-loaded words + familiarity (no per-scope server `overview` call).

2. **Quick Practice is a collapsible card; settings open before Start.** Given the Quick Practice card, when I tap its header, then its settings unfold inline (Familiarity presets, Lessons, Words-per-session, live count, Direction, Scoring) with a **Start ✦** button at the bottom; collapsed, the card shows a one-line summary of what it will launch. Nothing launches from the collapsed card — you always open the settings first. The launched session and all existing Quick behaviour (presets, per-user persistence, count preview, empty-guard, direction/scoring from Story 2.12) are unchanged.

3. **Lessons & Topics are collapsible lists of rows.** Given the Lessons and Topics sections, when I tap a section header, then it expands to a **vertical list** of rows (one per lesson / topic); each row shows the lesson code / topic name, a mini familiarity ramp for that scope, and its word count. The empty lesson (`""`) is still excluded as a scope. Empty sections show the existing empty message.

4. **One region open at a time.** Given Quick Practice, Lessons, or Topics is open, when I open another, then the previously open one collapses (the screen never shows two expanded regions at once).

5. **Selecting a row opens its actions inline.** Given an expanded list, when I tap a row, then that scope is selected and a drawer unfolds beneath it with **Direction** / **Scoring** and the **Study** / **Practice ✦** CTAs; tapping the same row again deselects it. Launch behaviour (route query `scope`/`label`/`direction`/`mode`, Typed EN→JP-only) is unchanged from today.

6. **Return-from-drill still lands on the scope.** Given I return to setup with `?scope=lesson:L2` (or a topic), when the page mounts, then that section opens and the scope's drawer is shown, with its (freshly reloaded) familiarity reflected in the ramps.

7. **Quality gate.** `npm test` green; `vue-tsc` + Prettier clean. Frontend-only — no backend, store-contract, or drill change.

## Dev Notes

**Why client-side stats.** The page already loads every word (`store.words`) and all familiarity (`store.loadFamiliarity`), and the Quick count already aggregates over them (`store.familiarityTier`). The server `overview` endpoint returned only `word_count` + `familiarity[5]` — both derivable client-side — so computing the ambient ramp and each row's mini-ramp locally removes the async overview juggling and lets the all-words ramp and a selected scope's drawer coexist (the old single `practice.overview` could only hold one). Return-from-drill freshness is preserved because `onMounted` reloads familiarity every mount. [Source: pages/PracticeSetupPage.vue quickCount; stores/useHotaruLibraryStore.ts familiarityTier/loadFamiliarity]

**The testid-collision trap.** Quick's Direction/Scoring and a scope drawer's Direction/Scoring reuse the same `dir-*`/`mode-*` testids and the same shared `direction`/`mode` refs (as today). They must never be in the DOM together. `openSection` is mutually exclusive, so gate Quick's body on `openSection === 'quick'` and each drawer on `selected === scope && openSection === '<section>'`. List **rows** stay in the DOM via `v-show` (so a row is clickable/queryable even when its section is visually collapsed), but each row's **drawer** is `v-if`-gated. [Source: PracticeSetupPage `.practice-opts`, `direction`/`mode`/`setDirection`]

**Reuse, don't reinvent.** Direction/Scoring markup (`.practice-opts`), the Quick chips, `.practice-chip`, `.practice-seg`, `.practice-start`/`.practice-study`, `startQuick`/`startDrill`/`startStudy`/`setDirection`/`scopeLabel`, and the per-user preset persistence all carry over unchanged. New CSS: `.practice-ramp*`, `.practice-qcard*`, `.practice-sec*`, `.practice-row*`, `.practice-drawer`, `.practice-chev`, `.fam-seg--0..4`. Removed CSS: `.practice-overview*`, `.practice-count`, `.practice-tier`, `.quick`/`.quick__title`. [Source: PracticeSetupPage.vue `<style>`]

**Behaviour change to call out.** Today, selecting a scope *replaces* the all-words view and hides Quick Practice. In the redesign, Quick Practice, Lessons, and Topics are permanent sibling regions — selecting a lesson opens its drawer within the Lessons list while the Quick card stays (collapsed) at the top. The old "Quick shows only in the all-words view" behaviour is intentionally gone. [Source: Design 1, whole-screen comparison — approved 2026-07-19]

**Scope (YAGNI).** Frontend-only re-layout. **NOT** here: session recipes (Option P), a bottom sheet (Option C), per-scope tier *counts* in the drawer (the mini-ramp carries the signal), editable presets, or any backend/`overview` endpoint change. The `overview` route can stay server-side for other callers; this page just stops calling it. [Source: Sally comparison — Design 1 chosen over P/C]
