# Story 2.4: Practise in either direction

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want to choose recognition or production — and, for production, type my answer,
so that I can test myself the way I want today.

## Acceptance Criteria

1. **Direction choice in the picker (default JP→EN).** Given a selected Lesson/Topic scope, when the start controls render, then a **JP → EN** (recognition) / **EN → JP** (production) toggle appears near the "Let's practice" CTA, defaulting to **JP → EN**, and the chosen direction is carried into the drill (FR-13). Calm microcopy — bare `JP → EN` / `EN → JP`, no urgency.

2. **JP→EN (recognition) — today's behaviour preserved.** Given JP→EN, when a card shows, then the prompt is the Japanese headword (`kanji ?? reading`, cyan glow) and reveal shows the reading (when there's kanji) + meaning (+ romaji when the aid is on); the furigana aid (kana above a kanji prompt) still applies.

3. **EN→JP (production) — mirrored card.** Given EN→JP, when a card shows, then the prompt is the **English meaning** and reveal shows the **Japanese** (`kanji ?? reading` in the cyan headword style, reading beneath when there's kanji, romaji when the aid is on); the task is to recall/produce the Japanese. Furigana-on-prompt does **not** apply (the prompt is English).

4. **Per-session direction toggle on the drill.** Given an active drill, when I flip a per-session direction toggle, then the remaining cards swap prompt↔answer immediately **without refetching** the queue and **without** losing my place or any pending grades (the `r2m`/`m2r` pair is universal — every word carries both caps — so a re-fetch is unnecessary; document this). The current card re-renders in the new direction.

5. **Direction honoured server-side via `drill_caps`.** Given a direction, when the queue is requested (`GET /api/hotaru/practice/queue?...&direction=`), then it is passed through and `build_queue` filters to words whose `drill_caps` include it (for the JP↔EN pair this excludes nothing, since all words have `r2m`+`m2r`; the mechanism still holds). SRS ordering, soft-cap, and queue-not-debt are unchanged (FR-19, FR-18, NFR-5).

6. **Scoring-mode choice; Typed is EN→JP-only (completes the deferred FR-14).** Given the picker, when the start controls render, then a **Self-grade** (default) / **Typed** scoring toggle appears; **Typed is available only when the direction is EN→JP** (hidden/disabled for JP→EN) and is carried into the drill (FR-14). _This closes the typed path carved out of Story 2.5._

7. **Typed — exact kana match → Correct.** Given Typed mode (EN→JP), when the card shows the English prompt with a kana **text input** and I submit an answer whose trimmed value equals the word's `reading`, then it records **Correct** and advances — no manual reveal or grade needed (FR-14).

8. **Typed — miss → reveal + self-grade.** Given Typed mode, when I submit a non-matching answer, then the card reveals the Japanese answer and presents the existing **Incorrect / Close / Correct** buttons, and the grade I choose is what's recorded (FR-14). (Reuses the Story 2.5 self-grade + optimistic batch-sync path unchanged.)

9. **Conventions & no regressions.** Grades still update optimistically and sync via the existing background batch loop (Story 2.5) — no change to `POST /practice/grades`. HTTP via `useApi`; stores keep `loading`/`error`. No streak/debt/due surfaces anywhere. `pytest` + `npm test` green; `black`/`ruff` + `vue-tsc` + Prettier clean.

## Dev Notes

**What this story is.** The drill (Stories 2.3/2.5) currently hard-codes recognition (`r2m`) and self-grade. This story adds the **direction** dimension (FR-13) and, because production (EN→JP) is the prerequisite that was missing, the **typed scoring mode** (FR-14) that Story 2.5 explicitly deferred. Both are "practise your way" controls on the same drill; keep the calm loop intact. [Source: epics-hotaru.md#Story 2.4 + #Story 2.5 (typed = EN→JP only, deferred); prd FR-13/FR-14]

**The backend already supports direction — this is mostly frontend.** `hotaru_practice_service.build_queue(scope, user, direction="r2m", ...)` already filters `direction in w.drill_caps`, and `GET /practice/queue` already takes `direction: DrillCap` (invalid → 422, tested). Every word's `drill_caps` always contains `r2m` **and** `m2r` (`k2r` only when kanji present — see `_drill_caps`), so the JP↔EN toggle never drops words; the filter still matters conceptually (and for any future k2r-only surface). No new endpoint, no schema change. [Source: backend/app/services/hotaru_practice_service.py build_queue + _drill_caps; routers/hotaru.py practice_queue; test_hotaru_practice.py test_queue_invalid_direction_is_422]

**Direction is a render concern, not a re-fetch.** Because the same word supports both `r2m` and `m2r`, the per-session toggle should just swap which side is prompt/answer on the **already-loaded** queue — instant, no `loadQueue`, no reorder (SRS ordering is direction-agnostic), no loss of `pending` grades. Only the initial fetch passes `direction` (so `drill_caps` filtering runs once). Call this out in a comment so a future reader doesn't add a needless re-fetch.

**Card content per direction (be precise):**
- `r2m` (JP→EN, recognition) — *unchanged from today*: prompt `kanji ?? reading` (60px cyan `.flashcard__jp`); optional furigana (kana above a kanji prompt); reveal → reading (if kanji) + romaji (if aid) + meaning.
- `m2r` (EN→JP, production): prompt = `meaning` (English — a clear large prompt, **not** the cyan JP treatment); reveal → the Japanese headword in the cyan `.flashcard__jp` style + reading (if kanji) + romaji (if aid). No furigana-on-prompt.
[Source: Flashcard.vue current template; DESIGN.md (kanji cyan / kana lamp-yellow, glowing headword); EXPERIENCE.md drill flow]

**Reading-aid adapts to which side shows Japanese.** Today: furigana on the (Japanese) prompt for kanji words, romaji on the reveal. Generalise: furigana only when the *prompt* is Japanese (`r2m` + kanji); romaji when the side being shown is Japanese (the reveal, either direction). Keep the eye toggle, the reserved `.drill-tools { min-height }` (so revealing doesn't resize the card), and the `ふりがな`/`Romaji` labels (label follows what it toggles). [Source: DrillPage.vue aidAvailable/aidOn/toggleAid]

**Typed mode = a pre-reveal input, then fall through.** Only for `m2r`. Before reveal, show a kana input instead of the Reveal button. Exact match (`input.trim() === word.reading`) → record **Correct** and advance (reuse `onGrade("correct")`, which buffers into `pending` and triggers the background flush — do **not** bypass the sync loop). Miss → `reveal()` + the existing `<GradeButtons>` (self-grade), so the miss path is identical to self-grade mode. Compare against `reading` (the kana); romaji/kanji input simply won't match → miss path. No IME enforcement, no partial-credit logic. [Source: epics-hotaru.md#Story 2.5 typed AC; useDrill.grade; DrillPage.onGrade/flushGrades; GradeButtons.vue]
