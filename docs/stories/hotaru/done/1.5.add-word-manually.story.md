# Story 1.5: Add a word manually (+ two-level library)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want to quickly add a word I encountered — and optionally file it into an existing lesson,
so that I'm not limited to the textbook and can organize my own vocabulary.

## Acceptance Criteria

1. **Low-friction create.** Given the Add-word form, when I submit with just **reading** and **meaning** (kanji optional), then the word is created, persisted, and visible in the library immediately (FR-8, realizes UJ-2).

2. **Correct persistence + id + storage file.** Given a submitted word, when created, then it gets a generated `id` `"{source}-{uuid8}"`, computed `drill_caps` (`r2m`+`m2r`; `k2r` iff kanji), `kanji` normalized (`"" → null`); it is written to **`vocab_shared.json` when Shared** or **`users/{active user}/words_private.json` when Private** — the storage file is chosen by **visibility**, independent of the source tag (FR-4, FR-7).

3. **Default = a Custom word.** Given I do NOT tick "Add to a lesson", when the word is created, then `source = <active user id>` (e.g. `dani`) and `lesson = ""`, and it appears in the library under **Custom words → Shared** or **→ Private** per the toggle.

4. **Optional filing into a lesson.** Given I tick **"Add to a lesson"**, when I choose a **Source** and a **Lesson** from the dropdowns (populated with distinct values from the current vocabulary; Lesson filtered to the chosen Source), then the word's `source`/`lesson` are set accordingly and it appears under that **textbook section → lesson** (e.g. **Genki → L2**), not under Custom.

5. **Two-level library.** Given the library, when it renders, then it shows **main sections** with **subsections**: each **textbook source** (e.g. `Genki`) → its **lessons** (G, L1…L9 ordered); and **Custom words** → **Shared** / **Private**. Selecting a section then a subsection lists its `WordRow`s; empty subsections show a calm empty state. A word is "custom" iff its `source` is one of the two user ids; otherwise it's a textbook word grouped by lesson. Private words shown are only the active user's.

6. **Validation + safety.** Given a submission missing reading or meaning, then the API returns `422` + `{detail}` and the form surfaces it; given `POST /api/hotaru/words?user=<id>` with an unknown user, then `404`; writes go through `_storage.atomic_write_json` (repos `mkdir(parents=True)`); concurrent adds never corrupt the file (last-write-wins acceptable).

7. **Conventions + no regressions.** HTTP via `useApi`; stores expose `loading`/`error`; scoped `.hotaru-app` theme; `pytest` + `npm test` green; Prettier clean.

## Dev Notes

**This story does three coupled things:** (a) the first WRITE path (add a word), (b) restructures the Library into **two levels** (textbook source → lesson; Custom words → Shared/Private), and (c) the optional "file into a lesson" flow. They're coupled because a newly-added Custom word needs the Custom section to be visible in. This **evolves Story 1.4's Library** and **pulls the shared/private *browsing* forward from Story 1.6** — 1.6 then refocuses on the 🔒 private-row mark + isolation tests (and visibility editing). [Source: architecture.md#Data Architecture; EXPERIENCE.md#Information Architecture; user IA decision 2026-07-06]

**The model (confirmed):**
- Every word already has `source`, `lesson`, `visibility` — no new fields.
- **Section = derived from `source`.** `source` NOT a user id → a **textbook section** (grouped by `lesson`). `source` ∈ {`dani`,`jake`} → **Custom words** (grouped by `visibility`).
- **Storage file = derived from `visibility`**, NOT source: Shared → `vocab_shared.json`; Private → the *active user's* `words_private.json`. So a Custom word filed into `genki_3`/`L2` (source=`genki_3`) still lives in the writable shared/private file per its visibility, and shows under **Genki → L2**. A private filed word shows there only to its creator (privacy preserved via `list_words(user)` assembly).
- **"Add to a lesson" default off** keeps the common case one-tap: `source = active user`, `lesson = ""` → Custom.

**Existing code to extend (read before editing) — all from Story 1.4 (this session):**
- `repositories/vocab_repo.py` — has `read_seed/read_shared/read_private`, `migrate`, `_SHARED_PATH`, `_private_path(user)`, `_HOTARU_DIR`. Add writers; preserve reads.
- `services/hotaru_vocab_service.py` — has `list_words(lesson, user)` (assembles seed+shared+private, filters by lesson). Add `create_word`; leave `list_words` intact (it already surfaces new words — no change needed for them to appear).
- `routers/hotaru.py` — has `GET /users`, `GET /words`, `VALID_USER_IDS`. Add `POST /words`.
- `schemas/hotaru.py` — `Word`, `DrillCap`, `Visibility`, `HotaruUser`. Add `CreateWordRequest`.
- `stores/useHotaruLibraryStore.ts` — `words`, `loading`, `error`, `lessons`, `wordsByLesson`, `loadWords(user?)`. Add `createWord` + section helpers.
- `pages/LibraryPage.vue` — single-level lesson tabs today; rework to two-level.
- `components/WordRow.vue` — the row (JP/reading/meaning + the romaji toggle just added). Reused as-is; the 🔒 private mark is Story 1.6.

**Word id (user-added).** `f"{source}-{uuid4().hex[:8]}"` — random suffix (runtime), unlike the seed's deterministic positional id. `source` may be a user id (Custom) or a textbook slug (filed). IDs immutable. [Source: architecture.md#Data Architecture — Word IDs]

**Atomicity + LWW.** Full-list read-modify-write in the **service**; atomic write in the **repo** via `_storage.atomic_write_json`. Shared file has two possible writers → last-write-wins, no locking (accepted, low-effort app). [Source: architecture.md#Implementation Patterns; #Core Architectural Decisions]

**Privacy is the path.** Private words are written to / read from only the active user's `users/{user}/` dir; `list_words(user=…)` includes exactly that user's private words, so the other user never sees them — true even for filed-into-Genki private words. Isolation *tests* + the 🔒 UI mark are Story 1.6. [Source: architecture.md#Authentication & Security]

**Dropdowns from current vocab (no new endpoint).** The Add-word Source/Lesson selects read from the already-loaded `store.words` (via `textbookSources`/`lessonsForSource`). Load words on mount if empty. [Source: architecture.md#NFR-6 — small in-memory list]

**Section labels.** Prettify a textbook source for display (e.g. `genki_3` → "Genki 3"); the raw `source` value is what's stored/sent. Keep the mapping trivial and local.

**Scope (YAGNI).** Add create + the two-level browse + optional filing only. Do NOT build: edit/delete words, changing a word's visibility after creation, the 🔒 row mark, isolation tests, Topics (1.7), AI, familiarity display. The visibility toggle is included because create must choose one.

**Coding standards.** Backend type hints + `pathlib`; frontend `<script setup lang="ts">`, `defineProps/Emits<{}>()`, `interface`, no `any`; co-located `*.spec.ts`; scoped theme; full-bleed mobile. [Source: docs/architecture/coding-standards.md; DESIGN.md]
