# Story 2.10: Filter the library by familiarity (and jump there from practice)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

_Added 2026-07-11, drafted 2026-08-26 — the last unbuilt story in the Hotaru epic breakdown. Turns the read-only familiarity signal into a navigational filter. Two of its original acceptance criteria were written against surfaces that **Story 2.13 has since replaced**, so they are restated here against what actually exists; see "Deviations from the epic AC"._

## Story

As a learner,
I want to filter the library by familiarity and jump straight to a familiarity group from Practice,
so that I can find and act on exactly the words at a given level — everything I've mastered, or everything still New.

## Acceptance Criteria

1. **A compact tier filter in the Library.** Given the library, when I use the familiarity filter, then I can select **one or more of the 5 tiers** and the list shows only words at those tiers. The control reuses `FamiliarityIcon` and stays compact (a row of five toggles, not a wide toolbar) — mobile-first, per UX-DR3.

2. **It combines with the existing navigation.** Given a tier filter is active, when I switch section or subsection (textbook source / lesson / Custom / Topics), then the tier filter still applies within the new view — the two filters compose rather than replace each other.

3. **A new "All" section.** Given the Library's section tabs, when I select **All**, then every word visible to me is listed (seeded textbook words and custom words together) with no subsection tabs. *(New in this story — the Library previously had no whole-library view, so a tier filter had nowhere to work across everything.)*

4. **Per-tier counts are visible on the filter.** Given the filter, when it renders, then each tier toggle shows how many words in the **current section/subsection view** sit at that tier, so I can see where the words are before filtering.

5. **Jump from Practice to a filtered Library.** Given a selected Lesson or Topic on the Practice setup screen, when its drawer is open, then it lists the 5 tiers with `FamiliarityIcon` + count, and tapping one navigates to `/hotaru/library?tier={n}&scope={scope}` — landing on that lesson/topic with only that tier shown.

6. **The originating scope is respected.** Given a jump from `lesson:L2`, when the Library opens, then the lesson's own section and subsection are pre-selected; from `topic:{id}`, the Topics section with that topic; from the whole-library ramp, the **All** section. A deep link **overrides** the remembered last-viewed selection.

7. **Filters are clearable and the empty case is calm.** Given a tier filter that matches nothing in the current view, when the list renders, then it shows a calm empty state naming the filter as the reason, and the filter can be cleared to return to the full view in one tap.

8. **Familiarity is never stale.** Given familiarity changed in a session, when I open or return to the Library, then the tiers shown reflect the updated values (`loadFamiliarity` already runs on every mount — this story must not cache around it).

9. **Quality gate.** `.venv/bin/pytest` green; `black`/`ruff` clean; `npm test` green; `vue-tsc` + Prettier + ESLint clean.

### Deviations from the epic AC (decided 2026-08-26)

- The epic AC deep-links from "the Practice **pre-session stats table**". **Story 2.13 deleted that table**, replacing it with ramp bars. The link source is now the **scope drawer** (AC 5). This knowingly reverses 2.13's Dev Note *"NOT here: per-scope tier counts in the drawer"* — that note was about avoiding redundant *information*; here the counts are **navigation**, which is a different job.
- Ramp segments are **not** made tappable: the per-lesson mini-ramp sits inside the row `<button>` (`PracticeSetupPage.vue:52-71`), and a button inside a button is invalid HTML and an accessibility problem.
- The epic AC assumed "no scope → the whole library". The Library had no such view, hence the new **All** section (AC 3).
- **Backend is untouched.** The epic cites `GET /api/hotaru/practice/familiarity`, which already exists and is already loaded by both pages.

## Dev Notes

**Backend: nothing to do.** `GET /api/hotaru/practice/familiarity` exists, and **both** pages already call `loadFamiliarity` on mount. AC 8 is satisfied by not adding caching — it is a "don't break this" criterion, not a feature.

**`store.words` is already the right set for All.** `loadWords(user)` hits `/hotaru/words?user=`, and the backend returns shared words plus that user's own private ones. So the All section needs no new store getter and no new request. [Source: stores/useHotaruLibraryStore.ts loadWords; backend list_words]

**Where the tier filter must sit in `visibleWords`.** The existing computed branches on section (`CUSTOM` → custom words, `TOPICS` → `wordsForTopic`, else `wordsBySourceLesson`). Apply the tier filter **after** that branch returns, so every section gets it for free and AC 2 holds by construction rather than by repetition. [Source: pages/LibraryPage.vue:237-247]

**Counts must be pre-filter.** AC 4's counts describe the *current view*, computed **before** the tier filter is applied — otherwise selecting "Strong" would show `Strong: n` and every other tier at 0, which is useless for deciding where to go next. Compute the branch result once, derive counts from it, then filter.

**Empty means unfiltered.** `activeTiers` empty = show everything. Do not model "no filter" as "all five selected" — clearing would then be indistinguishable from selecting all, and the clear affordance would have nothing to key off.

**Lesson→source is ambiguous by construction.** Lessons live under sources, and nothing prevents two sources listing an `L2`. **Rule: first source, in `textbookSources` order, that lists the code.** Document it inline; it is a deliberate choice, not an oversight. An unresolvable code must not throw — fall back to `ALL`.

**Do not make ramp segments tappable.** The mini-ramp is inside the row `<button>` (`PracticeSetupPage.vue:52-71`). Nesting interactive elements is invalid HTML and breaks keyboard/AT navigation. The drawer is the correct home for the tappable breakdown; it is also where the learner is already looking at that scope.

**The testid-collision trap still applies.** 2.13 gated Quick's `dir-*`/`mode-*` block and each scope drawer on `openSection`/`selected` so exactly one is ever mounted. New drawer content inherits that gating — do not add tier rows outside the existing `v-if`, or two scopes' rows will coexist in the DOM. [Source: Story 2.13 Dev Notes, "The testid-collision trap"]

**Reuse, don't reinvent.** `FamiliarityIcon` (5 tiers, colour + shape + label, the accessibility floor), `tiersOf`/`segStyle`/`dominant` on the practice page, `.library-tab` / `.library-tab--sub` / `.library-tab--active` for the tabs, `.library-state` for empty states, `--hotaru-fam-1..5` for the ramp hues. No new colour tokens.

**Accessibility floor.** `FamiliarityIcon` already pairs colour + shape + label — never let a tier read by colour alone, in the filter or the drawer. Filter toggles need an accessible name and a pressed state (`aria-pressed`), since the visual active state is a colour change. [Source: EXPERIENCE.md Accessibility]

**Scope (YAGNI).** **NOT** here: a backend filter endpoint (the client already holds every word and tier); persisting the tier filter across visits (the section/subsection memory is deliberate; a *filter* that silently survives is a trap — a learner returning to a seemingly-empty library); sorting by familiarity; bulk actions scoped to a tier; tappable ramp segments; a tier filter on the Practice screen itself.

### Completion Notes List

- **Frontend-only, as scoped.** No backend, no store contract change, no new components.
- **`visibleWords` was split in two.** `scopedWords` resolves section/subsection (now including `ALL` → `store.words`); `visibleWords` applies the tier filter on top. Tier counts derive from `scopedWords`, so they keep describing *where the words are* while a filter narrows what is listed — selecting "Strong" does not collapse every other count to 0.
- **Bug caught during implementation:** adding `ALL` as the first section silently broke the first-visit default. Both "first textbook section" finders excluded only `CUSTOM`/`TOPICS`, so `ALL` would have become the default view and the existing "defaults to the textbook lesson" test would have failed. Both call sites now exclude `ALL` too; a regression test was added.
- **Deep link.** `?tier=` accepts a comma-separated list, drops non-integers and out-of-range values, and an empty result means no filter. `?scope=` resolves `all` / `lesson:{code}` / `topic:{id}`; an unresolvable scope falls back to the All section rather than erroring. A deep link takes precedence over the remembered `activeSection`/`activeSubsection`.
- **Lesson→source ambiguity** is resolved by "first source, in tab order, that lists the code", documented inline at the helper. Nothing prevents two sources sharing an `L2`; this is a stated choice, not an oversight.
- **The jump lives in the scope drawer**, not on ramp segments — the mini-ramp is inside the row `<button>` and nesting interactive elements is invalid HTML. The breakdown is driven by a single `selectedTiers` computed derived from `selected`, which is safe because 2.13's accordion guarantees exactly one drawer is mounted; a test asserts that invariant so the shared `scope-tier-*` testids cannot collide.
- **Accessibility.** Filter toggles carry `aria-pressed` and an `aria-label` naming tier and count; the drawer rows use `FamiliarityIcon` with `show-label`, so no tier is ever conveyed by colour alone.
- **Zero-count tier rows are inert** — both `disabled` and guarded inside `openInLibrary`, so a jump can never land on an empty filtered view.
