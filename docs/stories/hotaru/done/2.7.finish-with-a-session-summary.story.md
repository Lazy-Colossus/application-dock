# Story 2.7: Finish with a session summary

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

> **Rewritten 2026-08-14.** The original ACs (post-session familiarity distribution + "N remain in scope") were built and then superseded by a fuller recap design — a breakdown ring, a per-word result list, multi-select filters, and a replay. Both dropped ACs depended on a post-session `GET /practice/overview` fetch the screen no longer makes. This file now describes the shipped design; the superseded version is in git (`docs(hotaru): ...`, story file at commit `4ad9c47`) and the design rationale is in `.working/session-summary.html`.

## Story

As a learner,
I want a recap when I finish a session that shows how each word went,
so that the session feels complete and I can immediately re-drill what I missed.

## Acceptance Criteria

1. **A recap replaces the bare "Session complete" end screen.** Given a completed session (the queue is exhausted), when the end screen shows, then it presents a breakdown ring, the three grade tallies, and every word met this session — in place of the plain "Session complete." line (FR-17). The `蛍` glyph and `data-testid="drill-done"` are kept; the exit button keeps `data-testid="drill-done-btn"` and its return-to-picker-with-`?scope=` behaviour, relabelled **"Close"**.

2. **The ring shows this session's grade mix.** Given the session's grades, when the recap renders, then a donut is split proportionally into one arc per grade actually earned (Correct cyan, Close amber, Incorrect magenta — the grade-button hues), with the count of words practised at its centre. It is built **entirely from local state**: no post-session fetch, so it draws the instant the queue empties.

3. **Every word met is listed with its result.** Given the recap, when it renders, then each practised word appears in the order it came up, showing its headword (kanji cyan / kana lamp-yellow, per the list colour split), its reading, its meaning, and the grade it earned. **The grade is rendered as a word** — "Correct" / "Close" / "Incorrect" — not as colour alone, and is visually distinct from the familiarity icon (session grade ≠ lifetime familiarity).

4. **Tallies are multi-select filters.** Given the recap, when a tally is tapped, then it toggles independently and the list narrows to the union of the selected grades (not the intersection); unselected ring arcs dim; the state line names the active selection; and a **"Show all"** control appears that clears every selection at once. Tallies expose `aria-pressed`.

5. **The filter re-scopes the replay button.** Given a selection, when the recap renders, then the primary button reads **"Practice these {N} again ✦"** where N is exactly what the list shows — what you see is what will run. With **nothing** selected it reads **"Practice Again ✦"** with no count, so it cannot be misread as a subset. When the current selection matches no words, the button is hidden and "Close" is the way out.

6. **Replay re-drills from memory.** Given the replay button, when it is tapped, then the drill restarts over just those words, de-duplicated, re-seeded from the card objects already held client-side — **no new fetch and no new endpoint** (it works offline). Direction and scoring mode carry over unchanged. The replay is its own round: it earns its own recap rather than accumulating onto the previous one.

7. **A replay cannot inflate familiarity.** Given a grade submitted during a replay, when it reaches the SRS engine, then a replay **Correct** earns its point toward the next tier but **never crosses the threshold** (repeated replays stall one point short; only a later genuine review promotes), while a replay **Incorrect** still drops a tier as normal. Recalling an answer seen a minute ago is short-term memory, not retrieval — the guard is against inflated progress, not against lapses.

8. **Calm — no streak/debt.** Given the recap, when it renders, then it shows **no** streak, points, due-count, "overdue", or urgency language (FR-18, UX-DR9). **The mistake count never escapes this screen**: it is session-bounded and opt-in, with no carry-over into the next session, no Home badge, and no nudge to return. (A persistent "N outstanding" count would be exactly the backlog wall the product is built against.)

9. **Conventions & no regressions.** HTTP via `useApi`; the practice store keeps `loading`/`error`; the grade sync loop (Story 2.5) and drill flow (2.3/2.4) are unchanged apart from the grade payload gaining `replay`. Existing clients that omit `replay` keep promoting normally. `pytest` + `npm test` green; `vue-tsc` + Prettier + `black`/`ruff` clean.

## Dev Notes

**What this story is.** The drill's end screen becomes a real recap: a ring showing how the session went, every word met with the grade it earned, and a one-tap way to re-drill a chosen slice of it. It replaces the earlier text recap (practised count / remaining-in-scope / familiarity distribution). [Source: `.working/session-summary.html`; prd FR-17/FR-18; DESIGN.md grade-button hues + word-row colour split]

**Everything derives from local state.** `results` holds `{word, grade}` per graded card, so the ring, the tallies, the list and the replay queue all come from memory. This is why AC-2's "no post-session fetch" is achievable, why replay works offline, and why the earlier `fetchOverview` call and its loading state are gone. `store.fetchOverview` itself is left in place — the picker still uses it.

**The filter and the button are one mechanism.** The strongest design constraint here: selecting tallies re-scopes *both* the list and the primary action, so the learner never reconciles "what's shown" against "what will run". The unfiltered label deliberately carries **no** number, because naming one (e.g. "the 8 you missed") next to a list of 20 reads as a mismatch. [Source: `.working/session-summary.html`, "The filter IS the button"]

**Grade is a word, not a hue.** `EXPERIENCE.md`'s accessibility floor: *"Grade outcome carries its meaning in the word, not the colour."* Hence the text pill. It is also deliberately **not** the familiarity `○◔◑◕●` glyph — session grade and lifetime familiarity are different facts, and the spine forbids collapsing them into one mark.

**The SRS guard is narrower than it looks.** The engine already floors every review at Learning (`tier = max(1, tier)`) and already fails to restore a lost tier on the next Correct (the drop resets points, and climbing out of Learning takes 3). So "a replay can't undo the lapse" was *mostly* already true; the only new behaviour is withholding **promotion** on a replay Correct. Implemented as a single `elif` branch — non-replay grading is byte-identical.

**Replay is its own round.** Clearing `results` on replay is deliberate: carrying them over would double-count a re-practised word and leave the ring showing two contradictory grades for it. A replay round's recap counts only that round.

**The calm guardrail.** A per-word scorecard plus a "re-drill your mistakes" button sits close to the FR-18 line. It clears it *only* because it is session-bounded and opt-in. If a future story surfaces "3 words outstanding" on Home or carries mistakes into the next session, that constraint is broken — see AC-8.
