# Story 2.14: Hotaru Settings — reset my progress

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

_Added 2026-08-26 — the avatar menu has always offered a **Settings** row, but `AvatarSwitcher.onSettings()` is an empty function: the control is dead. `EXPERIENCE.md` had left the surface "referenced but not specified … a stub for v1". A brainstorming session (`docs/brainstorming/brainstorming-session-2026-08-25-2346.md`, logged in the UX `.decision-log.md` 2026-08-26) inventoried 16 candidate settings and tested each against "where else could this live?". Twelve had a better home — **where the thing is used** or **the platform shell**. One survived: **reset the active user's familiarity progress**. This story builds the screen and that single action._

## Story

As a learner whose familiarity has drifted away from what I actually know,
I want to wipe my progress and start the whole library from New,
so that I can begin again cleanly — without it counting against me, and without losing the words and notes I wrote.

## Acceptance Criteria

1. **The Settings menu item goes somewhere.** Given the avatar menu, when I tap **Settings**, then I navigate to a Hotaru Settings screen. `AvatarSwitcher.onSettings()` is no longer an empty function, and the stale comment claiming no Settings screen exists is removed. (The platform's own `/settings` is a *different* screen and is not the destination — see Dev Notes.)

2. **The screen names whose progress it is.** Given the Settings screen with an active user, when it renders, then the reset action names that user explicitly — **"Reset Jake's progress"**, not "Reset progress" — and the surrounding copy makes clear it affects only that person. *(This is the feature's principal failure mode: unnamed, Dani wipes Jake's months of progress by not noticing who is signed in.)*

3. **Reset is confirmed before it acts.** Given I tap the reset action, when it fires, then a confirm step appears stating what will be cleared **and what will be kept**, with a cancel that leaves everything untouched. Only on explicit confirmation does the request go out. There is no undo, and the confirm must not pretend otherwise.

4. **Reset clears familiarity only.** Given I confirm, when the reset completes, then the active user's `users/{id}/progress.json` is emptied — every word returns to **New** (tier 0) — while `users/{id}/words_private.json`, their authored notes, and all shared content are **untouched**. *(Progress is earned state; private words and notes are content the person authored.)*

5. **The app reflects it immediately.** Given a completed reset, when I return to Library or Practice, then every word shows **New ○** and the familiarity ramps read as a fresh library — no stale tiers from before the reset, and no page reload required.

6. **It is scoped to one user.** Given users Dani, Jake and Jim, when Jake resets, then only Jake's progress is cleared; Dani's and Jim's `progress.json` are byte-identical to before.

7. **Errors surface, they don't vanish.** Given the reset request fails, when the error returns, then it is shown to the user and the screen stays usable — no silent failure, no `console.error`-only path. Loading state is set in a `try/finally` per the store convention.

8. **Nothing else is added.** Given the screen, when it renders, then reset is its **only** action. No motion toggle, no export, no About block, no practice preferences. *(Explicitly enumerated and rejected — see Dev Notes "Scope".)*

9. **The guardrails hold.** Given the whole feature, when reviewed against PRD SM-C1 and the no-debt-wall rule, then it introduces no streak, no due-count, no badge, and no persistent obligation of any kind.

10. **Quality gate.** `.venv/bin/pytest` green; `black . && ruff check .` clean; `npm test` green; `vue-tsc` + Prettier clean.

## Dev Notes

**The two Settings screens — do not conflate them.** `frontend/src/pages/SettingsPage.vue` at `/settings` already exists and is the **platform** screen: container update, dock **login accounts** (`/auth/users`), password change. Its "users" are auth accounts — a different concept from Hotaru's study identities (`dani`/`jake`/`jim` from `/api/hotaru/users`). Routing Hotaru's avatar menu there would hand the learner a screen where "user" silently means something else. This story adds a **Hotaru-scoped** screen at `/hotaru/settings`. The stale comment in `AvatarSwitcher.vue` ("No Settings screen exists yet") was already wrong about the platform one; delete it rather than update it. [Source: frontend/src/pages/SettingsPage.vue; frontend/src/router/routes.ts:20]

**Why a screen and not a menu row.** The action is destructive, person-scoped and rare. A dropdown row one tap below "Switch to Dani" is a mis-tap hazard and has no room for a confirm that explains what dies and what survives. That need for room *is* the justification for the surface — it is the only reason this screen exists. [Source: .decision-log.md 2026-08-26]

**What "progress" is, exactly.** `users/{id}/progress.json` maps `word_id → ProgressEntry`, and `ProgressEntry.tier` is the familiarity level. `familiarity_map()` returns `{word_id: entry.tier}` for **only** the words present — an absent word is New, resolved client-side by `familiarityTier()` returning `?? 0`. So clearing the map *is* resetting every word to New; there is no need to write tier-0 rows for the whole library. [Source: repositories/progress_repo.py; services/hotaru_practice_service.py:74-81; stores/useHotaruLibraryStore.ts:48-50,132-133]

**Why `{}` and not deleting the file.** `_storage.read_json(path, default={})` already treats a missing file as empty, so both work — but `atomic_write_json` is the project's mandated write path (write-`.tmp`-then-`os.replace`), and an unlink has no atomic equivalent here. Keep every mutation on the sanctioned path. [Source: repositories/_storage.py; CLAUDE.md "All writes go through atomic write"]

**Layering is strict.** `routers/` translates stdlib exceptions to `HTTPException` and nothing else; `services/` holds logic and raises stdlib errors; `repositories/` is the only filesystem code. `progress_repo`'s own docstring states "services call this; routers do not" — the router must go through the service even though the service method is a one-liner. [Source: CLAUDE.md Architecture; repositories/progress_repo.py:1-5]

**Clearing the local map beats refetching.** After a successful reset, setting `familiarity.value = {}` makes every `familiarityTier()` call return 0 immediately — same result as re-fetching `/practice/familiarity`, without the round trip or the intermediate stale render. `PracticeSetupPage` computes its ramps from `store.words` + `familiarityTier` client-side (Story 2.13), so it picks the change up with no extra work. [Source: stores/useHotaruLibraryStore.ts:119-133; Story 2.13 Dev Notes]

**Voice.** Follow the EXPERIENCE.md voice principle — *calm is the manner, not the mission*. Avoid "gentle"/"serene" filler. The copy should be plain and unfrightened: this is a legitimate thing to want, framed as starting over rather than as damage. It is the *queue-not-debt* stance applied to the whole library at once — nothing is held against you (PRD SM-C1). But **do not soften the confirm** into implying reversibility; there is no undo.

**Styling.** Reuse `css/hotaru.sass` — `.hotaru-app`, `.hotaru-panel` (glass), `.hotaru-topbar`, `.hotaru-action`. No new design tokens: the palette already carries a destructive-appropriate hue in the grade-button ramp. If a 蛍 glyph appears, it is **lamp-yellow `#ffd24a`** literal, never `--hotaru-lamp-yellow` (still aliased to cyan — see Known debt). [Source: .decision-log.md 2026-08-15]

**Scope (YAGNI).** The inventory rejected fifteen candidates; do not smuggle them back in. **NOT here:** practice preferences (Direction / Scoring / Quick preset / session limit — these want "remember last used" on `PracticeSetupPage` and remain deferred by PRD §6.2); household user management (dropped 2026-08-26 — and its home would be `IdentityPage`, not this screen); a fireflies/motion toggle; export/backup; an About or data-location block; per-word or per-selection reset (**the unit is all progress**, ruled 2026-08-26); anything touching authored words or notes. [Source: .decision-log.md 2026-08-26]
