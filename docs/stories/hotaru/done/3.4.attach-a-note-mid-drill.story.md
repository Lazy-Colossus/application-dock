# Story 3.4: Attach a note mid-drill

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a learner,
I want to jot a note on the current word without leaving the session,
so that I can capture a hack the moment it strikes.

## Acceptance Criteria

1. **Add a note during an active drill.** Given an active drill card, when I open the note affordance and write a note (text + a Shared/Private choice), then it persists via the existing `POST /api/hotaru/words/{id}/notes?user=` for the **current** word (per Story 3.1/3.2) — including the 300-char limit and the Shared/Private default — with no new endpoint (FR-16).

2. **The drill resumes without losing my place.** Given I add (or cancel) a note mid-drill, when I close the affordance, then I'm back on the **same** card in the **same** state (same word, same reveal/prompt state, same direction, same progress) — nothing advances, the queue is not re-fetched, and buffered grades are untouched.

3. **The new note shows on the current card immediately.** Given I add a note to the current word, when it persists, then it appears on that card's notes (reveal side, per Story 3.3) **without a re-fetch** — the created note is merged into the current queue item locally.

4. **Privacy + attribution are consistent.** Given the mid-drill note UI, when it lists/adds notes, then it behaves exactly like the library's `WordNotesDialog` — shared + the active user's own private notes, 🔒 on private, "You" for my own, author attribution, and (reusing 3.2) the author-only visibility flip — all scoped to the **active** drill user.

5. **Conventions + quality gate.** No backend changes (reuses 3.1 create + 3.2 flip endpoints). Frontend: reuse `WordNotesDialog` + `useHotaruNotesStore` (no raw `fetch`; the store already exposes `loading`/`error`); the drill's session state (`useDrill`) is not disturbed. `pytest` + `npm test` green; `vue-tsc` + Prettier clean.

## Dev Notes

**Frontend-only, maximal reuse — this closes Epic 3.** Everything needed already exists: the create endpoint (`POST /words/{id}/notes`, 3.1), the flip (`PATCH /notes/{id}`, 3.2), the store actions (`addNote`/`setVisibility`, with `loading`/`error`), the full add UI with the 300-char limit + Shared/Private toggle (`WordNotesDialog`, 3.1/3.2 + the UX pass), and notes-on-the-card (`Flashcard`, 3.3). 3.4 is just **wiring a note affordance into the drill that opens that dialog for the current word** and merging the result back onto the current card. No new component, endpoint, schema, or store action. [Source: routers/hotaru.py POST/PATCH notes; stores/useHotaruNotesStore.ts; components/WordNotesDialog.vue; components/Flashcard.vue (3.3 notes render)]

**"Without losing my place" is free if you use the teleported dialog.** `WordNotesDialog` is a `q-dialog` that teleports to `<body>`; opening it does not unmount or reset the drill (`useDrill`'s `index`/`revealed` are untouched, no timer exists). Closing returns to the identical card. Do **not** navigate, advance, or re-fetch the queue. [Source: components/WordNotesDialog.vue (q-dialog); composables/useDrill.ts (in-session state); epics-hotaru.md#Story 3.4 "drill resumes without losing my place"]

**Reflect the new note without a refetch (mirror 3.3's no-second-fetch spirit).** `current` (from `useDrill`) is `queue.value[index]` — a live reference into the store's queue array. `notesStore.addNote` returns the created `Note`; reassign `current.value.notes = [...existing, created]` and Vue re-renders both the card and the open dialog. This keeps the drill's single-fetch model (NFR-6) — no `GET /words/{id}/notes` mid-drill. `current.notes` may be `undefined` for a Study-reuse item, but in the graded drill it's always the queue payload's array; still guard with `?? []`. [Source: composables/useDrill.ts `current`; stores/useHotaruNotesStore.ts `addNote` returns the note; Story 3.3 QueueItem.notes]

**The dialog's notes source in the drill = the queue item, not a `loadNotes`.** In the Library, `LibraryPage` backs the dialog with `notesStore.notesFor()` after a `loadNotes` GET. In the drill, the notes are **already present** on `current.notes` (3.3), so pass those directly and keep them current via the add/flip return values — avoids an extra fetch and a second source of truth. (If you instead `loadNotes` into the store, you'd have to reconcile it with the queue item — don't.) [Source: pages/LibraryPage.vue dialog wiring (the pattern to adapt, not copy verbatim); Story 3.3]

**Flip mid-drill is a bonus, not scope creep.** Reusing `WordNotesDialog` means the author-only visibility flip (3.2) is available mid-drill too. That's consistent and correct (same word, same rules) — wire `@flip` the same lightweight way as `@add`. Not required by FR-16 but comes for free; keep it. [Source: WordNotesDialog flip control; Story 3.2]
