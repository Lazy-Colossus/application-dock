## Story

As a learner,
I want to expand a word's row in the library to see its topics and notes and add new ones inline,
so that I can review and enrich a word's context without opening a separate dialog for each.

## Acceptance Criteria

1. **Expand / collapse a row.** Given the library list, when I tap a word row's **expand affordance** (a chevron/disclosure control — not the ⋮ menu), then the row expands in place to reveal a detail panel, and tapping again (or the collapse control) closes it. The collapsed row is unchanged (headword, reading, meaning, 🔒, familiarity, ⋮). Mobile-first, one-handed, Neon-themed. _(Whether more than one row can be open at once is settled in Task 1 — default: single-open for calm.)_

2. **See the word's topics.** Given an expanded row, when the panel renders, then it lists the topics this word belongs to (from the already-loaded topics + `Topic.word_ids`) as pills; a word in no topics shows a calm empty hint. Private-word visibility is unaffected (topics are shared; membership shown is just this word's).

3. **Add / assign a topic inline.** Given the expanded panel, when I assign the word to an existing topic or create a new topic, then it uses the **existing** library-store actions (`assignWord` / `unassignWord` / `createTopic`) and the pills update; behavior matches the `WordTopicsDialog` (same endpoints, same result), just inline. Removing the word from a topic is available the same way.

4. **See the word's notes (comments), privacy-filtered.** Given an expanded row, when the panel renders, then it lazy-loads and lists this word's notes for the active user — shared notes + the user's own private notes, attributed, newest-first, 🔒 on private — exactly as `WordNotesDialog` does (reusing `notesStore.loadNotes` / `notesFor`); another user's private notes are absent (NFR-2). A word with no notes shows the calm empty hint.

5. **Add a note (comment) inline.** Given the expanded panel, when I add a note (text + a Shared/Private choice, defaulting Shared) and submit, then it persists via `notesStore.addNote` and appears in the inline list — including the **300-character limit** with the live counter + error already built into the notes add UI (empty or >300 is blocked). Reuse that behavior; don't reimplement it.

6. **Coexists with the ⋮ dialogs; no regression.** Given the change, when it ships, then the existing ⋮ → **Notes** and ⋮ → **Topics** dialogs still work unchanged (this story adds an inline path, it does not remove them), and the row stays correct in **bulk-select mode** (`selectable`) — expansion is disabled while selecting (mirroring how the ⋮ menu is hidden), so a tap still toggles selection.

7. **Conventions + quality gate.** No backend changes (reuses `GET/POST /words/{id}/notes`, topic assign/unassign/create, familiarity). Frontend `<script setup lang="ts">`, `defineProps<{}>()`/`defineEmits<{}>()`, no `any`; HTTP only via the existing stores (`useApi` underneath); co-located `*.spec.ts`. `npm test` green; `vue-tsc` + Prettier (scoped) clean.

[Source: routers/hotaru.py (notes + topics routes); stores/useHotaruNotesStore.ts, useHotaruLibraryStore.ts]

### Design direction (Sally, 2026-07-16)

_A UX review of the shipped `WordNotesDialog` produced these decisions. The notes-side ones are already applied to the dialog and must carry into the inline panel; the panel-specific ones are new. This is the "agreed design" seed for Task 0 — extend + confirm, don't re-derive._

**Notes section (inherit from the dialog — keep parity):**
- **Textarea, not a single-line input.** A note is a thought (up to 300 chars), not a label — the add control is a 2-row auto-growing textarea (`min-height ~46px`, grows to ~140px). Plain Enter = newline; submit via the **Add** button (or ⌘/Ctrl+Enter). [applied in `WordNotesDialog.vue`]
- **Semantic visibility toggle.** Selected **Shared = violet** (`--hotaru-…` violet / `#9b6bff`), selected **Private = amber** (`#ffce5c`) + lock — **never the cyan CTA hue** (cyan means "primary action", not "private"). Shared carries no badge; only Private shows the lock. In the panel, use the `--hotaru-*` vars (the row is inside `.hotaru-app`), not hardcoded hex. [applied in the dialog as hardcoded hex because it teleports]
- **Lock glyph consistency.** One lock rendering everywhere — the `q-icon name="lock"`, not the emoji 🔒. [applied]
- **A11y.** The char-limit error is `role="alert"` + `aria-live="polite"` and the textarea is `aria-describedby` it, so the limit is announced, not just shown. [applied]
- **Comment-style note header + identity.** Each note leads with its author on a head row (author name above the text, not a trailing label): a coloured **initial chip** in the per-user avatar hue (Dani=violet, Jake=amber — identity, distinct from the amber lock which is privacy), the name **bold/bright**, and the **active user rendered as "You"** (UJ-3 payoff — pass the active user in). [applied in the dialog]
- **Whisper-quiet relative timestamp.** A soft "just now / 3h ago / 2d ago / 3 Jan" per note — relative, never a hard datetime or countdown (calm guardrail). [applied]
- **Quiet character counter.** Hidden until the last ~40 chars (`≥260/300`), amber near the cap, red once over; the error text stays. No running tally from keystroke one. [applied]
- **Overflow → scroll the list only.** Header + composer stay fixed; only the note list scrolls (dialog capped at `88vh`, thin neon scrollbar) so many notes can't push the Add box off-screen. The panel's note list needs the same treatment (cap + inner scroll), not the whole row growing unbounded. [applied in the dialog]

**Panel + expand interaction (new for 3.5):**
- **Single-open rows** (expanding one collapses others) — calmer, less scroll thrash on a phone.
- **Layout:** Topics block (pills + inline add/assign) **above** Notes block (list + textarea add), a compact two-block stack; full-bleed single column.
- **Motion:** a light height/opacity reveal that becomes **instant under `prefers-reduced-motion`** (same rule as the FireflyLayer).
- **Theme:** use `var(--hotaru-*)` (cream/bamboo/sage/**violet** panel edges/**amber-private**) — the teleport→hardcode rule is dialog-only; the row is in-scope.
- **Architect for AI from day one:** reserve the **"✨ improve" note action slot** in the panel layout (stubbed/absent in v1) exactly as the word-detail spec calls for. [Source: EXPERIENCE.md — reserved ✨ improve slot; PRD §10]
