# Story 3.2: Browse the history of past days

## Status

Draft

## Story

**As** a user,
**I want** a reverse-chronological list of past questions,
**so that** I can revisit what the group has been asked over time.

## Acceptance Criteria

1. **History endpoint.** Given `GET /api/qotd/history`, when a logged-in user calls it, then it
   returns past days (today excluded) **newest-first**, each with its `date`, the question `text`
   (resolved from the stored `question_id`), and its `type` — by **scanning the days directory**, not
   an index. (FR-11, AR-2)

2. **No silent truncation.** Given days exist with no answers (a question was surfaced but nobody
   answered), when history is built, then those days are handled by a documented, tested rule — either
   included (the question was asked) or limited to days with a file — but the list is **never
   silently truncated**. (FR-11)

3. **Empty state.** Given there are no past days yet, when the history view renders, then it shows a
   calm empty state rather than an error or a blank screen. (FR-11)

4. **Rows link to the day.** Given the history list, when it renders, then each row links to that
   day's detail (Story 3.3), loaded via `useApi` with store `loading`/`error`. (FR-11, NFR-4)

5. **Contract.** Given the response, when it serialises, then fields are snake_case, serialization is
   direct, dates are `YYYY-MM-DD`, and errors `{detail}`. (NFR-4)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and lint/format are clean on touched files.

## Dev Notes

**Scan, don't index (AR-2).** History is built from `list_days()` scanning `days/*.json` — the same
reason KDH/archery avoid an index file. Sorting by the `YYYY-MM-DD` filename/date descending gives
newest-first for free.

**Resolve text at read time (AR-3).** A day stores only `question_id`; the list resolves the current
`text` from the set. If a referenced id has been removed from the set, this surfaces the Story 1.2
AC-5 failure loudly — a good place to have a test that the row-build handles/ propagates it rather
than silently dropping the row (which would violate AC 2's no-silent-truncation).

**Past-only (NFR-5).** Exclude today (it is the home page's job and is still answerable) and any
future date via the server `is_past`/`today()` — never the client clock.

**Scope discipline.** The list only — opening a past day and showing its answers is Story 3.3. Keep
the row payload lean (date + question text + type); the detail fetch carries the answers.
