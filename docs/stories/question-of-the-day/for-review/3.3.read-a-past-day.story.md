# Story 3.3: Read a past day (question + all answers, read-only)

## Status

Ready for Review

## Story

**As** a user,
**I want** to open a past day and read its question and everyone's answers,
**so that** I can see the full record of any previous day.

## Acceptance Criteria

1. **Past-day endpoint.** Given `GET /api/qotd/days/{date}` for a **past** date, when a logged-in
   user calls it, then it returns that day's question (resolved from `question_id`) and **all**
   answers attributed to their authors, **always visible** — past days are not gated behind
   answer-to-reveal. (FR-12)

2. **Bad or future date.** Given a `{date}` that is malformed or in the future/today, when it is
   requested, then the router returns `400`/`404` with `{detail}` — malformed rejected by the repo's
   date validation (Story 1.3), a future/never-surfaced date is a `404`, and today is redirected to
   the `/today` flow rather than served here. It never reads outside the store. (NFR-2, FR-12)

3. **Read-only render.** Given a past day is opened in the UI, when it renders, then it shows the
   question and the group's answers read-only (no form, per Story 2.3), reachable from the history
   list (Story 3.2), loaded via `useApi` with store `loading`/`error`. (FR-12, NFR-4)

4. **Empty day.** Given a past day that has a file but no answers, when it is opened, then it shows
   the question with a calm "nobody answered" empty state rather than an error. (FR-12)

5. **Contract.** Given the response, when it serialises, then fields are snake_case, serialization is
   direct, timestamps ISO-8601, and errors `{detail}`. (NFR-4)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and lint/format are clean on touched files.

## Dev Notes

**Always visible — no reveal gate (FR-12).** The answer-to-reveal rule (Story 3.1) is a *today*
concept. Past days are the archive: show everyone's answers to any logged-in user regardless of
whether they answered that day (they usually could not have — it is past). Do **not** reuse
`today_feed`'s gate here.

**Reject today/future here (NFR-5).** `/days/{date}` is for the past only; today belongs to the home
flow (`/today`) which carries the reveal gate and the answer form. Serving today through this
always-visible endpoint would bypass answer-to-reveal — refuse it.

**Untrusted date from the URL (NFR-2).** The repo's `_validate_date` (Story 1.3) is the guard; the
router turns its `ValueError` into a 400. Add an explicit test that a traversal-style date neither
reads nor creates anything outside the store (mirror KDH's path-traversal test).

**Scope discipline.** Read-only detail view only. No editing (locked by Story 2.3), no feed gate, no
new write path. Reached from the history rows built in Story 3.2.
