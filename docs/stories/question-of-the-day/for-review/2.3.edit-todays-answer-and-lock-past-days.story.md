# Story 2.3: Edit today's answer, and lock days that have passed

## Status

Ready for Review

## Story

**As** a user,
**I want** to change my answer while it is still today but be stopped once the day has passed,
**so that** I can refine a response in the moment without rewriting history.

## Acceptance Criteria

1. **Edit today.** Given the user has an answer for today, when they change it and resubmit, then the
   same answer is replaced in place (upsert), `updated_at` is bumped and `created_at` is preserved,
   and the day still holds exactly one answer for them. (FR-8)

2. **Server rejects past writes.** Given a write targeting **any day other than today** (a past date,
   whether via a dated endpoint or a stale client), when it reaches the service, then it is rejected
   — the past/present boundary is decided by the server-side helper from Story 1.3, `today` itself
   counts as still-writable, and nothing is written. (FR-9, NFR-5)

3. **Past days render read-only.** Given a past day is viewed, when the UI renders it, then there is
   no answer form — it is presented read-only — and any attempt to submit is refused by the server
   with a `{detail}` error even if the UI is bypassed. (FR-9)

4. **Boundary is testable without waiting.** Given the boundary logic, when it is tested, then tests
   cover: editing today succeeds; a write to yesterday is refused; and the today→past transition is
   driven by the injectable/server `today()` (not the client clock), verified without sleeping until
   midnight. (NFR-5)

5. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and lint/format are clean on touched files.

## Dev Notes

**One boundary helper, server-side (NFR-5).** Reuse `today()` / `is_past()` from Story 1.3 — do not
re-derive the date in the router or trust the client. `today` is *not* past, so today stays editable
all day. Make `today()` injectable in tests (monkeypatch or a `settings`/dependency seam) so the
roll-over is testable without waiting for midnight.

**Defence in depth (FR-9).** The UI hides the form on past days, but the server must independently
refuse the write — a bypassed client (curl) gets a `{detail}` rejection, not a silent past-day edit.
This mirrors the platform's "finalised is strict / server decides" posture.

**No new write endpoint.** Editing reuses `PUT /today/answer` (upsert). This story adds the *guard*
and the *read-only rendering rule*, not a second mutation path. Past-day *reading* is Story 3.3.

**Scope discipline.** No history list and no feed reveal here — only the edit affordance for today
and the lock (server + UI) for past days.
