# Story 2.2: The answer form UI (text & scale)

## Status

Ready for Review

## Story

**As** a user,
**I want** an input that matches the question — a text box or a rating control — with a clear submit,
**so that** answering feels natural for whatever is being asked.

## Acceptance Criteria

1. **Text input.** Given today's question is `type: "text"`, when the answer form renders, then it
   shows a textarea and a submit control; submitting a non-empty response saves it via the store
   (Story 2.1) and the UI then shows the user's saved answer. (FR-6)

2. **Scale input.** Given today's question is `type: "scale"`, when the answer form renders, then it
   shows a rating/scale control bounded by the question's `min..max` with its end labels, and
   submitting a chosen value saves it via the store. (FR-7)

3. **Error handling.** Given a submission fails, when the store surfaces `error`, then the form shows
   the `{detail}` message and the user can retry without losing their input; the submit control
   reflects `loading` while in flight. (NFR-4)

4. **Pre-fill when answered.** Given the user has already answered today, when the page loads, then
   the form is pre-filled with their saved answer (setting up the edit affordance completed in Story
   2.3), not a blank input. (FR-8)

5. **Empty/invalid guarded client-side too.** Given an empty text answer or an unset scale value,
   when the user tries to submit, then the control prevents the no-op submit (server validation from
   Story 2.1 remains the source of truth). (FR-6, FR-7)

6. **No regressions.** Given the existing suites, when this story lands, then `npm test` stays green
   and lint/format are clean on touched files. Backend untouched.

## Dev Notes

**Type drives the widget (FR-6/FR-7).** The question `type` from `/today` decides which input to
render — never show both. For `scale`, honour the question's `min`, `max`, `min_label`, `max_label`;
Quasar's `q-rating` or a labelled `q-slider` both fit — pick one and keep it accessible (keyboard +
`aria-label`).

**The server is the source of truth (NFR-4).** Client-side guards (disable empty submit) are UX
only; the real validation lives in Story 2.1's service. Do not duplicate range logic in a way that
can drift — read bounds from the question payload.

**Pre-fill sets up 2.3.** Showing the saved answer in the form is what makes editing feel like
editing rather than re-answering; Story 2.3 adds the explicit edit/lock behaviour and past-day
read-only rendering.

**Scope discipline.** No history, no feed, no past-day handling — just today's form for both types.
All HTTP stays in the store via `useApi`; the component talks to the store, not the network.

## Dev Agent Record

### Completion Notes

- `AnswerForm.vue` switches on `question.type`: a `q-input` textarea for `text`, and a `q-slider`
  bounded by the question's `min..max` with its end labels for `scale`. It is presentational —
  props `question`/`initial`/`loading`/`error`, emits `submit` — so it is unit-testable without the
  store and the page owns the network call (component talks to the store via the page, not `fetch`).
- Submit is disabled on empty text / unset scale (a `canSubmit` guard, with `onSubmit` guarding a
  bypass too); the server remains the source of truth. The scale starts unset so an accidental submit
  is blocked until a value is chosen.
- Pre-fill: a `watch(initial, …, { immediate: true })` seeds the drafts from the caller's saved
  answer on load and after a successful submit; the button reads "Save changes" when editing.
- `QotdHomePage.vue` now renders `AnswerForm` beneath the question (replacing 1.4's read-only
  preview), passing `my_answer` as `initial` and wiring `@submit` → `store.submitAnswer` (errors stay
  in `store.error`, input preserved for retry).
- Tests: `AnswerForm.spec.ts` (textarea vs bounded slider + labels; disable-until-input for both
  types; trimmed-text and rating payloads; error shown; pre-fill from a saved text/scale answer) and
  a reworked `QotdHomePage.spec.ts` (stubs `AnswerForm`; asserts the page renders it with the right
  type + pre-fill prop, wires submit to the store, and hides the form on a failed load). Full
  frontend suite green (1467). Backend untouched, as scoped.
