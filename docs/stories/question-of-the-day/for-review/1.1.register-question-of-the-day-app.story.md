# Story 1.1: Register Question of the Day in the Application Dock shell

## Status

Ready for Review

## Story

**As** a user,
**I want** Question of the Day to appear as an app in the dock and open to its own home,
**so that** I can launch it like any other app in the platform.

## Acceptance Criteria

1. **Shell card.** Given the dock landing page, when it renders the app registry, then a Question of
   the Day card appears (label "Question of the Day", icon `help_center`) alongside the existing
   apps, and selecting it routes to `/question-of-the-day`. (FR-1)

2. **Backend registry.** Given `GET /api/apps`, when called, then the response includes a QotD
   `AppDescriptor` (`id: "question-of-the-day"`, `label: "Question of the Day"`,
   `icon: "help_center"`, `route: "/question-of-the-day"`).

3. **Routes.** Given the router, when `/question-of-the-day` is visited by a logged-in user, then
   `QotdHomePage.vue` renders (lazy-loaded, `meta: { title: "Question of the Day", requiresAuth: true }`).

4. **App module skeleton.** Given the new app, when the project is set up, then
   `frontend/src/apps/question-of-the-day/` exists and is self-contained (the shell imports it only
   via `registry.ts`), and a backend `routers/qotd.py` is mounted under `/api/qotd` behind
   `Depends(get_current_user)` — even if it exposes nothing but a health-shaped placeholder until
   Story 1.4.

5. **Story folders.** Given the docs tree, when the app is registered, then
   `docs/stories/question-of-the-day/for-review/` and `docs/stories/question-of-the-day/done/`
   exist. (AR-1)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and `black`/`ruff`/ESLint/Prettier are clean on touched files.

## Dev Notes

**Two-file change.** Adding an app is meant to be registry + routes; `HomePage` iterates the registry
and `AppCard` is generic — no other shell changes. [Source: CLAUDE.md#Adding a new app]

**Auth from the start.** Every QotD route sits behind `Depends(get_current_user)` — unlike
archery/shell, this app *uses* the username to attribute answers (Story 2.1), so pass it into
services rather than discarding it as `_`.

**Icon.** `help_center` (Material Icons) reads as a question prompt and stays distinct from the other
apps' glyphs (`adjust`, `school`, `swap_horiz`, `table_chart`, `event_available`).

**Scope discipline.** No data model, no question set, no endpoints beyond the mounted router. The
home page is a placeholder — Story 1.4 makes it show today's question.
