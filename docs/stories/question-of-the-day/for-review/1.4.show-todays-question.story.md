# Story 1.4: Show today's question

## Status

Ready for Review

## Story

**As** a user,
**I want** opening the app to show me today's question and date, rendered for its type,
**so that** I know what is being asked before I answer.

## Acceptance Criteria

1. **Today endpoint.** Given `GET /api/qotd/today`, when a logged-in user calls it, then it resolves
   today's date server-side (Story 1.3 `today()`), selects the day's question (Story 1.2), and
   returns the question (`id`, `text`, `type`, and `scale` bounds/labels when scale), today's
   `date`, and **whether the caller has already answered** (`answered: bool`) — but **not** other
   users' answers (that is Epic 3's answer-to-reveal). (FR-5, FR-2)

2. **Day is materialised lazily.** Given today has no file yet, when `/today` is first called, then
   the response still resolves the question deterministically; whether an empty day file is written
   on read is an implementation choice, but a first visitor never errors and never sees a stale
   question id. (FR-4, FR-5)

3. **Renders by type.** Given the question is `type: "text"`, when the home page renders, then it
   shows the prompt with a read-only preview of where the written response will go; given a `scale`
   question, it shows the scale's range and end labels. (FR-5)

4. **Single HTTP boundary & store.** Given the frontend, when it loads today's question, then it
   goes through `useApi` only, and a Pinia store (`useQotdStore`) exposes `loading` and `error`,
   sets `loading` in a `try/finally`, and routes failures into `error.value` (no bare
   `console.error`). (NFR-4)

5. **Contract.** Given the API contract, when the endpoint responds, then fields are snake_case,
   serialization is direct (no envelope), errors are `{detail}`, and timestamps are ISO-8601.
   (NFR-4)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and lint/format are clean on touched files.

## Dev Notes

**Do not leak other answers here (FR-10).** `/today` returns *your* answered-flag and the question,
never the pool of answers — the reveal is gated in Epic 3. Keep the today DTO deliberately thin so a
curious client cannot read the feed before answering.

**Server clock only (NFR-5).** The date comes from `today()` in the service, never from a query param
or the browser. A dated read endpoint for *past* days is Story 3.3; `/today` takes no date.

**Store shape.** Follow `useArcherySessionStore` / KDH stores: `loading` and `error` refs, every
async action in `try/finally`, errors into `error.value`. All HTTP through `useApi` — no raw
fetch/axios. [Source: CLAUDE.md#Frontend]

**Scope discipline.** No answering, no editing, no feed — read-only display of today's question and
whether *you* have answered. Story 2.1 adds the write path; Story 2.2 the real input.
