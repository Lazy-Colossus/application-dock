# Story 1.2: Curated question set & deterministic daily selection

## Status

Ready for Review

## Story

**As** the platform,
**I want** a bundled set of typed questions and a pure function that picks one per date,
**so that** every user sees the same question on the same day and the choice is reproducible.

## Acceptance Criteria

1. **Bundled, validated set.** Given `backend/app/data/qotd_questions.json`, when it is loaded, then
   it is a non-empty list of questions, each with a unique `id`, a `text`, and a `type` of `"text"`
   or `"scale"`; every `scale` question carries a `scale` object with integer `min < max` and
   optional `min_label`/`max_label`. A loader validates the file at first use and raises on a
   malformed or empty set. (FR-3, AR-3)

2. **Typed question model.** Given `backend/app/schemas/qotd.py` (or a question submodule), when the
   set is parsed, then a Pydantic v2 `Question` model represents both types and rejects a `scale`
   question missing its bounds or a `text` question carrying a `scale`. (FR-3)

3. **Deterministic selection.** Given a calendar date and the curated set, when the selection helper
   resolves the day's question, then it returns exactly one question id and is **pure and
   deterministic** — same date + same set → same id, in any process and after restart. (FR-4, AR-4)

4. **Set coverage.** Given a run of consecutive dates, when the helper is applied, then it walks the
   whole set rather than fixating on one entry (e.g. ordinal-of-date modulo set length). (FR-4)

5. **Missing question is loud.** Given a stored day references a `question_id` no longer in the set,
   when resolution runs, then it raises a stdlib exception (the router later maps it to a 5xx) rather
   than returning a half-built question — the set is treated as append-mostly. (FR-3)

6. **Layering & tests.** Given the service layer, when it resolves or looks up questions, then it
   raises stdlib exceptions only (no `HTTPException`), and unit tests cover determinism, set
   coverage, both question types, and the malformed/empty-set guards. (NFR-4)

7. **No regressions.** Given the existing suites, when this story lands, then `pytest` stays green
   and `black`/`ruff` are clean. Frontend untouched.

## Dev Notes

**Determinism is the whole point (FR-4).** Do not use `random` or wall-clock time inside the helper —
selection must be a pure function of the date and the set so two processes agree and a restart does
not shift the day's question. An ordinal-of-date (e.g. `date.toordinal()`) modulo `len(set)` is the
simplest reproducible mapping; if you want to avoid a visible linear walk, hash the ISO date string
deterministically — but keep it pure.

**Store the id, never the text.** A day file records only `question_id` (Story 1.3). The text is
always resolved from the set, so editing wording in the asset reflects everywhere and there is one
source of truth (AR-3).

**Append-mostly set.** Reordering or trimming the set can change which question a *future* date maps
to — acceptable. Removing a question that a *past* day already referenced is the failure mode AC 5
guards; keep entries and their ids stable once shipped.

**Scope discipline.** No day storage, no endpoints — Story 1.3 adds the repository and Story 1.4 the
`/today` endpoint. This story is the question set and its selection only.

## Dev Agent Record

### Completion Notes

- Added `Scale` and `Question` Pydantic v2 models to `schemas/qotd.py`. `Scale` enforces `min < max`;
  `Question` enforces exactly the type↔scale correspondence (a `scale` must carry bounds, a `text`
  must not) via `@model_validator(mode="after")`, so a malformed set fails at load.
- Bundled `app/data/qotd_questions.json` — 40 curated **conversation-starter** questions (32 `text`
  opinions / problem-solving / moral dilemmas, 8 `scale` agree-disagree statements interleaved every
  5th so both types appear in any window) with stable ids, giving a ~40-day rotation. Located via
  `Path(__file__).resolve().parent.parent / "data" / ...`, mirroring `hotaru_seed`'s relative-path
  loading (no absolute paths).
- `qotd_service.py`: `_read_and_validate(path)` (pure, path-injectable for tests — rejects
  empty/non-list sets and duplicate ids, lets `Question` validation errors propagate),
  `load_questions()` (reads + caches once), `get_question(id)` (raises `KeyError` on an unknown id —
  the AC-5 append-mostly guard), and the deterministic selection: `question_id_for_date(date)` =
  `questions[date.toordinal() % len]`, with `question_for_date(date)` resolving it to a `Question`.
- Selection is a pure function of the date and the set — no `random`, no wall clock — so it is
  reproducible across processes and restarts, and walks the whole set over consecutive days.
- Tests: `test_qotd_questions.py` (load/validate, both-types coverage, unknown-id `KeyError`, and
  loader/schema guards via bad fixtures) and `test_qotd_selection.py` (determinism, full set
  coverage over a window, both types across a range, purity of wall clock). 17 tests, all pass.
- Frontend untouched, as scoped. Backend suite green apart from the pre-existing Windows-only
  `test_core_storage` concurrency failure noted in Story 1.1.
