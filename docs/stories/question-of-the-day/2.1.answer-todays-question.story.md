# Story 2.1: Answer today's question (write endpoint & store action)

## Status

Draft

## Story

**As** a user,
**I want** to submit my answer to today's question and have it saved under my name,
**so that** my response is recorded once per day.

## Acceptance Criteria

1. **Upsert endpoint.** Given `PUT /api/qotd/today/answer` with a body carrying `text` (text
   question) or `rating` (scale question), when a logged-in user submits, then the answer is stored
   under **their JWT username** in today's day file, exactly one answer per user per day (a resubmit
   **upserts**, stamping `updated_at` and preserving `created_at`), and the endpoint returns the
   caller's saved answer. (FR-6, FR-7, FR-8, FR-2)

2. **Type-matched validation.** Given a body whose shape does not match the day's question type (a
   `rating` for a text question, `text` for a scale question, a `rating` outside the question's
   `min..max`, or empty/whitespace-only `text`), when it is validated, then the service raises
   `ValueError` and the router returns `422`/`400` with `{detail}` — nothing is written. (FR-7)

3. **Attribution is from the token.** Given the request, when the username is determined, then it
   comes from `get_current_user`; a `user`/`username` field in the path or body is ignored (or
   rejected), never used to attribute or select. (FR-2)

4. **Concurrency-safe.** Given concurrent submissions to today by different users, when they run,
   then the write goes through `day_transaction(today)` (Story 1.3) so every answer survives and none
   is lost. (NFR-1)

5. **Store action.** Given the frontend store, when it submits an answer, then it calls the endpoint
   via `useApi`, sets `loading`/`error` correctly, and on success updates the caller's own answer and
   the `answered` flag in state. (NFR-4)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and lint/format are clean on touched files.

## Dev Notes

**Exactly one field, matched to the question (FR-6/FR-7).** The day's question type is authoritative:
for a `text` question require non-empty `text` and reject `rating`; for `scale` require `rating` in
`[min, max]` and reject `text`. Validate in the **service** (stdlib `ValueError`); the router is the
only place that turns it into an HTTP status. [Source: CLAUDE.md#Backend — strict 3-layer]

**Never trust a body username (FR-2).** Attribution is `get_current_user`. Mirror the platform rule
from KDH/Listies: no `user` field is accepted in path or body. A test should prove a forged body
`username` cannot write into another user's slot.

**Upsert, don't append (FR-8).** `answers` is keyed by username, so there is structurally one answer
per user per day; a resubmit overwrites the value and bumps `updated_at`. `created_at` is set only on
first write.

**Scope discipline.** This is the write path and the store action — the *form UI* is Story 2.2 and
the *edit/lock* rules (past days) are Story 2.3. Writing to a non-today date is out of scope here
(the endpoint only ever targets `today()`).
