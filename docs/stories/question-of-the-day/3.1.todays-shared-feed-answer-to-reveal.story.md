# Story 3.1: Today's shared feed (answer-to-reveal)

## Status

Draft

## Story

**As** a user who has answered today,
**I want** to read everyone else's answers to today's question,
**so that** answering is rewarded with seeing how the group responded.

## Acceptance Criteria

1. **Withheld before answering.** Given the caller has **not** answered today, when they request
   today's answers, then other users' answers are **withheld** — the response reveals only that
   answering is required first (a count may be shown as a teaser, but never the contents). (FR-10)

2. **Revealed after answering.** Given the caller **has** answered today, when they request today's
   answers, then every answer for today is returned, each **attributed to its author** (username) and
   typed correctly (text or rating), ordered stably (e.g. by `created_at`). (FR-10)

3. **Enforced server-side.** Given the reveal boundary, when it is enforced, then a user who has not
   answered **cannot** obtain today's answers by calling the API directly — "has answered" is derived
   from the stored day, not a client flag. (FR-10, FR-2)

4. **Unlocks in place.** Given the frontend, when the user answers today, then the feed unlocks in
   place (re-fetch, or returned alongside the write) via `useApi`, with `loading`/`error` handled by
   the store. (NFR-4)

5. **Contract.** Given the response, when it serialises, then fields are snake_case, serialization is
   direct, timestamps ISO-8601, and errors `{detail}`. (NFR-4)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and
   `npm test` stay green and lint/format are clean on touched files.

## Dev Notes

**Gate on the stored day, not the client (FR-10/FR-2).** "Has answered" = `username in day.answers`.
The server must withhold contents for an un-answered caller even if the UI would have hidden them —
otherwise curling the endpoint leaks the feed. This is the crux of answer-to-reveal.

**Reveal is today-only.** Past days are always visible (Story 3.3) and are *not* gated — do not apply
this logic to `/days/{date}`. Keep the gate in the today path.

**One question, two shapes.** Answers carry either `text` or `rating`; render each by the question's
type. Order by `created_at` for a stable feed (avoid dict-insertion assumptions across reads).

**Scope discipline.** No history list (Story 3.2) and no past-day read (Story 3.3) — just today's
gated feed. No new write path; this reads what Story 2.1 wrote.
