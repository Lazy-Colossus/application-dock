# Story 1.5: JWT Authentication

## Status

Draft

## Story

**As a** user of Application Dock,
**I want** to log in with a username and password and stay logged in for 7 days,
**so that** only authorised people can access the app and its data.

## Acceptance Criteria

1. **Given** no valid JWT token is present, **When** any `/api/*` route is called (except `/api/health` and `/api/auth/login`), **Then** the server returns `401 Unauthorized`.
2. **Given** valid credentials are submitted to `POST /api/auth/login`, **When** the server processes the request, **Then** it returns `{ access_token, token_type: "bearer" }` with a token valid for 7 days.
3. **Given** invalid credentials are submitted to `POST /api/auth/login`, **When** the server processes the request, **Then** it returns `401 Unauthorized` with `{ detail: "Invalid credentials" }`.
4. **Given** a valid JWT token, **When** `GET /api/auth/me` is called, **Then** it returns `{ username }` for the authenticated user.
5. **Given** credentials have been set up with the setup script, **When** the app starts, **Then** it reads credentials from `{data_dir}/_auth.json` and all protected routes are accessible with the resulting token.
6. **Given** the user is unauthenticated in the browser, **When** they navigate to any route, **Then** they are redirected to `/login`.
7. **Given** the user logs in successfully in the browser, **When** they navigate to `/login` again, **Then** they are redirected to `/`.
8. **Given** the user is logged in, **When** they refresh the browser, **Then** they remain logged in (token persisted in `localStorage`).
9. **Given** the user is logged in, **When** they click Logout, **Then** they are returned to `/login` and the token is cleared.
10. **Given** the token expires or is invalid, **When** the frontend makes any API call, **Then** the user is automatically redirected to `/login`.

### Credential file format (`_auth.json`)
```json
{ "username": "admin", "password_hash": "$2b$12$..." }
```
Single-user file. Managed only via the setup script — no API endpoint to create/change users.

### JWT secret key
`JWT_SECRET_KEY` must be set as an env var (or in `.env`) in production. If left empty the service starts but tokens will be insecure (log a warning). Generate with: `python -c "import secrets; print(secrets.token_hex(32))"`.

### Token storage
Token stored in `localStorage` under key `auth_token`. Acceptable for self-hosted personal use. No refresh tokens — a single 7-day access token is issued.

### useApi circular dependency
`useApi.ts` needs `useAuthStore` and the router. Import both inside the `request()` function call (not at module top-level) to avoid circular dependency issues at boot time.

### Out of scope
- Multi-user support (adding/removing users via UI)
- Password change endpoint
- Refresh tokens
- MFA
