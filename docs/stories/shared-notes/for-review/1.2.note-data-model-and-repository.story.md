# Story 1.2: One-file-per-note data model, repository & schemas

## Status

Ready for Review

## Story

**As** the platform,
**I want** one JSON file per note with an atomic-write repository and typed schemas,
**so that** every note is stored as its own shareable document, isolated by membership.

## Acceptance Criteria

1. **None on first read.** Given `repositories/shared_notes_repo.py`, when a note id has no file yet, then `read_note(note_id)` returns `None` (not an error, not an empty object). (AR-2)

2. **Repo is the only filesystem access.** Given any write, when it happens, then it goes through `_atomic_write_json` (write-`.tmp`-then-`os.replace`) and `mkdir(parents=True, exist_ok=True)` creates `notes/` on first write; no service or router touches the filesystem. (NFR-1, AR-3)

3. **Note-id path safety.** Given a `note_id` containing `/`, `\`, `.` or `..`, when the repo derives a path, then it raises `ValueError` rather than reading or writing outside `DATA_DIR/shared-notes/notes/`. (NFR-2)

4. **Schemas.** Given `schemas/shared_notes.py`, when models are defined, then a Pydantic v2 `Note` model exists (`schema_version: int`, `id: str`, `title: str`, `body: str` defaulting to `""`, `owner: str`, `members: list[str]`, `rev: int`, `created_at: str`, `updated_at: str`) plus request/response models as needed (`NoteSummary`, create/update bodies). (AR-3)

5. **Migration hook.** Given `migrate(raw)`, when a note is read, then it runs before validation; v1 is a pass-through, so future `schema_version` bumps have one home. (AR-3)

6. **Id minting, membership seed and timestamps.** Given a note is created, when the service mints it, then it gets a stable `n-{uuid8}` id, `owner` and `members` seeded to the creator (owner is `members[0]`), `rev = 0`, `body = ""`, and ISO-8601 UTC `created_at`/`updated_at`.

7. **Listing by membership.** Given `list_notes_for(username)`, when called, then the repo enumerates note files and returns those whose `members` contains the username — there is no per-user index file. (AR-2)

8. **Layer purity.** Given the service, when it fails, then it raises stdlib exceptions (`FileNotFoundError` for a missing/inaccessible note, `ValueError` for invalid input) and never `HTTPException`. (NFR-3)

9. **Round-trip test.** Given a note with a multi-line body and several members, when written and read back, then it validates and is byte-stable in content.

## Dev Notes

**One file per note, not per user.** Unlike Listies (which embeds notes in a per-user doc and only promotes them on share), Shared Notes stores every note as its own file from creation because sharing is the whole point — no promotion/demotion machinery, and Epic 2 adds only membership mutation on top. The note filename is the note id, validated as a safe bare filename (mirror Listies' `_validate_username`). [Source: docs/planning-artifacts/epics-shared-notes.md#AR-2]

**Access ≡ membership.** There is no `user` field in any request; the caller comes from the JWT. The resolver (Story 1.3) loads a note only if the caller is in `members`, else `FileNotFoundError` → `404`, so a non-member cannot tell a note exists (NFR-2).

**`rev` now, events later.** Bump `rev` on every content write from the start even though nothing consumes it until Story 2.2 — keeping it in the write path means the SSE story only adds the bus and the emit call.

**Atomic writes.** Reuse `session_repo._atomic_write_json`, exactly as `listies_repo`/`context_switch_repo` do; extracting it to a shared core util is out of scope here.

**Scope discipline.** No routes beyond what Story 1.1 mounted, no membership mutation (Story 2.1), no SSE (Story 2.2). This story is the data layer.

### Completion Notes List

- **Deviation from Task 2:** the story says to reuse `session_repo._atomic_write_json`, but that helper no longer exists — it was consolidated into `app/core/storage.py::atomic_write_json` (same write-tmp-then-`os.replace` guarantee, with a unique temp name per write). Used the current one. AC-2 is satisfied; a test asserts no `.tmp` is left beside the note.
- **Addition beyond the story:** `note_transaction` wraps a note's read-modify-write in `key_lock` (`app/core/locks.py`, added to the codebase after these stories were drafted). Every note mutation bumps `rev`, so without it two members saving at once both read the same `rev` and one write is silently lost — exactly the case Epic 2 makes routine. `listies_repo` and `context_switch_repo` set the precedent.
- **Path safety is stricter than the pattern ref.** `_validate_note_id` rejects *any* `.`, not just a bare `.`/`..` as `listies_repo._safe_filename` does. Ids are minted `n-{hex8}` and never contain a dot, so nothing legitimate is refused, and `..` traversal plus `foo.json` collisions die on one check.
- Service scope kept to what has a caller: `now_iso`, `new_id`, `_clean_title`, `resolve_note` (AC-8) and `create_note` (AC-6). The rest of the lifecycle lands in Story 1.3 with its routes rather than sitting here unused (CLAUDE.md forbids dead code).
- Added `NoteView` alongside `Note`/`NoteSummary` — the editor's shape, carrying `can_manage`. Story 1.3 returns it.
