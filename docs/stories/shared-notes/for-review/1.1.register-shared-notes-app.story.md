# Story 1.1: Register Shared Notes in the Application Dock shell

## Status

Ready for Review

## Story

**As** a user,
**I want** Shared Notes to appear as an app in the dock and open to its own home,
**so that** I can launch it like any other app in the platform.

## Acceptance Criteria

1. **Shell card.** Given the dock landing page, when it renders the app registry, then a Shared Notes card appears (label "Shared Notes", icon `sticky_note_2`) alongside the existing apps, and selecting it routes to `/shared-notes`. (FR-1)

2. **Backend registry.** Given `GET /api/apps`, when called, then the response includes a Shared Notes `AppDescriptor` (`id: "shared-notes"`, `label: "Shared Notes"`, `icon: "sticky_note_2"`, `route: "/shared-notes"`).

3. **Routes.** Given the router, when `/shared-notes` is visited by a logged-in user, then `SharedNotesHomePage.vue` renders (lazy-loaded, `meta: { title: "Shared Notes", requiresAuth: true }`); `/shared-notes/notes/:noteId` is also registered and renders a placeholder `NotePage.vue` that reads `:noteId` (fleshed out in Story 1.5).

4. **App module skeleton.** Given the new app, when the project is set up, then `frontend/src/apps/shared-notes/` exists and is self-contained (the shell imports it only via `registry.ts`), and a backend `routers/shared_notes.py` is mounted under `/api/shared-notes` behind `Depends(get_current_user)` — even if it exposes nothing but a placeholder until Story 1.3.

5. **Story folders.** Given the docs tree, when the app is registered, then `docs/stories/shared-notes/for-review/` and `docs/stories/shared-notes/done/` exist. (AR-1)

6. **No regressions.** Given the existing suites, when this story lands, then `pytest` and `npm test` stay green and `black`/`ruff`/ESLint/Prettier are clean on touched files.

## Dev Notes

**Two-file change.** Adding an app is meant to be registry + routes; `HomePage` iterates the registry and `AppCard` is generic — no other shell changes. [Source: CLAUDE.md#Adding a new app]

**Icon.** `sticky_note_2` (Material Icons) reads as a note/scratchpad; the other apps use single thematic glyphs (`adjust`, `school`, `swap_horiz`, `table_chart`).

**Auth.** Every Shared Notes route sits behind `Depends(get_current_user)` from the start — this app *uses* the username to identify the caller and pick which notes they can see (Stories 1.2–1.3), so pass it into services rather than discarding it as `_`.

**Scope discipline.** No data model, no endpoints beyond the mounted router, no editor. Pages are placeholders.
