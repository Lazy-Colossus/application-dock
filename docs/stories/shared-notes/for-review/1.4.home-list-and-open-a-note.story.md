# Story 1.4: Home — list my notes and open one

## Status

Ready for Review

## Story

**As** a user,
**I want** a home screen listing the notes I can see, with a way to create one,
**so that** I can find a note and jump into it.

## Acceptance Criteria

1. **List.** Given the Shared Notes home (`/shared-notes`), when it loads, then it calls `GET /api/shared-notes/notes` through a Pinia store and shows my notes with their title, owner and a relative "edited" time, newest `updated_at` first. (FR-4)

2. **Store contract.** Given the store (`useSharedNotesStore`), when it loads or mutates, then it exposes `loading` and `error` refs, sets `loading` in a `try/finally`, and routes errors into `error.value` (never a bare `console.error`); all HTTP goes through `useApi`. (NFR-3, NFR-4)

3. **Empty state.** Given I have no notes, when the home renders, then it shows a calm empty state prompting me to create my first note rather than a bare frame.

4. **Create.** Given the home, when I use the "new note" control and enter a title, then `POST /api/shared-notes/notes` creates the note and I navigate to `/shared-notes/notes/:noteId`; a blank title disables submit (no request). (FR-3)

5. **Open.** Given a note in the list, when I select it, then I navigate to `/shared-notes/notes/:noteId`. (FR-4)

6. **Delete.** Given a note I own, when I choose delete from its list control and confirm, then `DELETE /api/shared-notes/notes/{note_id}` removes it and it disappears from the list; the control requires an explicit confirmation and is offered only for notes I own (owner-only, matching the backend guard). (FR-7)

7. **Tests.** Given the frontend suite, when it runs, then `npm test` stays green, ESLint/Prettier are clean, and specs cover the list render, empty state, create-and-navigate, and owner-only delete with confirmation (`useApi` mocked at its boundary).

## Dev Notes

**Members-scoped list, not owner-scoped.** The list shows every note where I am a member; until Epic 2 adds sharing that is just my own notes. The shared-with-me / shared-by-me visual distinction (FR-12) and live appearance of a newly-shared note (FR-11) land in Story 2.3 — do **not** build the badges here, but leave the summary's `owner`/`shared` fields flowing through so 2.3 only touches presentation.

**Owner-only delete in the UI.** Offer delete only when the note's `owner` is the current user; the backend already enforces `403` for a non-owner (Story 1.3) — the UI check is convenience, not the security boundary.

**Contract.** snake_case JSON, direct serialization, `{detail}` errors surfaced through `ApiError`; ISO-8601 `updated_at` rendered as relative time client-side. [Source: CLAUDE.md#Frontend]

### Completion Notes List

- The "new note" control is a `q-dialog` inlined in the page rather than a separate component: it is one text field, where Listies' `CreateSheetDialog` has a whole column builder to justify its own file.
- `relativeTime` is a small local helper in `apps/shared-notes/time.ts`, with its own spec. Hotaru has an equivalent inside `useNoteDisplay`, but importing across apps would break self-containment and `src/components/` is for shared primitives only — so this is deliberate duplication, not an oversight.
- **Beyond the ACs:** the empty state is suppressed when `store.error` is set. A failed load also has zero notes, and "No notes yet" there asserts something we do not know. Covered by a test.
- Delete failures leave the note in the list — the server still has it — and surface the message through `error`.
- `byline` says "Mine" / "Shared by {owner}" as plain text. Story 2.3 owns the badge treatment (FR-12); the summary's `owner`/`shared` fields flow through untouched so that story is presentation only.
