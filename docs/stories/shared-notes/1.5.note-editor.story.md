# Story 1.5: Note editor — edit the shared title and body

## Status

Draft

## Story

**As** a user,
**I want** to open a note and edit its title and body,
**so that** I can actually write in the scratchpad.

## Acceptance Criteria

1. **Load.** Given `/shared-notes/notes/:noteId`, when it loads, then it calls `GET /api/shared-notes/notes/{note_id}` through the store and renders the note's title and a full-height body textarea. (FR-6)

2. **Not found.** Given a note id that isn't mine or doesn't exist, when the page loads, then the API returns `404` and the page shows a not-found state with a way back to the home. (FR-2, NFR-2)

3. **Body autosave.** Given the body textarea, when I type and then pause, then the change is saved via `PUT /api/shared-notes/notes/{note_id}` (debounced), the editor stays responsive throughout, and a subtle saved/saving indicator reflects state. (FR-6, NFR-4)

4. **Save errors don't lose text.** Given a save fails, when it errors, then the message surfaces via the store's `error` and my in-progress text is preserved (the textarea is never reverted to the server copy on a failed save). (NFR-4)

5. **Title edit.** Given the title field, when I edit it and commit (blur / Enter), then it is saved via the same `PUT`; a blank title is rejected and the field reverts to the last saved title. (FR-5)

6. **Empty body persists.** Given a body I clear entirely, when it saves, then an empty string is persisted and the note is not deleted.

7. **Tests.** Given the frontend suite, when it runs, then `npm test` stays green, ESLint/Prettier are clean, and specs cover load + render, debounced body save, blank-title rejection/revert, and the not-found state (`useApi` mocked; debounce driven with fake timers).

## Dev Notes

**Debounced, non-blocking autosave.** The textarea is the source of truth while typing; a debounce (e.g. ~600ms after the last keystroke) flushes a `PUT`. Never block input on the network, and never overwrite the textarea with the server response on a *successful* save either — the local text is already ahead. Live updates from *other* members are Story 2.2's concern; until then a single editor is the only writer. (NFR-4)

**Blank title reverts.** The backend rejects a blank title with `422` (Story 1.3); the field should also prevent the empty save client-side and restore the last good title so the user isn't left with an invalid field.

**No live sync yet.** This story assumes one editor at a time. Story 2.2 adds `useNoteEvents` and the reconciliation that merges in another member's change without clobbering text I'm actively typing — leave a clear seam (the save/apply path in the store) for it to hook into.

**Contract.** All HTTP via `useApi`; `{detail}` errors through `ApiError`. [Source: CLAUDE.md#Frontend]
