# Story 5.3: Sharing UI and live membership

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Listies user,
I want to share a sheet from the interface, see who I'm sharing with, and be told live when a sheet
I'm in is shared with someone, taken away, or ended,
so that collaboration is something I do and understand in the app — not an API I can't see.

This is the **user-facing layer** of Epic 5. Story 5.1 gave us the share/unshare/member API and the
shared-sheet response shape; Story 5.2 gave us the live event channel and the store's
`onMembersChanged` / `onClosed` wiring. This story puts a face on both: a share dialog, home badges,
a shared indicator on the sheet, and live reactions to membership changes. **Depends on Stories 5.1
and 5.2.**

## Context & Design Decisions

- **Flat editor model (from 5.1).** Only the **owner** sees and uses share/unshare/manage/delete
  affordances; every member edits content. Non-owners see the sheet is shared and by whom, but no
  management controls.
- Users are chosen from the platform roster: `GET /api/auth/users` returns `{ usernames: [...] }`.
- All HTTP goes through `useApi`; the SSE channel is already isolated in `useSheetEvents.ts` (5.2).
  The store exposes `loading`/`error`; every failure routes into `error`, never a bare
  `console.error`.

## Acceptance Criteria

### Sharing from the UI (owner)

1. **Given** a sheet I own
   **When** I open its menu (on the home card and/or the sheet page) and choose **"Share…"**
   **Then** a `ShareSheetDialog` opens listing the other dock users (from `GET /api/auth/users` minus
   me) to tick, and confirming calls the store's `shareSheet(usernames)` → `POST
   /sheets/{id}/share`; on success the sheet shows as shared-by-me (FR-22).

2. **Given** a shared sheet I own
   **When** I reopen the dialog
   **Then** it shows current members with a way to **add** more (calls `shareSheet`) and **remove**
   any member (calls `removeMember(username)` → `DELETE /sheets/{id}/share/{username}`), plus a
   **"Stop sharing"** action (`stopSharing()` → `DELETE /sheets/{id}/share`); each takes effect on
   confirm and updates the dialog (FR-22).

3. **Given** I am **not** the owner of a shared sheet
   **When** I view it on the home or open it
   **Then** I see it is shared and by whom, but there is **no** share / manage / delete affordance —
   those are owner-only (FR-23).

### Seeing shared sheets

4. **Given** sheets shared with me or by me
   **When** the Listies home renders
   **Then** shared sheets are badged **shared**; a sheet shared *with* me shows the **owner's name**
   ("shared by {owner}"), and a sheet I've shared shows a shared indicator — all in the same list as
   my private sheets (FR-25).

5. **Given** a shared sheet open on the sheet page
   **When** it renders
   **Then** a small shared affordance shows the collaborators (e.g. member count / names); for the
   owner it is the entry point to the share dialog (FR-25).

### Live membership & lifecycle (consuming 5.2 events)

6. **Given** I have a shared sheet open
   **When** the owner adds or removes another member
   **Then** a `members.changed` event updates the collaborator list I see (and the open dialog, if
   owner) without a reload (FR-26).

7. **Given** I have a shared sheet open
   **When** the owner removes me, stops sharing, or deletes the sheet
   **Then** on the `sheet.closed` event (reason `removed` / `unshared` / `deleted`) my view closes,
   I am returned to the Listies home, and a brief Quasar notify explains why — no dead grid, no stack
   trace (FR-26).

8. **Given** any share action fails (network, 403, 422)
   **When** it returns
   **Then** the failure surfaces via the store's `error` (and/or an inline dialog message), the
   dialog stays usable, and nothing is left in a half-applied local state (NFR-4).

9. **Given** the test suite
   **When** it runs
   **Then** `ShareSheetDialog` (add/remove/stop flows, owner-only rendering), home badges, the sheet
   shared affordance, and the live `members.changed` / `sheet.closed` reactions are covered with the
   SSE channel mocked; existing `npm test` stays green and linters are clean (NFR-4).

### Owner-only UI is a convenience, not the guard

The API (Story 5.1) is the real authority — non-owner manage/delete returns 403 regardless of UI.
Hiding the controls is UX, so also handle a 403 gracefully (surface via `error`) rather than assuming
the button can never be reached.

`<script setup lang="ts">`; `defineProps`/`defineEmits` generic syntax; no `any` without a justifying
comment; store exposes `loading`/`error` and routes failures into `error`; snake_case API contract;
tests co-located as `*.spec.ts`.

### Completion Notes List

- **Store actions on the open sheet.** `shareSheet(usernames)` / `removeMember(username)` /
  `stopSharing()` act on `currentSheet` and reuse the Story-5.2 `applyView`, so the returned
  `SheetView` updates collab state and the home summary in one place; `shareSheet` (re)subscribes to
  the live channel, `stopSharing` tears it down. All route failures into `error` (403/422 surface too
  — the UI hiding controls is convenience, not the guard). Added `fetchUsers()` for the picker.
- **Sharing surface = the sheet page.** The `ShareSheetDialog` lives on `SheetPage` (owner-only via
  `v-if="canShare"`, so it is *never instantiated* for a non-owner member — AC-3). It reads collab
  state reactively from the store, so a live `members.changed` updates the open dialog (AC-6). The
  home's "Share…" entry navigates to `/listies/sheets/{id}?share=1`, which auto-opens the dialog on
  load — this is the "and/or the sheet page" latitude in AC-1, chosen because the home summary has no
  member list to manage from.
- **`canShare` ≠ `canManage`.** A **private** sheet I own has `can_manage=false` (it is not shared),
  but I can still share it — so `canShare = !shared || canManage`. The dialog handles the private case
  (no member list / no stop-sharing; button reads "Share"), then flips to manage mode once promoted.
- **Home badges** (AC-4): shared-with-me → "shared by {owner}"; shared-by-me → "shared"; non-owner of
  a shared sheet loses the share **and** delete controls (rename stays — any member may rename, per
  5.1). `isMine = !shared || owner === me`.
- **Live close** (AC-7): `SheetPage` watches `store.closedReason` (set by the 5.2 `onClosed` logic:
  removed→named member, unshared→spares owner, deleted→everyone) → Quasar `notify` + route home. The
  notify call is null-guarded (`$q?.notify?.()`) so it is inert under unit tests where the Quasar
  plugin is absent.
