# Story 2.7: Add a date picker when clicking into a date-type cell

## Status

Ready for Review

## Story

**As** a user,
**I want** a small calendar to pop out when I click into a date cell,
**so that** I can pick a day by eye instead of typing an ISO string by hand.

## Acceptance Criteria

1. **Click opens a popout picker.** Given a `date` column cell, when I click it, then a small popout calendar (not a full-page dialog) opens anchored to the cell, showing days for a month, ready for me to pick from. It replaces the native `type="date"` box used since Story 2.2 as the way a date is entered. (FR-7)

2. **Defaults to the current month.** Given I open the picker on an **empty** date cell, when it appears, then it shows the **current month** with today reachable at a glance; given the cell already holds a date, then the picker opens on that date's month with that day highlighted.

3. **Click a day to fill the cell.** Given the picker is open, when I click a day, then that date is written into the cell through the ordinary row-cells `PUT` (the `commit` contract from Story 2.2) as an ISO `YYYY-MM-DD` string, the picker closes, and the grid shows the compact display form (e.g. `02 Sep 26`) immediately. (FR-7)

4. **Persists like every other cell.** Given a day is picked, when it commits, then it goes through the store's optimistic `commitCell` — applied locally at once, reconciled on success, rolled back with the error surfaced on failure — exactly like a text or number edit; no date-specific write path is added. (NFR-5)

5. **Clearing.** Given a filled date cell, when I clear it from the picker, then it is stored as `null` — not `""`, not an epoch date — the key is pruned from `cells`, and it renders as the muted `—`. (FR-7)

6. **Picker closes appropriately.** Given the picker is open, when I pick a day, click outside it, or press Esc, then it closes; on Esc or an outside click without a pick the cell keeps its previous value and nothing is sent — consistent with every other editor's cancel behaviour. (FR-8)

7. **Keyboard grammar holds.** Given a date cell, when I Tab or Enter out of it without picking a day, then movement behaves exactly as it does for other cells (Story 2.3) and no half-formed value is stored; the picker never traps the cursor in the cell.

8. **The stored value stays canonical.** Given any picked date, when it is stored, then it is a strict ISO `YYYY-MM-DD` string that `parseCell` and the backend's date coercion both accept, that `formatCell` renders in the compact form, and that Story 2.6 still sorts chronologically — the picker changes how a date is entered, never the shape of what is stored.

## Dev Notes

**One write path, again.** Picking a date goes through the same `PUT .../rows/{rid}` cell commit as typing a number — the payload is just an ISO string. No date-specific endpoint, no second `commitCell`. [Source: Story 2.2]

**The mask is the whole trap.** `q-date`'s default output mask is `YYYY/MM/DD`; the sheet stores and validates `YYYY-MM-DD`. Set `mask="YYYY-MM-DD"` so the model the picker emits is already the canonical form — otherwise every picked date fails `parseCell` and the backend's date coercion. `parseCell`/`formatCell`/`formatDate` in `coerce.ts` are the contract the stored value must satisfy. [Source: frontend/src/apps/listies/coerce.ts]

**Editing stays parent-controlled.** The grid owns which cell is being edited because the keyboard moves that selection (Story 2.3); `GridCell` still only asks (`begin-edit` / `end-edit`) and reports (`commit`). The picker opening/closing is driven by the `editing` prop, not by the cell owning its own edit state. [Source: frontend/src/apps/listies/components/GridCell.vue]

**Don't trap the cursor.** Story 4.3 already had to make `commit()` a no-op for `place` columns so Tab-out wouldn't be read as an invalid entry and trap the cursor; a date picker has the same shape — there is no free text to validate — so `commit()` for a date column must likewise just end the edit. Reuse that pattern rather than inventing a new one. [Source: Story 4.3]

**Small popout, not a dialog.** Use `q-menu` (as `ColumnHeaderMenu.vue` does) or `q-popup-proxy` around `q-date` so it floats over the grid and closes on outside-click/Esc for free — a full `q-dialog` would be the wrong weight for a single-tap pick. The place-search dropdown (Story 4.3) had to be teleported to the body to escape the cell's `overflow: hidden`; a `q-menu`/`q-popup-proxy` already renders in a portal, so it will not be clipped by the cell or the grid's scroll container. [Source: frontend/src/apps/listies/components/ColumnHeaderMenu.vue; Story 4.3]
