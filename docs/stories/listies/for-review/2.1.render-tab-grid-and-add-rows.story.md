# Story 2.1: Render a tab as a grid and add rows

## Status

Ready for Review

## Story

**As** a user,
**I want** to see my tab's columns and rows as a dense, readable grid I can add rows to,
**so that** the sheet is something I can actually put data in.

## Acceptance Criteria

1. **Load the sheet.** Given `/listies/sheets/:sheetId`, when it loads, then it calls `GET /api/listies/sheets/{sheet_id}` and renders the first tab (lowest `order`) as a grid. (FR-6)

2. **Grid chrome.** Given the grid, when it renders, then it has a sticky header row of column names in column `order`, one row per stored row in row `order`, real gridlines and subtle zebra striping, tuned to the shell's dark theme. On a narrow screen it scrolls horizontally rather than reflowing. (FR-6, NFR-1)

3. **Type-aware presentation.** Given columns of each type, when cells render, then text is left-aligned, numbers are right-aligned in tabular figures, dates render as `02 Sep 26`, an empty (`null`) cell shows a muted `—`, and each header carries a small glyph for its type (`Aa` / `#` / `▤`).

4. **Add a row.** Given the grid, when I use the "+ row" control, then `POST /api/listies/sheets/{sid}/tabs/{tid}/rows` appends a row with all cells `null` at the end of the stored order, and it appears at the bottom of the grid. (FR-6)

5. **Empty tab.** Given a tab with no rows, when the grid renders, then it shows the header row plus an inviting empty state (not a bare frame) with the add-row action to hand.

6. **Not found.** Given a sheet id that isn't mine or doesn't exist, when the page loads, then the API returns `404` and the page shows a not-found state with a link back to `/listies`.

7. **Loading.** Given the fetch is in flight, when the page renders, then it shows a loading state driven by the store's `loading`, and any failure surfaces the store's `error` rather than a blank page.

## Dev Notes

**One tab only, for now.** This story renders the *first* tab; the tab bar and switching are Epic 3. Keep `activeTabId` in the store from the start so Epic 3 is a UI addition, not a refactor.

**Dense, but designed.** The look is the deliberate part: sticky header, real gridlines, zebra rows, tabular figures for numbers, the focused-cell accent ring (2.3). Not a soft card list. [Source: spec#Visual direction]

**No editing here.** `GridCell.vue` is display-only in this story; 2.2 adds the editor. Splitting it keeps the grid's rendering contract testable on its own.

### Completion Notes
- **Backend:** `GET /sheets/{id}` returns the whole sheet (tabs, columns, rows); `POST /sheets/{sid}/tabs/{tid}/rows` appends a row at `order = len(rows)` and accepts optional initial cells. `_coerce_cells` validates a partial payload against the tab's columns — an **unknown column id raises** rather than being silently dropped, and empty values are pruned so an absent key is exactly `None`. It is shared with the update path in Story 2.2.
- **Frontend:** `coerce.ts` (`formatCell`, `typeGlyph`, `EMPTY_DISPLAY`) is pure and fully unit-tested — dates render `02 Sep 26`, a malformed date passes through rather than being invented, and `0` is never treated as empty. `GridCell` is display-only in this story (2.2 adds the editor). `SheetGrid` renders a real `<table>`: sticky `<th>`, gridlines, zebra rows, horizontal scroll rather than reflow (NFR-1).
- **`order` is authoritative on both axes.** Both the column list and the row list are sorted by `order` before rendering, with tests that shuffle array position to prove it — the document's array order is just however it was last written.
- **The store selects the lowest-`order` tab**, not `tabs[0]`, for the same reason. `activeTabId` exists from this story so Epic 3's tab bar is a UI addition rather than a refactor.
- **TDD:** 10 backend tests red first, then `coerce.spec` (no module), the store additions (7 red), `GridCell.spec`, `SheetGrid.spec`, `SheetPage.spec` (7 red) each in turn.
- **Two of my own test bugs, fixed:** the store spec shared a `SHEET` object that `addRow` pushed into — converted to a `sheet()` factory, the same lesson as Story 1.4's `summary()`. And a header assertion stripped non-letters to remove the type glyph, which does not work when the glyph is `Aa`; the header name now carries its own `data-testid` and the test reads that.
- **Suites:** backend **617** passed (was 605). Frontend **746** passed plus the one pre-existing `hotaru/LibraryPage` failure. `black`, `ruff`, ESLint, Prettier clean.
