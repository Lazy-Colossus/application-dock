# Story 4.6: Colour map pins by a place group

## Status

Ready for Review

## Story

**As** a user,
**I want** to sort my places into named, coloured groups,
**so that** I can tell at a glance which pins belong together on the map — must-see versus maybe, food versus lodging, day one versus day two.

## Acceptance Criteria

1. **A fifth column type.** Given column creation or a retype, when the type list renders, then `place_group` ("Group") appears alongside text / number / date / place. Unlike `place`, it is offered whether or not maps are configured — a group is just a label until there is a map to colour.

2. **Groups live on the tab.** Given `schemas/listies.py`, when a tab is validated, then it carries `place_groups: list[PlaceGroup]` where a `PlaceGroup` is `{ id, name, color }` with `color` matching the existing `#rrggbb` pattern. The field is optional and additive, so a document written before groups validates unchanged and `schema_version` stays `1`.

3. **A group cell stores an id.** Given a `place_group` cell, when it is written, then it holds a **group id string** (or `null` for ungrouped) — never the colour or name — so recolouring or renaming a group updates every pin without touching a single cell. A cell whose id is not among the tab's `place_groups` is treated as **ungrouped**, not an error (a group can be deleted out from under it). The cell union is unchanged: an id is a string.

4. **Coercion / retype.** Given a retype touching a group column, when applied, then `place_group` → text keeps the group's **name** (resolved through the tab's groups); `place_group` → number / date blanks to `null`; anything → `place_group` blanks to `null` (a group cannot be reconstructed from a scalar); and Story 2.5's "this will empty N cells" warning covers each direction.

5. **Grid rendering + the dropdown editor.** Given a `place_group` cell, when it renders, then it shows the group's colour swatch and name; an empty group cell shows the muted `—`. When I click it, then a **dropdown-select** of the tab's groups opens — each option a swatch beside its name — plus a "None" option to clear; choosing one commits the group id through the ordinary `commitCell`, exactly like any other cell.

6. **The Groups button.** Given the active tab has at least one `place_group` column, when the sheet toolbar renders, then a **"Groups" button** appears in the top-right toolbar (`listies-sheet__toolbar`, beside "Map"), shown whether or not the map is open and whether or not any place exists yet. Given no `place_group` column, then the button is absent.

7. **Managing groups.** Given the Groups button, when I open it, then a popup lists each group with an **editable name**, a **colour picker** (hex output), and a **delete** control, plus **"Add group"**. When I add, rename, recolour or delete a group, then it persists through the tab's existing update path (`PUT .../tabs/{id}`, extended to carry `place_groups`) and every pin and cell using that group reflects the change at once.

8. **Pins colour by group — the column scheme is gone.** Given the map, when pins render, then each row's pins take the colour of the group in that row's `place_group` cell, and **all** of a row's place pins share it (per the one-group-per-row model). A row with no group, or a tab with no `place_group` column, shows the **plain default pin**. The previous automatic "one colour per place column" scheme (`COLUMN_COLOURS` / `colourFor` / `iconFor`) is removed. If a tab somehow has more than one `place_group` column, the first by `order` decides the colour.

9. **The legend follows groups.** Given at least one group is in use on the map, when the legend renders, then it lists those groups (swatch + name) at the bottom-left; with no group in use, no legend shows. The old column-name legend is gone.

10. **Sorting.** Given a sort on a `place_group` column, when applied, then rows compare by the group's **name** (resolved through the tab's groups) with the text comparator, empties last — consistent with how `place` sorts by name in Story 4.2.

## Dev Notes

**Replacing, not layering.** This story *removes* the automatic colour-by-column scheme in `MapPane.vue` (`COLUMN_COLOURS`, `colourFor`, `iconFor`'s column branch, and the column legend) and makes the group the only meaning of pin colour. That scheme only ever fired for tabs with 2+ place columns, so most tabs see no behavioural change beyond gaining the new type. [Source: frontend/src/apps/listies/components/MapPane.vue]

**Store the id, not the colour.** A group cell holds the group's id; colour and name live once on the tab in `place_groups`. Recolouring or renaming a group is then one tab write, and every pin and cell reflects it with no per-cell rewrite. A deleted group leaves dangling ids that simply read as ungrouped — no cascade. [Source: AC 3, AC 7]

**No new endpoint, no union change.** Group management rides the existing `PUT .../tabs/{id}` that already sets a tab's accent colour — `UpdateTabRequest` gains an optional `place_groups`, and the store action mirrors `recolourTab`. And because a group id is a string, `CellValue` is untouched on both sides of the wire; this is even more additive than Story 4.2's place type. [Source: frontend/src/apps/listies/stores/useListiesStore.ts#recolourTab; backend/app/schemas/listies.py#UpdateTabRequest]

**One shared type list.** Add `place_group` to `columnTypes.ts` only — the builder, header menu and add-column popup all read from it, so they cannot drift (the trap Story 4.2 called out). Unlike `place`, the group type is *not* gated on maps being configured. [Source: frontend/src/apps/listies/columnTypes.ts]

**One group per row colours all its pins.** A tab can have several place columns (Hotel, Dinner, Coffee) but one group cell per row; every place pin in that row takes the row's group colour. This is the model the user chose over per-individual-pin grouping. [Source: brainstorming session, 2026-09-04]

**The button lives above the split, not inside the map.** It sits in `listies-sheet__toolbar` (where the "Map" toggle already is), so groups can be defined before any place is added and while the map is closed — the map pane itself only renders once there are pins. [Source: frontend/src/apps/listies/pages/SheetPage.vue]

**Don't trap the cursor.** As with `place` (Story 4.3) and the date picker (Story 2.7), a group cell has no free text to validate, so its `commit()` must just end the edit when nothing is chosen — otherwise the grid's commit-before-move (Story 2.3) can trap the cursor. [Source: Story 4.3]

### Completion Notes

- **The `CellValue` union never changed, on either side of the wire.** A group cell holds a `str` id; `coerce_value` accepts a non-empty string (or `null`) in a `place_group` column and rejects a `Place`/dict there. This is even more additive than Story 4.2's place type — a document written before groups validates unchanged and `schema_version` stays `1` (tested both backend and via `migrate`).
- **Retype coercion needed the *old* type and the tab's groups.** `place_group` → text keeps each group's **name** (resolved through `tab.place_groups`); a **dangling** id blanks even then; `place_group` → number/date/place blanks; anything → `place_group` blanks. `recoerce_column`/`_reparse` gained `old_type` and `groups` params, threaded from `update_column` (which already had the tab in hand). The frontend `countBlankedByRetype` mirrors this with optional `fromType`/`groups` so the "empties N cells" warning is accurate.
- **A deleted group is not a cascade.** Deleting a group never rewrites cells; a dangling id "reads as ungrouped, not an error" everywhere — the grid cell shows the muted `—`, the sort treats it as an empty name, and the map gives it the default pin. Verified in coercion, cell-render, sort and map tests.
- **Pins recolour live despite the SDK marker having no `setIcon`.** The marker's map key folds in its group colour (`${pin.key}#${colour}`), so a recolour makes the old-keyed marker stale and `syncMarkers` recreates it; `placeGroups` was added to the marker watch so a recolour actually triggers the sync. A test drives a live recolour and asserts the repaint.
- **The old colour-by-column scheme is gone.** `COLUMN_COLOURS`, `colourFor`, `iconFor`'s column branch and the column legend were removed from `MapPane.vue`; a tab with several place columns and no group is now all default pins with no legend (tested). The now-unused `Pin.columnId` field was dropped.
- **One shared offered-types list.** `place_group` ("Group") was added to `columnTypes.ts` only, so the builder, header menu and add-column popup all pick it up; unlike `place` it is **not** gated on maps being configured.
- **The Groups button sits above the split** in `listies-sheet__toolbar` beside "Map", shown whenever the active tab has a group column — with maps on or off. `GroupManager.vue` holds a working draft and emits `save` on each committed change (add / rename-on-blur / recolour / delete); `SheetPage` persists it via the new `store.setPlaceGroups`, which rides the existing `PUT .../tabs/{id}` (mirroring `recolourTab`).
