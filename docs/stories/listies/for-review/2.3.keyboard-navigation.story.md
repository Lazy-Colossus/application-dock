# Story 2.3: Keyboard navigation across the grid

## Status

Ready for Review

## Story

**As** a user,
**I want** to move around the grid with the keyboard the way I would in a spreadsheet,
**so that** I can enter a lot of data without touching the mouse.

## Acceptance Criteria

1. **Tab / Shift-Tab.** Given a cell in edit mode, when I press Tab, then the cell commits and focus moves one cell right — wrapping from the last column to the first cell of the next row. Shift-Tab mirrors it, wrapping from the first column to the last cell of the previous row. At the very start/end of the grid, focus stays put. (FR-8)

2. **Enter.** Given a cell in edit mode, when I press Enter, then the cell commits and focus moves one cell down in the same column; from the last real row it moves into the trailing empty row.

3. **Arrows when not editing.** Given a focused cell that is not in edit mode, when I press an arrow key, then focus moves one cell in that direction and stops at the grid's edges; typing a printable character enters edit mode with that character.

4. **The trailing ghost row.** Given the grid, when it renders, then exactly one empty "ghost" row follows the last real row. Typing into a ghost cell creates a real row via `POST .../rows` carrying that value, focus stays in the cell that is now real, and a fresh ghost row appears beneath it. (FR-8)

5. **No phantom rows.** Given a ghost row, when I move through it without typing anything, then no row is created.

6. **Visible focus.** Given the focused cell, when it is focused, then it shows a crisp accent ring (not the default browser outline), and it is scrolled into view when focus moves off-screen.

7. **Testable in isolation.** Given the focus model, when it is implemented, then it lives in `composables/useGridNavigation.ts` as pure state + movement functions, unit-tested without mounting the grid.

## Dev Notes

**Why a composable.** Focus movement with wrapping and a ghost row is where off-by-one bugs live. Keeping it as pure state means each rule is a two-line test instead of a mounted-grid interaction test. [Source: spec#Frontend structure]

**Commit-then-move.** Movement keys always commit first (reusing 2.2's commit path); Esc is the only key that discards. If a commit fails, focus still moves — the rollback + `error` from 2.2 handles the failure, so a network blip never traps the cursor.

**Double-creation guard.** The ghost row is the one place a keystroke can create a row; a second keystroke arriving before the POST resolves must extend the same pending row, not create another.

### Completion Notes
- **`useGridNavigation`** holds `{focused, editing}` over a `(rowCount, columnCount)` shape supplied as getters — no DOM, no store, no Vue components. 21 tests cover wrapping both ways, edge clamping, the edit transitions, and `clampToGrid` for when rows disappear. Exactly the payoff the story predicted: each rule is a two-line test instead of a mounted-grid interaction.
- **`GridCell` became parent-controlled.** The keyboard moves the *selection*, so the grid has to own which cell is editing; the cell now asks (`begin-edit` / `end-edit`) and reports (`commit`). Its spec was rewritten to the new contract first, watched fail (15 red), then the component changed.
- **A bug the design surfaced before it could ship:** moving focus removes the editor from the DOM, and **removal does not fire `blur`** — so relying on blur to save would silently discard the entry that the Tab keystroke was meant to commit. The grid now explicitly commits the focused cell (through an exposed `commit()`) *before* moving. That is also why `Enter` is handled by the grid rather than the cell: having both handle it produced a double commit.
- **Arrows are ignored while editing** — inside a text box they belong to the text, not the grid.
- **Ghost row:** one trailing empty row, always. Typing in it emits `add-row` with just that cell; passing through without typing emits nothing. A `ghostPending` flag makes a second keystroke unable to create a second row, and it re-opens when the row count changes.
- **One process slip, corrected:** I wired `@add-row="store.addRow($event)"` in `SheetPage` in the same step as its test rather than before it. I re-ran with the fix reverted to confirm the test genuinely fails without it, then restored — evidence rather than assumption.
- **Suites:** frontend **823** passed plus the one pre-existing `hotaru/LibraryPage` failure; backend unchanged at **629** (this story is frontend-only). ESLint and Prettier clean.
