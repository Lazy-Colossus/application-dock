# Story 2.5: Manage a tab's columns

## Status

Draft

## Story

**As** a user,
**I want** to add, rename, retype, reorder and delete columns after creating a tab,
**so that** the sheet can change shape as I learn what I actually need.

## Acceptance Criteria

1. **Add a column.** Given a tab, when I add a column (`POST .../columns` with `{name, type}`), then it is appended in column order with a fresh `c-{uuid8}` id, and every existing row shows it as empty (`—`) with no change to their stored cells. (FR-10, AR-5)

2. **Rename.** Given a column header, when I open its menu and rename the column (`PUT .../columns/{cid}` with `{name}`), then the header updates and no row data changes — cells are keyed by column id, not name.

3. **Retype.** Given a column header, when I change its type, then the endpoint returns the whole updated tab with each cell coerced by the documented rules: any → `text` keeps everything as a string; → `number` keeps values that parse as numbers and blanks the rest; → `date` keeps values that parse as `YYYY-MM-DD` and blanks the rest. Blanked cells become `null` (pruned), and the UI warns before applying a retype that would blank data.

4. **Reorder.** Given a column header, when I move it left or right (`PUT .../columns/order` with the full `{column_ids}` list), then the grid re-renders in the new order and the order persists.

5. **Reorder validation.** Given a `column_ids` payload that is not a permutation of the tab's current columns (missing, extra or duplicated ids), when submitted, then it is rejected with `422` `{detail}` and nothing is written.

6. **Delete.** Given a column header, when I delete the column and confirm, then the column and every row's value for it are removed from my file.

7. **Last column protected.** Given a tab with exactly one column, when I try to delete it, then the API rejects it with `422` `{detail}` and the client does not offer delete — a tab always has at least one column.

8. **Name validation.** Given a rename or add with a blank name or a name that duplicates another column in the same tab, when submitted, then it is rejected with `422` `{detail}`.

9. **Unknown ids.** Given any column operation naming a column id that isn't in that tab, when requested, then the API returns `404` `{detail}`.

## Dev Notes

**Why the endpoints return a whole `Tab`.** A retype can change many rows and a reorder changes every column's `order`; returning the tab lets the client replace it wholesale instead of reconciling deltas. [Source: spec#API]

**Coercion lives in one place.** `recoerce_column` was built in Story 1.2 and is shared with the write path — do not re-implement the rules here. [Source: Story 1.2, AC 7]

**Route ordering.** `/columns/order` before `/columns/{column_id}`. This is the single most likely silent bug in the story.

**Warn before blanking.** The client compares the current values against `parseCell` for the new type and tells the user how many cells will be emptied before it sends the retype.
