# Story 4.4: The map pane beside the grid

## Status

Draft

## Story

**As** a user,
**I want** to open a map next to my grid showing every place in the tab,
**so that** a tab of cafés becomes a map of that city.

## Acceptance Criteria

1. **The toggle.** Given a tab with at least one place column and maps configured, when the tab toolbar renders, then it offers a `Map` toggle; the toggle is absent for a tab with no place column and when maps are not configured. (FR-17, FR-20)

2. **Split and restore.** Given the toggle, when I open it, then the view splits — grid left, map right — and closing it returns the grid to full width. The open state is remembered per tab for the session. (FR-17, NFR-1)

3. **Lazy SDK.** Given the pane opens for the first time, when it loads, then the Maps JS SDK is fetched **once, on demand**, using the browser key from `GET /api/listies/maps-config`; the key is never baked into the bundle and the SDK is not loaded for users who never open a map. (NFR-6)

4. **Markers.** Given the pane is open, when it renders, then it plots one marker per non-empty place cell in the tab; when a tab has more than one place column the markers are colour-coded per column with a small legend. (FR-17)

5. **Bounds.** Given the pane opens, when the markers are plotted, then the map fits its bounds to them; a single place is centred at a sensible zoom rather than fully zoomed in.

6. **Labels.** Given a marker, when it renders, then it is labelled by its row's first text value, falling back to the place's own name when the row has no text column or the value is empty.

7. **Marker → row.** Given a marker, when I click it, then its row is highlighted and the grid scrolls to it. (FR-19)

8. **Row → marker.** Given a row, when I select it in the grid, then the map pans to that row's pin (without changing zoom). (FR-19)

9. **No places.** Given a tab whose place cells are all empty, when the pane opens, then it shows an empty state inviting me to fill a place cell — not a blank world map.

10. **Failure is contained.** Given the SDK fails to load or the key is rejected, when the pane opens, then it shows an error state and the grid keeps working normally. (FR-20)

11. **Live updates.** Given the pane is open, when I fill in or clear a place cell, then its marker appears or disappears without reopening the pane, and the bounds are not re-fitted.

## Dev Notes

**Toggleable split, deliberately.** The split view is the chosen shape, but it is opened rather than permanent: a wide grid keeps its width when you are not looking at a map, and the Maps SDK — the heaviest thing this app loads — is only fetched when someone actually asks for a map. [Source: spec#Interaction design]

**Never re-fit on data change.** Re-fitting the bounds while someone is editing makes the map lurch. Fit on open and on the explicit control (4.5); otherwise leave the viewport alone. [Source: AC 11, Story 4.5]

**Stub the SDK in tests.** No test loads Google's script. `maps.ts` is the seam: inject a fake `google.maps` in specs.
