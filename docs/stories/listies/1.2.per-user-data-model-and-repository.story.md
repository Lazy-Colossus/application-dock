# Story 1.2: Per-user data model, repository & schemas

## Status

Draft

## Story

**As** the platform,
**I want** a JSON file per user with an atomic-write repository and typed schemas,
**so that** every user's sheets, tabs, columns and rows are stored and isolated correctly.

## Acceptance Criteria

1. **Empty document on first read.** Given `repositories/listies_repo.py`, when a user's document is read and they have no file yet, then it returns `{ schema_version: 1, sheets: [] }` without error. (AR-2)

2. **Repo is the only filesystem access.** Given any write, when it happens, then it goes through `_atomic_write_json` (write-`.tmp`-then-`os.replace`) and `mkdir(parents=True, exist_ok=True)` creates `users/` on first write; no service or router touches the filesystem. (NFR-3, AR-3)

3. **Path safety.** Given a username containing `/`, `\`, `.` or `..`, when the repo derives a path, then it raises `ValueError` rather than writing outside `DATA_DIR/listies/users/`. (NFR-2)

4. **Schemas.** Given `schemas/listies.py`, when models are defined, then Pydantic v2 models exist for `Column` (`id`, `name`, `type: Literal["text","number","date"]`, `order`), `Row` (`id`, `order`, `cells: dict[str, str | int | float | None]` — `int` before `float` so a whole number stays a whole number on round-trip, `created_at`, `updated_at`), `Tab` (`id`, `name`, `order`, `columns`, `rows`), `Sheet` (`id`, `name`, `created_at`, `tabs`) and `ListiesDoc` (`schema_version`, `sheets`). (AR-3, AR-5)

5. **Migration hook.** Given `migrate(raw)`, when a document is read, then it runs before validation; v1 is a pass-through, so future `schema_version` bumps have one home.

6. **Id minting and timestamps.** Given anything created, when the service mints it, then it gets a stable id (`s-`/`tb-`/`c-`/`r-` + 8 hex chars) and ISO-8601 UTC timestamps; ids are unique within the document.

7. **Type coercion helpers.** Given `services/listies_service.py`, when a cell value is written or a column is retyped, then shared helpers `coerce_value(value, column_type)` (raises `ValueError` on a value that does not fit) and `recoerce_column(rows, column_id, new_type)` (keeps what parses, blanks the rest) implement the documented rules — one implementation used by both paths.

8. **Layer purity.** Given the service, when it fails, then it raises stdlib exceptions (`FileNotFoundError` for a missing sheet/tab/column/row, `ValueError` for invalid input) and never `HTTPException`. (NFR-4)

9. **Round-trip test.** Given a document with a sheet, a tab, columns of all three types and rows with `null` and non-`null` cells, when written and read back, then it validates and is byte-stable in content.

## Dev Notes

**Cells keyed by column id.** `Row.cells` is `dict[column_id, value]`. Never index- or name-keyed — this is what makes rename/reorder/delete of columns non-destructive. Absent key ≡ `null`; the service prunes `null` entries and entries for columns that no longer exist so files stay small. [Source: spec#Data model, AR-5]

**`null` is not `0` or `""`.** Empty means "not filled in". A text value that is empty or whitespace normalizes to `null`. Same rule archery uses for unentered shots. [Source: CLAUDE.md#Sessions data model]

**Atomic writes.** Reuse `session_repo._atomic_write_json`, exactly as `context_switch_repo` does; extracting it to a shared core util is tracked separately and out of scope here.

**Scope discipline.** No routes and no endpoints in this story beyond what Story 1.1 mounted. Sheet creation lands in 1.3.
