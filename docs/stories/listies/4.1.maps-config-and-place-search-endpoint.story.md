# Story 4.1: Maps configuration and the place-search endpoint

## Status

Draft

## Story

**As** the platform,
**I want** Google credentials in server configuration and place search proxied through our own API,
**so that** the server key never reaches the browser, searches are cached, and an unconfigured deployment degrades cleanly instead of breaking.

## Acceptance Criteria

1. **Settings.** Given `app/core/config.py`, when settings load, then `google_maps_server_key` and `google_maps_browser_key` are read from the environment (both defaulting to `""`), and `docker-compose.yml` passes `GOOGLE_MAPS_SERVER_KEY` / `GOOGLE_MAPS_BROWSER_KEY` through. (AR-6, FR-20)

2. **Config endpoint.** Given `GET /api/listies/maps-config` called by an authenticated user, when both keys are configured, then it returns `{ enabled: true, browser_key: "…" }`; otherwise `{ enabled: false }` with no key field. It **never** returns the server key. (NFR-6)

3. **Search endpoint.** Given `GET /api/listies/places/search?q=…`, when maps are configured, then `services/places_service.py` calls the Google Places **Text Search** endpoint with the server key and returns a normalized `list[PlaceResult]` — `place_id`, `name`, `address`, `lat`, `lng`. It is the only module in the codebase that talks to Google. (AR-6, FR-16)

4. **Caching.** Given a repeated `(q, near)` within the cache TTL, when requested, then it is served from an in-process cache with no second upstream call; the cache is bounded in entry count and entries expire. (NFR-6)

5. **Location bias.** Given `near=lat,lng`, when searching, then the upstream request biases results toward that point; an unparseable `near` is ignored rather than fatal.

6. **Unconfigured.** Given the keys are unset, when `/places/search` is called, then it returns `503` with a `{detail}` naming the missing configuration; nothing crashes and no other app is affected. (FR-20)

7. **Upstream failure.** Given an upstream non-2xx, transport error or timeout, when searching, then the endpoint returns `502` `{detail}` — never a stack trace, never the key, and never a partial result.

8. **Blank query.** Given a blank or whitespace `q`, when requested, then it returns `422` `{detail}` without calling Google.

9. **Auth.** Given either endpoint without a valid token, when called, then it is rejected by `Depends(get_current_user)` like every other route. (NFR-4)

10. **No live calls in tests.** Given the test suite, when it runs, then no test performs a real network call — `httpx` is stubbed — and `httpx` has moved from `requirements-dev.txt` into `requirements.txt`.

## Dev Notes

**Why proxy at all.** The server key stays server-side and searches are cached, so retyping a query does not re-bill; the browser key is separately referrer-restricted and handed to the SPA at runtime so it is never baked into a build artifact. [Source: NFR-6]

**Field mask is a cost lever.** Google bills Text Search by the SKU implied by the fields requested. Ask only for `places.id`, `places.displayName`, `places.formattedAddress`, `places.location`.

**Degrade, don't crash.** This is the platform's first optional external credential. `enabled: false` must be a completely ordinary state — the frontend hides the place type and the map, and nothing else in the dock notices. [Source: FR-20]

**Scope discipline.** Backend only. No `place` column type (4.2), no cell UI (4.3), no map (4.4).
