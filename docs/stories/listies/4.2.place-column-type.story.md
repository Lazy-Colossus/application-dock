# Story 4.2: The `place` column type

## Status

Draft

## Story

**As** a user,
**I want** a column whose cells hold a real location,
**so that** a row can be somewhere I intend to go rather than just its name.

## Acceptance Criteria

1. **A fourth type.** Given column creation or a retype, when the type list renders, then `place` appears alongside text / number / date — offered only when `maps-config` reports `enabled`. (FR-15, FR-20)

2. **Schema.** Given `schemas/listies.py`, when a place cell is validated, then a `Place` model (`place_id`, `name`, `address`, `lat`, `lng`) is accepted for a `place` column and rejected for any other column type; a scalar written into a `place` column is a `422`. (AR-7)

3. **Backward compatible.** Given a document written before places existed, when it is read, then it validates unchanged — the union widened additively, so `schema_version` stays `1`. (AR-7)

4. **Coercion.** Given a retype touching a place column, when applied, then `place` → `text` keeps the place's `name`; `place` → `number` / `date` blanks to `null`; anything → `place` blanks to `null`; and Story 2.5's "this will empty N cells" warning covers all three. (FR-10)

5. **Grid rendering.** Given a place cell, when it renders, then it shows a 📍 glyph with the place name on the first line and the address muted beneath; an empty place cell shows the same muted `—` as every other type.

6. **Sorting.** Given a sort on a place column, when applied, then rows compare by place **name** with the text comparator and empties last. (FR-11)

7. **Latitude / longitude sanity.** Given a place payload with `lat` outside ±90 or `lng` outside ±180, when validated, then it is rejected with `422`.

## Dev Notes

**Additive, so no migration.** Old documents contain no place columns and no object cells, so widening the union changes nothing on disk. `migrate()` stays a pass-through and `schema_version` stays `1`. [Source: AR-7]

**Snapshot, not a reference.** The cell keeps what Google returned at the time. Nothing is re-fetched later, so a sheet still reads correctly if the key is removed, and an "open in Google Maps" link is derived from `place_id` without a call. [Source: NFR-6]

**Scope discipline.** The type, its storage, its rendering and its sorting. Searching to *fill* a place cell is 4.3.
