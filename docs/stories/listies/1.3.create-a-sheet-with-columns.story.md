# Story 1.3: Create a sheet with custom columns, and pick one

## Status

Draft

## Story

**As** a user,
**I want** to create a sheet by naming it and defining its columns, and to open an existing one,
**so that** I can keep separate, differently-shaped lists.

## Acceptance Criteria

1. **Home lists my sheets.** Given `/listies`, when it loads, then it calls `GET /api/listies/sheets` (scoped to me by the token) and shows my sheets as selectable items with their name and a row count. (FR-2, FR-4)

2. **Empty state.** Given I have no sheets yet, when the home loads, then it shows a calm empty state prompting me to create my first sheet (no error).

3. **Create a sheet.** Given the create dialog, when I enter a name and define columns (each a name + a type from text / number / date), then `POST /api/listies/sheets` with `{ name, columns: [{name, type}] }` persists a sheet with an `s-{uuid8}` id and one tab named "Tab 1" carrying those columns (each with a `c-{uuid8}` id and an `order`) and no rows, and I am navigated to `/listies/sheets/:sheetId`. (FR-3)

4. **Column builder.** Given the create dialog, when I add, remove or reorder column definitions before submitting, then the builder reflects it live; the dialog starts with one empty column row.

5. **Create validation.** Given a submission with a blank sheet name, zero columns, a blank column name, a duplicate column name within the tab, or an unknown type, then the client disables submit (no request) and the API rejects it with `422` `{detail}` as a backstop.

6. **Open a sheet.** Given an existing sheet on the home, when I select it, then I navigate to `/listies/sheets/:sheetId`.

7. **Summaries only.** Given `GET /api/listies/sheets`, when it responds, then it returns `SheetSummary` objects (`id`, `name`, `tab_count`, `row_count`, `created_at`) — not full tab/row payloads (the sheet page fetches those).

8. **Isolation.** Given a second user's token, when they call `GET /api/listies/sheets`, then they see only their own sheets. (FR-2)

## Dev Notes

**Store contract.** Expose `loading`/`error` refs; async actions use `try/finally`; errors go to `error.value`, never a bare `console.error`. All HTTP through `frontend/src/composables/useApi.ts` (it injects `Authorization` and throws `ApiError`). [Source: CLAUDE.md#Frontend]

**Auth scoping.** Routes use `current_user: str = Depends(get_current_user)` and pass it into the service — this app needs the username to pick the file. No `user` is ever read from a path or body. [Source: AR-4]

**First tab name.** "Tab 1" — a plain default the user renames in Story 3.3. The sheet's creation columns seed *that tab*, not the sheet: columns are per-tab (FR-13).

**Scope discipline.** Sheet read/create and the home UI only. Rename/delete is 1.4; the grid is Epic 2; `SheetPage.vue` stays the placeholder from 1.1.
