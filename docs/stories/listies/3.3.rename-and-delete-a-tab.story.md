# Story 3.3: Rename and delete a tab

## Status

Draft

## Story

**As** a user,
**I want** to rename a tab or remove one I no longer need,
**so that** the sheet's tabs keep matching what's actually in them.

## Acceptance Criteria

1. **Rename.** Given a tab chip, when I open its menu and rename it (`PUT .../tabs/{tid}` with `{name}`), then the name updates in my file and in the bar. (FR-14)

2. **Rename validation.** Given a blank or whitespace name, when submitted, then the client disables submit and the API rejects it with `422` `{detail}`.

3. **Delete with confirmation.** Given a tab chip, when I choose delete and confirm, then `DELETE .../tabs/{tid}` removes the tab, its columns and all its rows from my file; if it was the active tab, the grid switches to its neighbour (the next tab, or the previous one if it was last). (FR-14)

4. **The confirmation names the cost.** Given the confirm dialog, when it opens, then it names the tab and how many rows will be destroyed.

5. **Last tab protected.** Given a sheet with exactly one tab, when I try to delete that tab, then the API rejects it with `422` `{detail}` and the client does not offer delete — a sheet always has at least one tab. (FR-14)

6. **Unknown id.** Given a rename or delete for a tab id that isn't in this sheet, when requested, then the API returns `404` `{detail}`.

7. **Order preserved.** Given the remaining tabs, when one is deleted, then their relative order in the bar is unchanged.

## Dev Notes

**Neighbour selection.** Deleting the active tab must always leave a valid `activeTabId` — next tab, or previous if the deleted one was last. AC 5 guarantees there is always at least one left.

**Say what will be lost.** Deleting a tab destroys every row in it with no undo; the confirm dialog carries the row count rather than a generic "are you sure". [Source: platform convention, Story 1.4]
