# Story 4.3: Search Google and fill a place cell

## Status

Draft

## Story

**As** a user,
**I want** to type a place name into a cell and pick the real place from Google,
**so that** filling in a location takes one search rather than a copy-paste of coordinates.

## Acceptance Criteria

1. **Search in place.** Given a place cell, when I click it, then it opens a search field in place, pre-filled with the current place's name if it has one and with the text selected. (FR-16)

2. **Debounced search.** Given the search field, when I have typed at least two characters, then after a debounce (~300ms) the client calls `GET /api/listies/places/search` through `useApi` and shows a result list beneath the cell — name in full, address muted. Fewer than two characters searches nothing. (NFR-6)

3. **Pick a result.** Given the result list, when I move through it with ↑/↓ and press Enter (or click a result), then the chosen place is written through the ordinary row-cells `PUT` as a whole place object and appears in the grid immediately, with the same optimistic-then-reconcile-or-roll-back behaviour as every other cell. (FR-16, NFR-5)

4. **Local bias.** Given the column already holds places, when a search is issued, then it passes `near` as the centroid of those places, so results are local to what is already in the column.

5. **Honest states.** Given a search that is loading, returns nothing, or fails, when it renders, then the cell shows a loading indicator, a "no places found" line, or the error message — never a silent empty dropdown.

6. **Clearing.** Given a filled place cell, when I clear it, then it is stored as `null` and renders as `—`.

7. **Esc.** Given the result list is open, when I press Esc, then the list closes, the cell keeps its previous value, and nothing is sent — consistent with every other editor. (FR-8)

8. **Keyboard grammar holds.** Given a place cell, when I Tab or Enter out of it without picking a result, then movement behaves exactly as it does for other cells and no half-typed query is stored. (FR-8)

9. **Unconfigured.** Given maps are not configured, when a place cell is opened, then it is read-only and says maps are not configured, rather than offering a search that cannot work. (FR-20)

10. **Stale responses.** Given two searches in flight, when the earlier one resolves last, then its results are discarded — the list always reflects the latest query.

## Dev Notes

**One write path.** Selecting a place goes through the same `PUT .../rows/{rid}` cell commit as typing a number — the payload is just an object. No place-specific endpoint. [Source: Story 2.2]

**Debounce is a cost control, not polish.** Every keystroke that reaches `/places/search` is a billable upstream call on a cache miss. Debounce plus the two-character minimum plus the server-side cache are what keep this cheap. [Source: NFR-6]

**Don't hijack the keyboard.** The result list owns ↑/↓ and Enter only while it is open; Tab, and Enter with no list, must behave exactly as they do in every other cell so the grid's movement rules stay uniform. [Source: Story 2.3]
