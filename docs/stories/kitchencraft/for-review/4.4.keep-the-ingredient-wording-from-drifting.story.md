# Story 4.4: Keep the ingredient wording from drifting

## Status

Ready for Review

## Story

As the builder,
I want each pass to reuse the ingredient wording that already exists in the collection,
so that the ingredient wording does not quietly fragment as the collection grows.

## Context

Re-cut 2026-09-15. This story guarded a shared category vocabulary that Story 2.8
removed. The duty survives against a different shape of data: there is still
wording to keep consistent, it is just free text now.

## Acceptance Criteria

1. **A pass reuses the wording already present**, introducing new wording only where nothing existing fits. (FR-22)

2. **Two passes do not produce near-synonyms or casing variants** for the same thing. (FR-22)

3. **A completed pass lists every newly introduced ingredient**, so drift is visible immediately rather than discovered months later. (FR-22)

4. **Amounts and units go in their own fields**, not into the ingredient name. (Story 2.8)

### Completion Notes

- **AC 1 is served by the report, not by the writer.** The report carries the collection's existing tags, ingredients and units precisely so the inference step can see them. A pass that cannot see the wording will invent a near-synonym for it, and no amount of post-hoc checking fixes that.
- **AC 2's casing half is structural and already enforced.** `_clean_ingredients` and `_clean_tags` fold onto the casing already in use, so `Red Lentils` becomes `red lentils` on the way in, whoever writes it. Tested from the enrichment path specifically, not just the API path.
- **AC 2's near-synonym half is not enforceable in code, and is not claimed to be.** `chicken` versus `chicken meat` is a judgement. That is exactly what AC 3 exists for.
- **AC 3 is the honest half of this story.** The script diffs the vocabulary before and after a write and prints what is new, with a line telling the operator to check it. It is a prompt to a human, not a guarantee — presenting it as a guarantee would be the lie this story is meant to prevent.
- **AC 4 is enforced by the schema, not by the pass.** Amount and unit are separate fields, so `2 tsp smoked paprika` cannot be stored as one opaque string by any writer, enrichment included.
- **A tag already on a recipe is neither duplicated nor marked.** The user's tag stays the user's; no mark is invented for a value a pass did not write.
