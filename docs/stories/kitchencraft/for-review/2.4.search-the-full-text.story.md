# Story 2.4: Search the full text

## Status

Ready for Review

## Story

As a cook,
I want to search for a word I remember from a recipe,
so that I can find it again without remembering what I called it.

## Acceptance Criteria

1. **Bodies are searched, not just tags.** Given a recipe whose body mentions paprika but carries no paprika tag, when the user searches `paprika`, then that recipe is returned. (FR-11)

2. **Case-insensitive and partial-word.** Given any search term, when it is matched, then matching is case-insensitive and matches partial words, across both names and bodies. (FR-11)

3. **Search combines with filters.** Given active filters, when a search is entered, then the two combine — the search narrows within the filtered set rather than replacing it. (FR-11)

4. **Instant at personal scale.** Given a collection of a few hundred recipes, when the user types, then results update without perceptible delay. (NFR-6)

### Completion Notes

- **Search runs client-side over the loaded collection**, which is why Story 1.4's list endpoint returns bodies. NFR-6 sanctions this explicitly at personal scale; AC 4 is satisfied structurally — there is no round trip to be slow, no spinner and no debounce, and a spec asserts no loading affordance appears.
- **"Combines rather than replaces" is enforced by shape, not by care.** `search` is one field on the same `Filters` object as the selections, and `results` is a single predicate over all of them. There is no code path in which entering a search could clear a filter, because nothing writes to the other fields. Two specs pin both directions.
- **`clearOne` is per-control** ([Source: EXPERIENCE.md § Interaction Primitives] — "Nothing clears anything else"): the search has its own clear line in the zero-result state (Story 2.5), and clearing it leaves every filter untouched.
- Search deliberately covers **names and bodies only**, not tags or ingredients. This is the spine's own open question ("a user typing `chickpeas` will match bodies that mention them but not recipes tagged with them") and it is left as specified — widening it would make the pantry filter's job ambiguous.
