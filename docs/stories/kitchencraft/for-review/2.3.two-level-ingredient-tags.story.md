# Story 2.3: Two-level ingredient tags

## Status

Ready for Review

## Story

As a cook,
I want to record what a recipe uses as a broad category plus the specific thing,
so that the app can match my pantry without losing the detail I care about.

## Acceptance Criteria

1. **Two separate inputs.** Given the recipe edit screen, when it renders, then Tags and Ingredients are two separate inputs; a value typed into one never lands in the other's namespace, and each suggests only from its own namespace. (FR-8)

2. **Category plus optional specific.** Given an ingredient being added, when it is stored, then it carries a category from the shared vocabulary, optionally with a free-text specific — `cheese` alone, or `cheese` → `feta`. (FR-7)

3. **Coining is a visibly distinct act.** Given a category that does not yet exist in the vocabulary, when the user introduces it, then doing so is a visibly distinct act from picking an existing category, so the vocabulary is not extended by accident. (FR-9, FR-22)

4. **Specific-or-category, never both.** Given a recipe tagged `cheese` → `feta`, when it is displayed, then the view shows `feta`, and shows the bare category only where no specific exists — never both stacked as two ingredients. (FR-7)

### Completion Notes

- **Architecture Gap 2 is closed here.** The vocabulary is not a separate `_`-prefixed file: the shipped seed is committed in the image (Hotaru precedent) and a user's coined categories live in `KitchencraftDoc.categories`. Effective vocabulary = seed ∪ coined ∪ in-use, unioned on read. Two tests pin the consequences — a coined category outlives its recipe, and a *seeded* category is never copied into the user's document.
- **What ships in the seed was an open question in the spine**, so this is a proposal, not a derivation: 105 broad household categories. Composition notes worth reviewing — the four categories the UX flows demonstrate are present, the two Epic 3 staples are present, and `harissa` is deliberately absent so the coining flow can actually be walked as written.
- **The add is two-step.** Take the category, then the optional specific, then Add. Matching Flow 5 step 5 ("takes `chickpeas` and adds the optional specific `dried chickpeas`"). The category alone is already a complete ingredient tag, so Add is reachable without typing a specific.
- **The specific is not vocabulary.** It is trimmed and otherwise kept exactly as typed — `Yorkshire Feta` stays capitalised — because nothing matches against it and it is this cook's note about this one recipe. A test pins that.
- **Coining reaches the server only on save.** `rememberCategory` widens the local vocabulary immediately (so the value is selectable in one action, per UX-DR7) and the category persists when the recipe is saved. This is what keeps an abandoned edit from leaving a category behind, at the cost that "joins the shared vocabulary" is true on save rather than on tap. Flagging it as the deliberate reading.
- **The chip keeps the category in its `title`** even when it shows the specific, so the basis the pantry filter matches on is never hidden from the user.
- Concurrency: six simultaneous captures all coining `harissa` record it **once** (`test_concurrent_coining_of_one_category_records_it_once`).

## Dev Notes

**The new-category row is distinct by position, rule, icon and wording — never by colour alone** ([Source: UX-DR7]), so coining survives any contrast setting as "a visibly distinct act". It is **not** gated behind a confirmation.

**Not offered when there is nothing to coin** ([Source: EXPERIENCE.md § State Patterns → New-category row]) — including when the typed value matches an existing category only in casing.

**The vocabulary ships seeded** ([Source: UX-DR19]), so the Ingredients typeahead and the pantry filter both do useful work against the very first recipe. There is therefore no true first-run empty state for this input. The seed is a starting point, not a closed list, and **no copy may present it as fixed or discourage adding to it**.

**Specific-or-category, never both** ([Source: FR-7]) — `ingredientLabel()` is the single place that decides.
