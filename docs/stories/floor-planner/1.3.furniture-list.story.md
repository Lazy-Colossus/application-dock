# Story 1.3: The furniture list

## Status
Draft

## Story
**As** Jake or Dani,
**I want** to turn our furniture into true-to-scale pieces, one at a time or from a pasted list,
**so that** everything we own is ready to drag onto the plan.

## Acceptance Criteria
1. Furniture mode follows design B's three columns:
   - Left: the furniture list, showing each piece's name, a small shape and its size.
   - Right: the add/edit form with a preview at the plan's scale.
   - Centre: the plan.
2. A piece has a name, a colour and an optional note. Its shape is one of:
   - rectangle (width × depth, in cm)
   - round (a diameter)
   - oval (width × depth)
   - egg (width × depth, with the wider end at the top)
   - custom

   Basic shapes keep their exact size in cm (FU-1, FU-3).
3. The colours are white, black, grey, beige, brown, red, orange, yellow, green, blue and purple
   (FU-2).
4. **Custom** opens a small grid editor where you paint the squares the piece covers, for example
   an L-shaped sofa. The size in cm (the bounding box) updates as you paint (FU-1, FU-3).
5. **Bulk add** opens a dialog for the line format `name; shape; size; colour[; note]`:
   - Size is `W x D` in whole cm, or a single number for round pieces.
   - Shape and colour names are not case-sensitive.
   - A preview table shows each line as valid, or marks it with the reason it failed.
   - **Add** adds only the valid lines, in one request (FU-4).
6. Editing a piece changes it in every layout. Deleting a piece asks for confirmation and removes
   it from every layout (FU-5).
7. `furnitureFormat.ts` has a spec file covering good lines, every kind of failure, case handling
   and blank lines. The backend validates each piece again, and has tests for that and for the
   cascade when a piece is deleted.

## Dev Notes
- Plan: `docs/superpowers/plans/2026-10-08-floor-planner-1.3-furniture-list.md`. It gives the plan
  its own `plan_rev`, so piece writes never make a plan save go stale.
- Spec sections FU-1 to FU-5. Furniture mode was not mocked up: reuse B's panels, card styling,
  and Plex Mono for every size.
- The parser is a pure function on the frontend. The backend never parses the line format, it
  only validates the structured pieces it receives.
- Egg shape: an SVG path for an asymmetric oval inside the W × D box.
