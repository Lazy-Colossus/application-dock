# Story 1.5: Several apartments, and a drawing that saves itself

## Status
Ready for Review

## Story
**As** Jake or Dani,
**I want** to keep several apartments side by side and never lose a drawing,
**so that** we can plan more than one flat (or try a copy of ours) and pick up where we left off.

## Acceptance Criteria
1. **Switcher.** The top bar shows the current apartment's name. Clicking it lists every apartment
   the user belongs to, most recently changed first, with its members. Picking one opens it at
   `/floor-planner/<id>`, and reloading keeps it open. `/floor-planner` opens the most recently
   changed one. A user with no apartment gets an empty one called "My apartment" on first visit
   (AP-1).
2. **New.** "New apartment" asks for a name and creates an empty, unlocked apartment with
   "Layout A", owned by the user, and opens it (AP-2).
3. **Duplicate.** "Duplicate" asks for a name (default "<name> copy") and copies the plan, room
   labels, lock state, furniture and every layout with its placements into a new apartment owned
   by the user alone, then opens it (AP-3).
4. **Rename.** Any member can rename the apartment, 1–60 characters (AP-4).
5. **Delete.** Only the owner can delete an apartment, after a confirmation. It disappears for
   every member. The user lands on their next apartment, or a fresh "My apartment" if none is
   left (AP-5).
6. **Limit.** A user belongs to at most 20 apartments. Creating, duplicating or being added past
   that is refused with a message (AP-6).
7. **Sharing (SH-1, revised).** The owner adds a dock user, which adds this apartment to that
   user's list and leaves their other apartments alone. Refused: an unknown user, an existing
   member, a user at the limit. Members can leave, after which they land on another of their
   apartments. The owner removes members and cannot leave while others remain.
8. **Autosave (FP-9).** A drawing saves itself about 1.5 s after the last change. The status bar
   shows Saving… / Saved / Unsaved, and Save still saves at once. Undo and redo survive autosaves
   for the rest of the editing session. Switching apartments or leaving the page saves first.
   If someone else's plan write wins, autosave stops and the existing "Save again / Discard"
   notice takes over.
9. **Existing data.** The current `memberships.json` (one apartment per user) and apartment files
   without a name keep working: they read as a one-item list and "My apartment".
10. `pytest`, `npm test`, `black`, `ruff`, `eslint` and `vue-tsc` pass. Backend tests cover
    create, duplicate, rename, delete (owner only, every member loses it), the limit, adding and
    leaving under the new rules, access to someone else's apartment (404), and the legacy
    membership format. The store spec covers autosave timing and keeping undo across a save.

## Dev Notes
- Plan: `docs/superpowers/plans/2026-10-08-floor-planner-1.5-several-apartments.md`.
- Spec: AP-1 to AP-6, FP-9, SH-1 (revised), Data model and Backend sections, updated for this
  story. It drops "Several apartments per person, or an apartment switcher" from Out of scope.
- Every route moves under `/api/floor-planner/apartments/{id}`; the caller must be a member, or
  the route answers 404 so ids don't leak.
- `memberships.json` becomes `{ username: [apartment_id, ...] }`, still the single source of
  truth (NFR-b). The old `{ username: apartment_id }` shape is read as a one-item list and is
  rewritten in the new shape on the next membership change.
- Apartment docs gain `name` and `updated_at`. Every write sets `updated_at`, which orders the
  switcher.

### Completion Notes
- Built per the plan. Decisions beyond the story:
  - `GET /apartments` creates "My apartment" eagerly, so the list is never empty and the old
    unsaved `id: null` view is gone.
  - The owner can't leave at all; they delete instead. Removing someone else and leaving are
    separate routes (`DELETE …/members/{u}`, `POST …/leave`); leaving and deleting return the
    caller's remaining list so the client knows where to go.
  - Duplicate keeps furniture and layout ids, since they are scoped to their apartment, and
    resets `rev` and `plan_rev` to 0.
  - Autosave keeps one save in flight at a time; a second waits for the first, since it would
    otherwise be refused against the first's new `plan_rev`.
  - Discard is now offered only in the conflict notice; with autosave there is no other
    unsaved drawing worth discarding.
  - `NameDialog` gained a `maxLength` prop (60 for apartments, 40 elsewhere).
