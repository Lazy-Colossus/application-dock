# Decision Log — Tea PRD

Canonical memory and audit trail. Every decision, change, and override recorded here.

## 2026-09-06 — Discovery

- **Intent:** Create. No prior tea-app PRD exists; only an idea pool at `docs/stories/tea/idea-pool.md`.
- **Origin:** User asked to "create epics and stories for the tea app"; on finding no PRD, chose to draft the PRD first (proper BMAD flow) covering **all six feature clusters** from the idea pool.
- **Working mode:** Coaching path.
- **Audience:** Just me — personal, single-user. No sharing, no other accounts. Matches hotaru/archery pattern.
- **Form factor:** Phone at the tea table — mobile-web priority surface; touch-first, glanceable, usable mid-brew.
- **Platform context:** Self-contained app in Application Dock (FastAPI + Vue 3/Quasar/Pinia, JSON-file persistence, no DB). Shared platform architecture + JWT auth already exist.
- **Vision stance:** "Both held in tension" — a precise brewing instrument AND a quiet reflective journal, in one place holding all features + data.
- **Ninth feature added by user:** **Teaware Cabinet** — inventory of teaware (gaiwan, pot, kyusu…) with parameters (material, volume, etc.). Distinct from The Cabinet (tea inventory). Sessions/Cha Xi reference teaware items; per-pot seasoning log lives on the ware. Idea pool updated to 9 features.
- **Feature count:** 9 features across 3 clusters (Session-time: Gongfu Session Timer, Steep Metronome; Journaling: Cha Xi Journal, Tea Wheel, Tea Meditation Timer; Collection & knowledge: The Cabinet, Teaware Cabinet, Tea Map, Cha Dao Almanac).
- **User Journeys:** SKIPPED at user request. Single-user personal app with one operator role — journeys not warranted. JTBD retained as lightweight Target User capture. Section order becomes capability-first (Vision → Target User → Glossary → Features).
- **Brewing Curve (v1):** Timer prefills each infusion's steep time from the user's **highest-rated** past Session of that Tea. Introduces a **Session Rating**. Fallback chain when no rated history: Tea's own recommended Brewing Parameters (Cabinet record) → Almanac tea-family default. Shown as a "recommended" note. No averaging/ML in v1.
- **Almanac:** Seeded + user-extensible. Ships starter curated content (tea families w/ default brewing params, ceremony vocabulary EN/中/日); user can edit and add. Family defaults feed the Timer prefill fallback. Requires a "seed content" story.
- **Flavor Wheel:** Built-in default wheel, user-extensible (add own categories/notes).
- **CORE MODEL DECISION — unified optional Session:** A "sitting" is ONE `Session` record that accretes all angles — infusion timings, flavor fingerprint, cha xi (ware/mood/photo), optional meditation. Every enrichment is OPTIONAL, including timing itself: a quick timed session with no notes is valid, and a reflective entry with no timing is valid. The Journal = browsable Session history. This shapes the whole data model and every session-related feature.
