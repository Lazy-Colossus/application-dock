# Decision Log — KitchenCraft PRD

Canonical memory and audit trail for this PRD run.

## 2026-09-09

- **App name: KitchenCraft.** Chosen from a lean naming brainstorm (semantic-field mining over culinary vocabulary). Shortlist included Larder, Fond, Docket, Mise; user selected KitchenCraft.
- **Branch:** `feat/kitchencraft-app`, cut from `origin/main` @ 12b1e13.
- **Process shape:** PRD → epics → stories; separate product brief skipped (single-app addition to an existing shell, matching the `tea` precedent).

## 2026-09-10 — Discovery (Fast path)

- **Working mode: Fast path.** User chose batch-questions-then-draft over coaching path.
- **Stakes: hobby/personal.** No competitive research subagents run; PRD kept short.
- **Parsing mechanic: offline, builder-run in Claude Code.** Rejected: in-app Claude API button (adds paid external dep + new failure mode to a dock with no LLM integration today); rejected: hybrid. Consequence: PRD needs export (FR-12) + bulk structured update (FR-13) instead of a parse endpoint.
- **Ingredient matching: plain tag filter.** Rejected: ranked best-match (more logic), strict fully-cookable (returns nothing until pantry + parsing are rich). Known cost recorded as a counter-metric.
- **Images: none in v1.** Keeps persistence pure JSON-on-disk; no binary storage introduced to the platform.
- **v1 scope additions: shopping list + favourites.** Servings scaling explicitly excluded (needs parsed quantities).
- **Body is immutable.** Elevated to an NFR and to FR-3/FR-13/FR-14: no operation may alter a captured body. This is the constraint that makes offline enrichment safe.
- **Open: shopping list overlaps Listies.** Flagged as Open Question 4 rather than resolved.

## 2026-09-10 — Open questions resolved

- **Q1 Enrichment access: direct volume access.** A maintenance script in `backend/scripts/` driven from Claude Code. Rejected: HTTP export + bulk-update endpoints. Consequence: dropped the export FR; added FR-17 (enrichment writes go through the repository layer — same atomic writes and locks as the app) to contain the risk of writing underneath a running container. Mechanics of reaching the volume from the host left to architecture.
- **Q2 Ingredient granularity: two-level.** Shared category (matched by the pantry filter) + optional free-text specific (shown in the recipe view). Added FR-5 and FR-20 (enrichment must reuse the existing category vocabulary and report new categories, or the filter silently degrades).
- **Q3 Tag UI: two separate inputs** (FR-6). A single combined input would need to guess namespaces and would pollute the ingredient namespace the pantry filter depends on. User confirmed.
- **Q4 Shopping list: stays in KitchenCraft.** The Listies-overlap concern was raised and not taken; user specified the design instead. Scoped deliberately small — one list, modal, tick-to-cross-off, clear (FR-12 – FR-16). Salt and black pepper hard-coded as staples, unchecked by default. Adding to a non-empty list prompts add-vs-overwrite.
- **FR renumbering.** FRs renumbered to a clean 1–20 sequence after the shopping-list and enrichment rewrites.

**Newly open (carried to architecture):** provenance of user-set vs machine-set values (FR-19); whether v1 seeds a starter category vocabulary; how the host reaches the volume.

## 2026-09-10 — Finalised

- **PRD marked `status: final`.** Reviewer gate skipped deliberately (hobby/personal stakes, per the skill's stakes calibration). Editorial polish passes not run.
- **Downstream complete:** `docs/planning-artifacts/epics-kitchencraft.md` — 4 epics, 19 stories, all 22 FRs and 8 NFRs covered.
- **Validation corrections:** Story 1.4 AC rewritten (it referenced structured fields that do not exist until Story 2.1 — an untestable criterion); Epic 1/2 file-overlap consolidation considered and rejected, rationale recorded in the epics document.

## 2026-09-15 — FR-5 reversed, FR-21 added

- **Q2 reversed.** Ingredient granularity is no longer two-level. FR-5 is now an
  optional amount, an optional unit, and a required free-text name. The shared
  category vocabulary, the pantry filter (FR-10) and enrichment's duty to reuse
  categories (FR-20, rewritten) went with it. Requested directly, with the blast
  radius stated and confirmed before removal.
- **Open question 2 closed as moot.** "Does v1 seed a starter category
  vocabulary?" — there is no category vocabulary. A shipped starter list of
  *units* took its place, deliberately open rather than closed.
- **FR-21 added: the star rating.** Written after Story 2.7 had already shipped
  it. Ratings moved out of §6.2's out-of-scope list; a ratings *history* stays
  out.
- **§12 Amendments added.** Post-`final` changes are recorded there rather than
  folded silently into the text, and each amended requirement carries a dated
  pointer to it.
- **Counter-metrics pruned.** Two of the five guarded the pantry filter and the
  category vocabulary; both are void. The remaining one — ingredient wording
  fragmenting across enrichment passes — survives against free text.
